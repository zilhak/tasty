# Plugin 설정과 신뢰 기록의 파일 경계

`plugins.toml`은 비활성·builtin 제거 표시, 허가 권한, 명령별 단축키를 저장한다. `known-plugins.toml`은 공개 키와 미인증 선택을 기록한다. 두 파일 사이의 transaction은 없다. [Plugin 런타임](plugin-runtime.md)의 프로세스·세대 소유권은 저장 요청과 별도로 유지한다.

## 읽기·병합·교체

`tasty_host_plugin::file_persistence::ConfigUpdate`는 변경 전후의 소유한 값을 받는다. 실행할 때 공용 파일 잠금을 얻고 최신 문서를 다시 읽는다. 비활성·제거 표시는 ID별로, 권한은 토큰별로, 단축키는 plugin·명령별로 변경한 부분만 병합한다. 같은 명령의 단축키가 관측 이후 다르게 편집되었으면 충돌을 반환한다. 반환된 `PluginsConfig`는 요청 값에 최신 외부 변경을 합친 실제 확정 값이다. 활성화·권한 같은 명시적 명령은 cache에서 같은 값이어도 최신 파일에 적용한다. 이 명령 의도는 draft snapshot과 합치지 않는다.

신뢰 변경은 최신 DB를 잠금 안에서 수정하는 명령이다. 오래된 객체의 `save`는 같은 ID의 알려진 필드가 달라졌으면 충돌로 끝난다. 다른 ID와 알 수 없는 필드·섹션은 보존한다. 조건부 undo는 이 작업이 쓴 기록과 현재 기록이 일치할 때만 이전 값을 돌려놓는다. 이후의 신뢰 선택을 되돌리지 않는다.

파싱·읽기 실패를 빈 문서로 덮어쓰지 않는다. 로그와 후속 저장 오류에는 파서 원문을 넣지 않는다. 변경하지 않은 TOML 표현과 주석은 유지한다. 공용 `tasty_utils::file_replace`의 고유 임시 파일·원자 교체를 쓰며 새 파일은 Unix 0600으로 생성한다. 기존 파일의 권한·플랫폼 보안 메타데이터와 symlink는 공용 교체 계약을 따른다. 참여하지 않는 편집기의 변경은 교체 직전 fingerprint로 검사하며, 마지막 검사와 rename 사이의 경쟁까지 막지는 않는다.

## 호출부의 소유권

런타임은 소유한 파일 작업을 공용 writer에 제출한다. manager·registry guard를 worker에 넘기지 않는다. 파일 확정 뒤 메인 루프가 cache·권한·프로세스 효과와 원 호출자의 결과를 반영한다. 접수만으로 저장 성공이나 권한 허가를 알리지 않는다. 결과 불명은 명령을 다시 실행하거나 plugin을 시작할 근거가 되지 않는다. 파일 확정 뒤 manager 적용이 불가능해도 이미 저장한 결과와 앞서 끝난 비활성·삭제 효과는 오류 응답의 saved/applied/partial에 보존한다.

단축키 draft는 아직 실행하지 않은 같은 구간의 변경만 합친다. 토글·설치·신뢰 명령은 순서를 지키는 경계다. 단축키 실패 값은 dirty로 남고, 나중에 성공한 변경은 자기 키의 실패 값만 해제한다.

GUI 부팅 worker의 builtin 설치는 동기 API를 사용할 수 있다. 파일 확정 뒤 discover/start로 이어야 하는 초기화 barrier이며 GUI 메인 루프에서 실행하지 않는다. 런타임 builtin 갱신은 파일 계획·복사와 메인 루프의 세대 회수·재시작을 나눈다. 파일을 바꾸지 않는 항목은 회수를 기다리지 않는다. 종료 중 생략한 재시작이나 이미 실행 중인 프로세스에 대한 no-op은 재시작 성공으로 보고하지 않는다.

## 검증 경계

호스트 크레이트의 파일 시험은 실제 잠금·외부 편집·실패·조건부 undo·주석·링크·mode를 다룬다. 이 시험만으로 GUI/headless의 공용 writer 주입과 종료 wiring을 증명하지 않는다. 실제 앱 검증은 격리된 데이터 루트와 소유한 가짜 plugin으로 저장 지연 동안 응답·프로세스가 대기하는지, 최종 응답과 종료 drain이 실제 receipt를 반영하는지 확인한다. Windows/macOS의 실행 여부는 Linux 검사 결과와 구분한다.
