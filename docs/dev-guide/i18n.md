# 국제화 (i18n)

모든 UI 문자열은 `t()` 계열을 통해 번역 키로 노출한다. 영어/한국어/일본어를 코드에 직접 하드코딩하지 않는다. 강제 정책은 [`../../CLAUDE.md`](../../CLAUDE.md) "국제화".

## API

번역 스토어는 leaf 크레이트 `tasty-i18n` 에 있다(전역 `OnceLock`). 본 바이너리는 `crate::i18n` 으로 재수출하고 `tasty-cli` 는 `tasty_i18n` 을 직접 의존 — **둘 다 같은 전역 테이블**을 공유한다.

```rust
pub fn t(key: &str) -> &str;                        // 단순 조회
pub fn t_fmt(key: &str, arg: &str) -> String;       // {} 1개 치환
pub fn t_fmt2(key: &str, a1: &str, a2: &str) -> String; // {} 2개
pub fn t_args(key: &str, args: &[&str]) -> String;  // {} N개 (CLI 등 3+ 인자)
pub fn t_fmt_fit(key: &str, fragment: &str) -> String;  // {} 1개 + 토스트 캡 맞춤
pub fn fit_fragment(fragment: &str, render: impl Fn(&str) -> String) -> String;
pub fn current_language() -> &'static str;
pub fn register_namespace(plugin_id: &str, lang_dir: &Path);
pub fn unregister_namespace(plugin_id: &str);
```

- **키를 못 찾으면 키 문자열을 그대로 반환** — 누락이 화면에 드러나 회귀를 즉시 노출.
- placeholder 는 키 값 안의 `{}` 를 순서대로 치환.
- **길이를 모르는 조각(경로·실패 사유·OS 에러)을 토스트에 실을 때는 `t_fmt_fit`** — 번역된 틀은 그대로 두고 조각의 **가운데만** 생략해 200자 캡에 맞춘다. 그냥 `t_fmt` 로 넘기면 호스트가 **꼬리를 잘라내**(`src/adapters/ui/toast.rs` `truncate_message`) 정작 식별에 필요한 부분이 사라진다. 조각이 캡 안이면 손대지 않는다. 인자 개수가 다르거나 틀이 복잡하면 `fit_fragment` 에 렌더 클로저를 직접 준다(`{}` 를 정확히 한 번 치환해야 예산이 맞는다).

```rust
ui.label(t("settings.appearance.custom_font_label")); // ✅
ui.label("Custom font file:");                         // ❌
```

## 번역 파일 위치

| 대상 | 경로 | 로드 |
|------|------|------|
| 본 바이너리 임베드 | `lang/{en,ko,ja}.toml` (워크스페이스 루트) | 시작 시 `include_str!` |
| 번들/외부 plugin | plugin 디렉토리 `lang/{en,ko,ja}.toml` | plugin 활성화 시 `register_namespace` |
| 사용자 오버라이드 | `~/.tasty/lang/{code}.toml` — **내장 코드(`en`/`ko`/`ja`) 전용** | 시작 시 내장 위에 overlay |
| 사용자 언어팩 | `~/.tasty/lang/<code>/pack.toml` (+ 동봉 폰트) — 내장이 아닌 새 코드 | 시작 시 영어 베이스 위에 overlay · 설정 콤보에 노출 |

언어 선택은 `~/.tasty/config.toml` 의 `general.language`(내장 `en`/`ko`/`ja` 또는 발견된 언어팩 코드), 변경 시 재시작. 오버레이 계층: **영어 베이스 → 선택 언어(내장 또는 팩) → 사용자 오버라이드(내장만)**, 누락 키는 한 단계 아래로 fallback. 세 파일 모두 `[meta] name = "<표시 이름>"` 을 가진다 — 설정 콤보의 라벨 출처다.

## 언어팩 (`~/.tasty/lang/<code>/pack.toml`)

내장 3 개 밖의 언어는 **디렉토리 + `pack.toml`** 이 하나의 언어팩이다. 로더·스캐너는 `tasty-i18n` 에 있고(`load_pack` / `scan_languages` / `available_languages`), 판정 근거·대안은 [ADR-0114](../adr/0114-language-pack-directory-shape-and-english-fallback.md).

```toml
# ~/.tasty/lang/fr/pack.toml
[meta]
name = "Français"          # 콤보 표시 이름 (선택 — 없으면 코드 "fr" 가 라벨)

[font]                     # 필수 — 아래 넷 중 하나
builtin = true             # 내장 폰트 스택으로 충분
# file = "fonts/x.ttf"     # 팩 디렉토리 기준 상대경로 (동봉 폰트)
# family = "Noto Sans"     # 시스템 폰트 패밀리명
# candidates = ["fonts/x.ttf", "Noto Sans"]   # 순서대로 첫 성공

[button]                   # 나머지는 내장 lang 파일과 같은 키 트리
ok = "OK"
```

- **`[meta] name`** — 표시 이름. 공백뿐이거나 문자열이 아니면 없는 것으로 본다(코드 폴백). `meta.name` 키로 `t()` 조회도 된다.
- **`[font]`** — **필수**. 우선순위 `builtin = true` > `file` > `family` > `candidates`(섹션은 있는데 넷 다 없거나 빈 값이면 형상 위반). 폰트를 실제 파일/패밀리로 resolve 하는 단계는 아직 없다 — 선언만 검증·보관하며(`FontDecl`), `TASTY_LOCALE_FONT` 는 현재 항상 unset 이다.
- 문자열 키는 `[font]` 를 제외한 모든 문자열 leaf. 영어 베이스 위에 overlay 되므로 일부만 번역해도 된다.
- **파일 크기 상한 2 MiB** (`tasty_i18n::MAX_PACK_BYTES`). 넘으면 파싱 전에 거부하고 `tracing::warn!` 후 목록에서 뺀다 — 같은 상한이 내장 오버라이드 `<builtin>.toml` 에도 걸린다. 가장 큰 내장 파일 `lang/ja.toml` 이 89 KiB / 약 1,300 키라 상한은 그 23 배다(장황한 언어 · 주석 · 키 증가를 모두 곱해도 12 배 정도). 상한 자체가 비용의 천장이기도 하다 — 발견 비용은 파일 크기에 비례하므로, 상한에 정확히 걸치는 팩 하나가 평범한 팩 20 개를 스캔하는 것과 같은 자릿수(초가 아니라 수십 ms)다. 자릿수로만 적는다 — 절대값은 머신·빌드 프로파일에 따라 달라지고, 이 결정은 그 정밀도에 기대지 않는다.
- **빈 값(빈 문자열·공백뿐)은 번역이 없는 것으로 본다** — overlay 에서 빠져 아래 층이 그대로 보인다. 빈 값이 그대로 나가면 라벨 없는 버튼이 생기고 화면만 봐서는 어느 키가 비었는지 알 수 없다. `[meta] name` 과 `[font]` 의 문자열 검사(`non_empty_str`)와 같은 규칙이다. 로드 시 몇 개가 빠졌는지 `tracing::warn!` 로 알린다.
  - **세 로드 경로에 같은 규칙**이 걸린다 — 팩 · 내장 오버라이드(`<builtin>.toml`) · plugin 언어파일(`<plugin>/lang/<code>.toml`)([ADR-0124](../adr/0124-blank-value-rule-is-load-path-independent.md)). 근거가 파일 형상이 아니라 그 아래 층이기 때문이다 — 빈 값이 테이블에 도달하면 어느 경로든 라벨 없는 UI 가 되고 화면에 단서가 남지 않는다. **폴백 대상만 다르다**: 팩은 영어 베이스로, 오버라이드는 내장 `<code>.toml` 의 문구로, plugin 파일은 그 plugin 의 `en.toml` 로 되돌아간다. `tasty-i18n` 단위 테스트가 세 경로에 같은 입력을 넣어 이 등가성을 고정한다.
  - 일부러 빈 텍스트를 두려면 **폭 없는 문자(U+200B ZWSP, U+2060)** 를 쓴다. **NBSP(U+00A0)·U+2007·U+3000 은 안 된다** — `str::trim` 은 유니코드 `White_Space` 속성을 전부 먹고 이 셋이 거기 포함된다.

### 발견 규칙 (설정 콤보 목록)

`available_languages()` = 내장 `en` / `ko` / `ja`(순서 고정) + `~/.tasty/lang/` 스캔 결과(코드순). 각 항목은 코드 · 표시 이름 · 출처(`Builtin` / `BuiltinOverridden` / `Pack`) · `[font]` 선언 종류 · 경로.

발견은 `load_pack` 이 아니라 **`load_pack_head`** 를 쓴다 — 목록에 필요한 것은 `[meta] name` 과 `[font]` 둘뿐인데, 문자열 leaf 를 전부 flatten 해서 만든 맵을 그대로 버리던 자리였다. 이 스캔은 설정 창을 처음 열 때 **렌더 스레드에서 동기로** 돈다. 수락/거절 판정은 두 경로가 동일하다("목록에 오르면 로드된다"가 성립해야 한다) — `tasty-i18n` 의 단위 테스트가 이 등가성을 강제한다.

| `~/.tasty/lang/` 안의 것 | 판정 |
|---|---|
| `<code>/pack.toml` (유효) | 팩 — 목록에 오른다 |
| `<code>/pack.toml` 파싱 실패 · `[font]` 없음/무효 | `tracing::warn!` + 제외 |
| `<code>/pack.toml` 이 2 MiB 초과 | 파싱 전 거부 — `tracing::warn!` + 제외 |
| `<builtin>/pack.toml` (예: `ko/`) | 내장 코드는 팩이 아니다 — warn + 제외 |
| `<builtin>.toml` (예: `ko.toml`) | 내장 오버라이드 — `ko` 가 `BuiltinOverridden` 으로 표시(`[meta] name` 이 있으면 라벨도 그것) |
| `<new>.toml` (예: `zz.toml`) | 팩이 아니다 — warn + 무시 (`zz/pack.toml` 로 옮겨야 한다) |
| `pack.toml` 없는 디렉토리 | 무시 |

### 부팅 시 로드와 폴백

`tasty_i18n::init(code)` 는 `LoadReport { requested, effective, outcome }` 를 돌려주고 `load_report()` 로 다시 읽을 수 있다.

- 팩이 정상이면 `effective == requested`.
- 팩이 **없거나**(`PackMissing`) **거부되면**(`PackInvalid` — 파싱 실패 · `[font]` 부재/무효 · 크기 상한 초과) 테이블은 **영어**(en 오버라이드 포함)로 만들고 `effective = "en"`. `current_language()` 와 자식 env `TASTY_LOCALE` 도 `en` 이다.
- 로드 시점에 `tracing::warn!` 한 줄(요청 코드 + 기대 경로 `~/.tasty/lang/<code>/pack.toml`, 단일 `<code>.toml` 이 놓여 있으면 그 사실도) — headless/CLI 는 이것이 전부다. 로그의 경로는 항상 온전하다.
- GUI 는 부팅 후 `LoadReport::user_warning()`(키 `i18n.warn.pack_missing` / `pack_invalid`)을 **경고 토스트 1회**로 띄운다(웹훅 bind 실패와 같은 구조). 토스트에는 본문 200자 캡이 있고(`tasty-i18n` 의 `TOAST_MAX_CHARS` — 호스트의 `truncate_message` 도 이 상수에서 파생하므로 캡은 한 곳에만 있다) 넘기면 호스트가 뒤를 자르고 `(200자 제한)` 접미를 붙이므로, `fit_path` 가 **경로만 가운데를 생략**해 캡 안에 맞춘다 — 머리와 꼬리(`<code>/pack.toml`)를 남긴다. 문구를 새로 쓰거나 번역할 때 이 캡을 염두에 두라: 문구가 길어질수록 경로에 남는 예산이 줄어든다.
- **설정값은 어느 경로에서도 고쳐 쓰지 않는다** — 사용자가 팩을 넣고 재시작하면 그대로 그 언어가 뜬다.

### 설정 콤보 동작

Settings › General 의 언어 콤보는 위 목록만 보여 준다(`tasty_ui_widgets::language_select`, 갤러리 Settings specimen 과 같은 위젯). 라벨은 `[meta] name`, 없으면 코드. 현재 설정값이 목록에 없으면(팩이 지워진 뒤 등) 값을 덮어쓰지 않고 `"<code> (not found)"` 행(`settings.general.language_missing_suffix`)을 끝에 붙여 선택 상태로 유지한다 — 그 행을 다시 골라도 값은 변하지 않는다. 목록은 설정 창을 열 때 1회 스캔한다.

## 새 문자열 추가 절차

1. 코드에 `t("namespace.key")` 호출 먼저 추가.
2. `lang/en.toml`·`ko.toml`·`ja.toml` **세 파일 모두** 같은 키 추가. (누락 시 fallback 영어 or 키 노출.)
3. plugin 문자열이면 그 plugin 의 `lang/` 에 추가.
4. `cargo test --locked --test i18n_key_parity --test no_hardcoded_ui_strings` 로 확인 — 세 파일 정합과 하드코딩 여부를 [강제 테스트](#강제-테스트) 가 잡는다.

키 네이밍: `<영역>.<서브영역>.<항목>` (점 계층, 예: `settings.appearance.theme_label`).

## 문체 (톤)

| 언어 | 종결 | 예 |
|------|------|-----|
| en | 평서문 · 명령형 그대로 | `It may have been deleted. Pick another from the header.` |
| ko | 존댓말 `~합니다` / 권유는 `~하세요`. 평서형 `~한다` · 하라체 `~하라` 금지 | `삭제되었을 수 있습니다. 헤더에서 다른 DAG 를 선택하세요.` |
| ja | ですます체. 常体(`~する` / `~ない` / `~選ぶ`) 금지 | `削除された可能性があります。ヘッダーから別の DAG を選択してください。` |

- **명사구는 규칙 밖이다** — 버튼 · 라벨 · 컬럼 헤더 · 빈 상태 제목처럼 종결어미가 없는
  문자열은 그대로 둔다(`닫기` / `DAG 없음` / `閉じる`).
- **프로젝트 문서의 문체를 lang 파일로 가져오지 않는다.** `CLAUDE.md` 와 `docs/` 는
  `~한다` 체를 쓰지만 UI 문자열은 사용자에게 말을 거는 자리라 화자 태도가 다르다.

## OS 네이티브 표면

egui 밖의 OS 네이티브 UI 도 사용자 표면이라 예외가 아니다. 라벨은 전부 `t()` 이고 단축키(key equivalent)는 별도 정책([key-mapping](../design/policies/key-mapping.md))이라 서로 독립이다.

| 표면 | 키 | 코드 |
|------|----|------|
| macOS 메뉴바(NSMenu) + Dock 메뉴 | `menu.macos.*` | `src/platform/macos_delegate.rs` |
| 시스템 트레이 메뉴·툴팁(3 OS) | `tray.*` | `src/platform/system_tray.rs` |
| Windows 작업표시줄 Jump List | `jump_list.*` | `src/platform/jump_list.rs` |

- 앱 이름을 결합하는 macOS 항목(About / Hide / Quit)은 키 값에 `{}` 를 두고 `t_fmt(key, &process_name)` 로 채운다 — 언어별 어순("About Tasty" / "Tasty 가리기" / "Tastyを非表示")을 리터럴 결합으로는 맞출 수 없다.
- ko/ja 의 macOS 메뉴 값은 OS 표준 메뉴 관용 표기(Apple 용어집)를 따른다 — 옆에 놓이는 다른 앱 메뉴와 같은 말을 써야 한다.
- Windows `w!()` 는 컴파일 타임 리터럴이라 번역 문자열에 쓸 수 없다 — 런타임에 null-terminated `Vec<u16>` 로 만들어 `PCWSTR` 로 넘기고, 호출이 끝날 때까지 버퍼를 살려 둔다. 실행 인자 토큰(`"new-window"`)만 `w!()` 로 남는다.
- 모든 호출 지점은 `locale::init()` 이후(macOS delegate 주입 / `resumed()`)라 부팅 순서 문제는 없다.

## Plugin 네임스페이스

활성화 시 `register_namespace(plugin_id, &lang_dir)` 로 overlay 합류. 키 충돌 방지를 위해 plugin 은 자기 키를 `<plugin_id>.<...>` 로 prefix 한다. 비활성/제거 시 `unregister_namespace` 로 정리. (문자열은 `Box::leak` 으로 `&'static` 을 만족 — 활성화 빈도가 낮아 누수는 무시할 수준.)

위 네임스페이스는 **host 가 그리는** plugin 문자열(매니페스트 `*_i18n_key` 등)용이다. plugin 이 **자기 프로세스에서 직접 그리는** 문자열은 host 카탈로그에 닿지 못하므로, SDK `tasty_plugin_sdk::i18n::Translator` 가 plugin 의 `lang/` 을 직접 로드한다(base `en.toml` → 활성 언어 overlay, 키 미스 시 키 반환 — host 와 같은 규칙). 활성 언어는 `TASTY_LOCALE` env 로 받는다.

- `TASTY_LOCALE` 은 host 본 바이너리가 부팅 시 `general.language` 에서 확정해 **자기 프로세스 env 에 set** 하고(`src/boot/locale.rs` — 이벤트 루프·스레드 생성 전 단일 스레드 구간), host-plugin 이 spawn 시 그대로 propagate 한다(`crates/tasty-host-plugin/src/process.rs` — `tasty-i18n` 비의존). 셸에서 export 한 값은 설정에 덮인다 — env 만으로 plugin 언어를 임시로 바꾸는 우회는 없으므로, 언어를 바꿔 보려면 `general.language` 를 편집하거나 debug 빌드에서 `tasty debug settings apply --json '{"general":{"language":"ja"}}'` 로 바꾼 뒤 재시작한다.
- 언어팩 폰트가 resolve 되면 `TASTY_LOCALE_FONT`(절대경로)도 같은 경로로 전달된다. 폰트가 없으면 unset.
- 값은 spawn 시점 고정이다 — 언어 변경은 재시작 후 plugin 에 반영된다(host 자신과 같은 정책). 근거·대안: [ADR-0103](../adr/0103-plugin-locale-via-host-process-env.md).

### plugin 이 돌려주는 IPC 에러 문구

**번역한다.** JSON-RPC `error.message` 는 CLI 가 stderr 로 그대로 흘리는 사용자 표면이다.

이 규약은 전수로 확인했다(2026-09-05, 번들 plugin 9 개 전부 · `IpcMethodError::new` 호출 44 건):

| plugin | `t()` 경유 | 영어 리터럴 |
|--------|-----------|-------------|
| claude | 17 | 0 |
| codex | 12 | 0 |
| agent-stream | 9 | 0 |
| image | 0 | 2 |

나머지 다섯 plugin 은 IPC 에러를 내지 않는다. image 의 둘은 `format!("save failed: {e}")`
꼴로 채택된 규약이라기보다 남은 자리다.

**레포 안에서 이 문구를 파싱하는 소비자는 0 이다** — `error.message` 를 내용으로 분기하는
자리를 `cfg(test)` 와 진단 호출 범위를 빼고 세면 남는 것이 없고, 스크립트·워크플로에도
없다. 기계가 가르는 축은 `code`(`-32602` 등)이지 문구가 아니다.

**예외 하나 — `*.hook` 은 두 곳으로 나간다.** `tasty <plugin> hook …` 의 실패는 stderr
말고 `~/.tasty/hook-failures.log` 에도 실리는데, 그 파일은 에이전트가 `grep` 으로 읽는
로케일 무관 채널이다(아래 "하드코딩 허용 예외"). **그 줄에서 로케일 무관성을 지는 것은
좌표 필드(`method`/`event`/`surface`/`code`)이고 `reason` 산문은 그 문구를 만든 쪽의
언어를 따른다** — 그러므로 여기 문구를 번역하는 것이 그 채널의 계약을 깨지 않는다.
근거·대안·재검토 조건은 [ADR-0164](../adr/0164-hook-failure-locale-invariance-rests-on-fields.md).

## CLI 출력 문자열

`tasty <subcommand>` 의 client 모드는 본 바이너리와 **같은 프로세스**에서 돌아(부팅 시 `locale::init()`), GUI 와 동일한 번역 테이블을 쓴다. `locale::init()` 은 라우팅 판정(`cli_routing::parse_or_route`) 진입부에서 올라가므로, clap 파싱 전에 도는 plugin CLI fallback(`tasty <plugin 명령>`) · `-a` · root `-h` 경로의 stderr 도 번역된다. `tasty-cli` 에서 `tasty_i18n::{t, t_fmt, t_args}` 를 직접 호출한다.

- 키 prefix 는 `cli.<명령>.<항목>` (예: `cli.remote_check.not_found`).
- 인자 3+ 메시지는 `t_args(key, &[...])`.

### CLI 도움말 (clap `about` / `help`)

clap 파생 매크로는 도움말 문자열을 **컴파일 타임**에 잡는다. 그래서 런타임 언어를
적용하려면 `Cli::command()` 가 만든 트리를 순회하며 빌더 API 로 갈아 끼운 뒤 **그
트리로 파싱**해야 한다 — 서브커맨드의 `--help` 는 clap 이 파싱 도중 직접 출력하므로,
교체가 파싱보다 늦으면 그 경로만 영어로 남는다.

그 일을 하는 곳은 `crates/tasty-cli/src/help_i18n.rs` 하나다. 트리를 만드는 자리가
여럿이라(라우팅 · 트리 인쇄 · 증강 도움말 · plugin 증강 · 인자 조회) **급소를 하나로
좁혔다** — 프로덕션은 `Cli::command()` 를 직접 부르지 않고 `help_i18n::command()` 를
쓴다. 본 바이너리 쪽은 `crate::cli` 퍼사드가 이름 하나(`localized_command`)로 노출한다.

**키 모양**은 `cli.help.<서브커맨드 체인>.<잎>` 이다.

| 자리 | 키 |
|---|---|
| 루트 설명 | `cli.help._root.about` |
| 서브커맨드 설명 | `cli.help._root.<a>.<b>.about` |
| 긴 설명 | 같은 자리에 `.long` |
| 인자 설명 | `cli.help._root.<a>.arg.<인자 id>.help` |
| 인자 긴 설명 | 같은 자리에 `.long` |

잎 마디(`about`/`long`/`help`)를 붙이는 이유는 TOML 이다 — **한 키가 값이면서 동시에
하위 테이블일 수 없다.** `cli.help._root` 를 문자열로 쓰면 `cli.help._root.new` 를 그
아래 둘 수 없고, 그때 깨지는 것은 도움말이 아니라 **언어 카탈로그 전체의 파싱**이다.

**영어 원본은 소스의 doc comment 다.** `lang/en.toml` 은 같은 값을 갖는 자유도 없는
복제이고, 그 복제가 번역자에게 **키 목록**이 된다. 손으로 맞추지 않는다 — 어긋나면
가드가 그 키를 짚는다.

**번역이 없는 자리는 영어 원문이 그대로 보인다.** `t()` 는 키가 없으면 키 문자열을
돌려주므로, 교체 유틸이 넣기 전에 "있는가" 를 먼저 묻는다. 그래서 부분 커버리지는
깨진 상태가 아니라 섞여 읽히는 상태이고, 번역은 화면 단위로 늘릴 수 있다. 다만 세
언어의 키 집합은 **정확히 같아야 하므로**(`tests/i18n_key_parity.rs`) 한 묶음을 열 때
en·ko·ja 를 함께 옮긴다.

★ 한국어를 옮길 때는 **어휘 게이트가 함께 문다.** `lang/ko.toml` 은
`one_concept_one_word_on_the_user_facing_surface` 의 스캔 대상이라, 은퇴한 표기를 쓰면
그 자리에서 빨개진다(실측: 도움말 한 묶음을 옮기며 `페인` 대신 은퇴 표기를 여덟 번,
`윈도우` 대신 `창` 을 두 번 썼다). 도움말 문구는 개발 문서가 아니라 **사용자 표면**이므로
`docs/` 의 관용 표기가 아니라 [`ubiquitous-language.md`](../concepts/ubiquitous-language.md)
의 정본을 따른다. 새 묶음을 넣은 뒤 그 가드를 한 번 돌리는 것이 가장 싸다.

**아직 영어로 남는 것**: clap 자신의 틀(`Usage:` · `Options:` · `Commands:` ·
`error: unexpected argument …`)은 clap 에 로케일 기능이 없어 `help_template` 커스텀
없이는 바뀌지 않는다. `help.rs` 의 증강 도움말 골격 문구도 아직 리터럴이다.

### 하드코딩 허용 예외

번역하면 의미가 변하는 고유명사·고정 식별자는 허용:

- 수식키 이름(`Ctrl`/`Alt`/`Shift`/`Cmd`), 단축키 조합 표시(`Ctrl+Shift+P`)
- 폰트 프리뷰 텍스트(`AaBbCcDdEeFfGg`), 언어 이름 자체(`English`/`한국어`/`日本語`)
- 내부 진단 `tracing::*` 로그(사용자 표면 아님)
- `clap` 파생 매크로의 `about`/`help` 는 **더 이상 하드코딩 예외가 아니다** — 도움말은
  실행 시점에 번역된다(아래 "CLI 도움말" 절). doc comment 는 그대로 두되 **영어로만**
  쓴다: 그것이 영어 원본이고, `clap_help_text_is_english_only` 가 그 규율을 강제한다.
  개발자용 배경 설명(설계 근거, 원칙 번호 인용 등)은 help 가 아니라 `//` 주석이나
  `docs/` 에 둔다 ([`cli-structure.md`](cli-structure.md) "도움말 문구").
  parse 오류 뒤에 붙는 augmented help 골격(`crates/tasty-cli/src/help.rs` 의
  `Available subcommands for …` / `Run '… --help' for full details.`)은 **아직** 리터럴이다
- CLI 가 host 의 에러 응답을 중계하는 `Error (…)` 줄(`crates/tasty-cli/src/run.rs`) —
  본문은 host 가 만든 문구를 그대로 통과시키고 접두 `Error (` 는 그 응답 형식의 일부다
- `crates/tasty-cli/src/out.rs` 의 `StdoutClosed` Display(`stdout closed by reader`) —
  사용자 표면에 닿지 않는다. CLI 진입점이 `quiet_if_stdout_closed` 로 종료 코드 0 으로
  접어 아무것도 출력하지 않는다(ADR-0101). 그 외 stdout 쓰기 실패는 `cli.out.write_failed`
- `format.rs` 밖의 **기계 판독 구조 출력** — attach mirror-dump 의 섹션 헤더
  (`crates/tasty-cli/src/local/attach.rs` 의 `=== surface N ===`, grep 로 구획을 자른다)와
  hook 실패 기록의 `key=value` 한 줄(`hook_failure.rs`, `grep`/`awk` 로 읽는 레코드).
  구획자가 로케일에 따라 흔들리면 그 출력을 소비하는 쪽이 깨진다.
  **`hook-failures.log` 의 로케일 무관성은 구획자와 좌표 필드(`method`/`event`/`surface`/
  `code`)가 진다** ([ADR-0164](../adr/0164-hook-failure-locale-invariance-rests-on-fields.md)).
  `reason` 산문은 그 문구를 **만든 쪽**의 언어를 따른다 — CLI 가 만드는 두 갈래는 영어이고,
  답한 쪽이 만든 문구를 그대로 싣는 갈래는 그 쪽의 언어다. 앞엣것을 영어로 묶는 이유는 —
  셸 래퍼가 `|| true` 로 exit code 를 버려 이 파일이 hook 전달 실패의 유일한 흔적이고,
  읽는 주체가 에이전트일 수 있어 알려진 실패 패턴과 대조 가능해야 한다. 같은 실패의
  **stderr 는 번역문**을 유지한다(사용자 표면). 그 분리는 `hook_failure::record` 가
  `DiagnosticEnglish` 만 받는 것으로 타입이 지키고, 그 타입의 탈출구
  (`new_unchecked`)는 `tests/hook_failure_reason_stays_english.rs` 가 소스 스캔으로 막는다.
  **그 스캔의 술어는 둘이고 서로를 못 대신한다** — 하나는 인자의 **출처**를 보고(`t()` 계열
  호출이나 번역 래퍼가 섞였나), 다른 하나는 인자에 박힌 리터럴의 **값**을 본다(한글·가나·한자가
  들어 있으면 어떤 로케일에서도 영어가 아니다). 출처 검사만 있을 때 `t()` 를 안 거치고 소스에
  직접 박은 한국어 리터럴이 그대로 통과했다. 값 검사도 규약 전체는 못 잰다 — ASCII 로만 된
  번역문(스페인어 등)은 값으로 구별되지 않고, 그 갈래는 출처 검사가 받는다.
  **그 타입과 가드가 덮는 것은 CLI 가 문구를 만드는 두 갈래뿐이다** — 셋째(오류 응답)의
  문구는 답한 쪽이 자기 프로세스에서 만들어 넘기므로 CLI 소스에 볼 `t()` 가 없다.
  스캔 범위를 넓히는 문제가 아니라 문구의 생산지가 프로세스 밖이라는 문제다. 그래서 그
  갈래의 로케일 무관성은 산문이 아니라 `code` 필드가 진다. 실측(2026-09-05, ko 격리
  인스턴스)으로 `codex.hook`·`claude.hook` 둘 다 한국어 `reason` 과 `code=-32602` 를
  남기는 것을 확인했다 — 앞엣것은 사용자가 읽을 산문이고 뒤엣것이 기계가 쓸 좌표다
- **debug 전용 명령**(`#![cfg(debug_assertions)]`)의 진행 출력 — `local/debug.rs` 의
  `stream-echo` 진행 줄. release 표면에 존재하지 않고 에이전트 자기검증용이라
  내부 진단 로그와 같은 자리다([debug-ipc.md](debug-ipc.md))
- JSON-RPC method 이름·프로토콜 토큰
- `tasty list` 계열(`workspaces`/`tree`/`panes`)의 구조 출력이 쓰는 고정 토큰 —
  `(id:N)`/`[mirror]`/`(N panes)`/`[ws:N name]`, 그리고 같은 파일의 구조 출력
  (`agent task-list`·알림 목록)이 쓰는 **빈 상태 토큰**(`No tasks`/`No notifications`).
  한 행 안에서 기계 파싱 대상과 나란히 놓이는
  식별자라, 이 중 하나만 번역되면 그 행 자체가 로케일에 따라 흔들리고, 빈 상태
  토큰이 바뀌면 그 출력을 파이프로 소비하는 에이전트가 깨진다
  (`crates/tasty-cli/src/format.rs` 의 `format_workspace_list` 등 — 이 파일은
  `t()` 호출이 없는 것이 기존 컨벤션이다)
- **매니페스트·설정 키를 그대로 비추는 필드명 행** — `tasty plugin doctor` 의
  `name:`/`version:`/`manifest_version:`/`api_version:` 와 action 요약의
  `surface "…"`/`ipc "…"`(매니페스트 `kind` 값)·handler 행의 `detector`
  (`crates/tasty-cli/src/plugin.rs`), `tasty tool remote-profile show` 의
  `ssh_ref`/`remote_tasty`/`port_mode`/`extra_options` 등 프로필 TOML 키 행과
  `tasty tool passkey show` 의 `name`/`kind`/`value` 행(`local/remote_profile.rs`,
  `local/passkey.rs`). 사용자가 그 단어로 매니페스트·설정 파일을 찾아가는 식별자라
  번역하면 대응이 끊긴다. 같은 출력의 문장·라벨(`Detectors contributed: N`,
  `(no action)` 등)은 `cli.plugin.*` 키다

그 외 사람이 읽는 모든 문자열은 예외 없이 `t()`.

### 위젯 호출이 아닌 경로도 대상이다

`t()` 의 적용 범위는 egui 위젯 인자에 한정되지 않는다. 다음처럼 *위젯 호출 형태가 아닌* 경로로 사람에게 도달하는 문자열도 전부 `t()` 다:

| 형태 | 예 | 키 |
|------|-----|-----|
| 도메인 intent 필드 초기화 | 터미널 BEL 알림의 `DomainIntent::PushNotification { title }` | `notification.bell_title` |
| IPC 파라미터 생략 시 UI 로 흘러가는 기본값 | `notification.create` 의 `title` 생략 | `notification.default_title` |
| `unwrap_or(..)` 폴백 라벨 | 알림 패널의 사라진 출처 워크스페이스명 · 원격 attach mirror 탭 제목 | `notification_panel.unknown_workspace` · `attach.tab_title_fallback` |

같은 값이 **기계 식별에도** 쓰인다면 표시 문자열과 식별 필드를 분리한다 — 알림은 `source` / `HookEvent` 로 식별하고 제목은 번역한다. 제목 문자열 비교로 분기하는 소비자를 만들지 않는다([ADR-0106](../adr/0106-non-widget-user-strings-go-through-i18n.md)).

## 공용 위젯의 문자열 — 호출자 주입

`crates/tasty-ui-widgets` 는 `tasty-i18n` 을 **의존하지 않는다**(egui / tasty-icons /
tasty-egui-theme / tasty-type-* 만). 위젯은 번역 테이블에 접근할 수 없으므로 **자기 문구를
소유할 수 없다** — 문구가 필요한 위젯은 호출자가 `t()` / `t_fmt()` 로 만든 문자열을 파라미터로
주입받고, 위젯은 *어느 문구를 쓸지 고르는 판정*만 한다.

선례: `multi_select` 의 트리거 요약 라벨.

같은 원칙이 `tasty-i18n` 을 의존하지 않는 **다른 leaf 크레이트**에도 적용된다 — 예: `tasty-git-core`(host 와
git-viewer plugin 이 공유하는 데이터 크레이트, [ADR-0056](../adr/0056-git-viewer-remote-attach-git-query-channel.md)).
데이터 크레이트는 "값이 없음"을 빈 문자열/`Option` 으로 돌려주고, 그 자리에 보여줄 문구(메시지 없는 커밋·작성자
미상 등)는 **소비자**가 고른다 — plugin 은 자기 `Translator`(git-viewer: `git_viewer.no_message` /
`git_viewer.unknown_author`), host 는 `t()`. 원격 attach 경로에서는 결과를
만드는 host 가 아니라 받아서 그리는 plugin 이 표시 주체이므로, host 측에서 문구를 채우면 원격 인스턴스의 언어가
로컬 화면에 새어 들어온다([ADR-0106](../adr/0106-non-widget-user-strings-go-through-i18n.md)).

전송 계층도 같다 — `crates/tasty-ipc` 는 wire framing / 세션 크레이트라 `tasty-i18n` 을 의존하지 않는다.
실패는 **조건을 담은 타입**으로 돌려주고(`port_file::PortFileError` — `HomeUnresolved` / `NotFound { path }` /
`Invalid`), 그 조건을 현재 로케일 문장으로 바꾸는 곳은 CLI 한 곳이다(`tasty_cli::port_file::read_port`,
`cli.port_file.*`). 포트 파일 조회는 CLI 의 여러 명령에서 일어나므로 지점마다 문구를 만들면 같은 실패가
명령에 따라 다르게 읽힌다 — 조회를 그 함수 하나로 모아 문구를 단일화한다. `PortFileError` 의 `Display` 는
이 경로를 타지 않는 소비자를 위한 **영어 기본 렌더링**이며 `lang/en.toml` 값과 문자 단위로 같아야 한다
(정합은 `tasty-cli` 테스트가 강제한다 — 갈라지면 같은 실패가 영어로도 두 가지로 읽힌다).

```rust
// 호출자(본체) — 번역은 여기서
let labels = MultiSelectLabels {
    none: t("dag_list.filter_none"),
    some: t("dag_list.filter_some"),   // "{} selected" — 치환 자리는 위젯이 채운다
    all:  t("dag_list.filter_all"),
};
multi_select(
    ui, theme, "dag_status", &mut selected, &opts,
    None,      // 행 단위 disabled 마스크 — 없으면 전부 활성
    &labels,
    None,      // 일괄 토글 행 opt-in — 켜면 문구 2 개도 같이 주입한다(아래)
    width, true,
);
```

일괄 토글 행을 켜는 호출부는 문구를 **같은 방식으로** 주입한다 — "켬" 과 "문구" 가
한 값이라 어긋날 수 없다.

```rust
let all_toggle = MultiSelectAllToggle {
    select_all: t("some_screen.select_all"),
    clear_all:  t("some_screen.clear_all"),
};
// … multi_select(…, &labels, Some(all_toggle), width, true)
```

- 치환 규약은 본체 `t_fmt` 와 같은 `{}` — 위젯이 `replacen("{}", …, 1)` 로 한 번만 채운다.
  호출자는 `t_fmt` 로 미리 채우지 말고 **`{}` 가 남은 원문**을 넘긴다(개수를 아는 건 위젯이다).
- 갤러리 specimen 은 본체가 아니라 카탈로그라 영어 리터럴을 그대로 주입한다.

## 강제 테스트

위 규칙은 가드 테스트 두 개가 집행한다. **자동으로 도는 채널은 없다** — 둘 다
`cargo test --workspace` 에만 들어 있고 그 잡(`test.yml` 의 `test-linux-x64`)은 수동
전용이라, 실제 집행 시점은 병합 후 main 에서 conductor 가 1 회 돌릴 때다(채널 전체는
[`ci-gates.md`](ci-gates.md)). pre-commit hook 도 `cargo test` 를 돌리지 않는다(hook
목록은 [`git-hooks.md`](git-hooks.md)). 그러므로 번역 문자열을 건드린 lane 은 아래
명령을 **직접** 돌린다 — 안 돌리면 누락이 병합 뒤에야 드러난다.

```bash
cargo test --locked --test i18n_key_parity --test no_hardcoded_ui_strings
```

**두 방향은 심각도가 달라서 한 검사로 합치지 않는다.** 누락(소스가 부르는데 카탈로그에 없다)은 화면에 raw 키가 뜨는 **시끄러운** 결함이고, 고아(카탈로그에 있는데 아무도 안 부른다)는 아무것도 안 깨지는 **조용한** 결함이다. 하나로 합치면 빨강 하나가 두 성질을 뜻하게 되고, 고쳐야 할 것과 지워도 되는 것이 같은 줄에 섞인다. 명부도 방향마다 따로다 — 누락 유예(`PENDING_FIX_MISSING_KEYS`)는 **비어 있는 것이 정상**이고, 고아 명부(`ORPHAN_KEYS`)는 항목을 갖고 산다 — 실측상 전부 **호출부가 사라진 뒤 아직 정리하지 못한 키**이고, 사유 칸이 그 자리를 짚었는지("L2 사이드바로 옮겨가며 없어졌다") 아직 못 짚었는지를 구분해 적는다.

**검사하지 않는 것** — 위 "하드코딩 허용 예외" 를 그대로 옮긴 목록이며 테스트 상수의
주석에도 같은 내용이 있다: 수식키·키 이름, 폰트 프리뷰, 언어 이름, 단위(`MiB`), 제품명
`Tasty`, `tracing::*` 로그, clap 의 **영어** 도움말, JSON-RPC 메서드명, `tasty list` 구조
출력(`crates/tasty-cli/src/format.rs` 통째로), clap 도움말 보강 출력(`crates/tasty-cli/src/help.rs` —
clap 의 영어 about 텍스트와 한 화면), 갤러리 specimen(`crates/tasty-gallery/`), 데모 plugin,
TUI 시뮬레이터, `debug/` 디렉토리, panic hook(`src/platform/crash_report.rs`), HTTP reason phrase
같은 프로토콜 토큰, `#[cfg(test)]`/`#[test]` 가 붙은 아이템의 본문(테스트 모듈 뒤의 코드는 스캔),
`//` 주석, 그리고 리터럴이 아닌
인자(변수·`format!`)와 `anyhow!`/`bail!` 메시지 — 변수에 담긴 영어 문장과 anyhow 에러 문구는 잡지
못하므로 리뷰가 남는 몫이다. 값 형태로 자동 예외되는 것(기호·숫자만인 값, 다섯 자 이하 약어, 경로·URL·
`tasty …` 명령, 소문자 단일 단어 폴백)도 등록이 필요 없다.

**잔존 위반의 처리** — 두 테스트는 `PENDING_FIX_*` 상수에 알려진 위반을 파일·리터럴(또는 키)·
고칠 방법과 함께 둔다. 그 항목이 사라지면(=고쳐지면) 목록에서 지우라고 fail 하므로 빚이 조용히
남지 않는다. 새 위반을 여기 넣어 덮지 않는다 — 고치는 것이 기본이다.
