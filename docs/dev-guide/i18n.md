# 국제화 (i18n)

모든 UI 문자열은 `t()` 계열을 통해 번역 키로 노출한다. 영어/한국어/일본어를 코드에 직접 하드코딩하지 않는다. 강제 정책은 [`../../CLAUDE.md`](../../CLAUDE.md) "국제화".

## API

번역 스토어는 leaf 크레이트 `tasty-i18n` 에 있다(전역 `OnceLock`). 본 바이너리는 `crate::i18n` 으로 재수출하고 `tasty-cli` 는 `tasty_i18n` 을 직접 의존 — **둘 다 같은 전역 테이블**을 공유한다.

```rust
pub fn t(key: &str) -> &str;                        // 단순 조회
pub fn t_fmt(key: &str, arg: &str) -> String;       // {} 1개 치환
pub fn t_fmt2(key: &str, a1: &str, a2: &str) -> String; // {} 2개
pub fn t_args(key: &str, args: &[&str]) -> String;  // {} N개 (CLI 등 3+ 인자)
pub fn current_language() -> &'static str;
pub fn register_namespace(plugin_id: &str, lang_dir: &Path);
pub fn unregister_namespace(plugin_id: &str);
```

- **키를 못 찾으면 키 문자열을 그대로 반환** — 누락이 화면에 드러나 회귀를 즉시 노출.
- placeholder 는 키 값 안의 `{}` 를 순서대로 치환.

```rust
ui.label(t("settings.appearance.custom_font_label")); // ✅
ui.label("Custom font file:");                         // ❌
```

## 번역 파일 위치

| 대상 | 경로 | 로드 |
|------|------|------|
| 본 바이너리 임베드 | `lang/{en,ko,ja}.toml` (워크스페이스 루트) | 시작 시 `include_str!` |
| 번들/외부 plugin | plugin 디렉토리 `lang/{en,ko,ja}.toml` | plugin 활성화 시 `register_namespace` |
| 사용자 오버라이드 | `~/.tasty/lang/{code}.toml` | 시작 시 베이스 위에 overlay |

언어 선택은 `~/.tasty/config.toml` 의 `general.language`(`en`/`ko`/`ja`), 변경 시 재시작. 오버레이 계층: **영어 베이스 → 선택 언어 → 사용자 커스텀**, 누락 키는 한 단계 아래로 fallback.

## 새 문자열 추가 절차

1. 코드에 `t("namespace.key")` 호출 먼저 추가.
2. `lang/en.toml`·`ko.toml`·`ja.toml` **세 파일 모두** 같은 키 추가. (누락 시 fallback 영어 or 키 노출.)
3. plugin 문자열이면 그 plugin 의 `lang/` 에 추가.

키 네이밍: `<영역>.<서브영역>.<항목>` (점 계층, 예: `settings.appearance.theme_label`).

## 문체 (톤)

| 언어 | 종결 | 예 |
|------|------|-----|
| en | 평서문 · 명령형 그대로 | `It may have been deleted. Pick another from the header.` |
| ko | 존댓말 `~합니다` / 권유는 `~하세요`. 평서형 `~한다` · 하라체 `~하라` 금지 | `삭제되었을 수 있습니다. 헤더에서 다른 DAG 를 선택하세요.` |
| ja | ですます체. 常体(`~する` / `~ない` / `~選ぶ`) 금지 | `削除された可能性があります。ヘッダーから別の DAG を選択してください。` |

- **명사구는 규칙 밖이다** — 버튼 · 라벨 · 컬럼 헤더 · 빈 상태 제목처럼 종결어미가 없는
  문자열은 그대로 둔다(`닫기` / `DAG 없음` / `閉じる`).
- **프로젝트 문서의 문체를 lang 파일로 가져오지 않는다.** `CLAUDE.md` 와 `docs/` 는
  `~한다` 체를 쓰지만 UI 문자열은 사용자에게 말을 거는 자리라 화자 태도가 다르다.

## OS 네이티브 표면

egui 밖의 OS 네이티브 UI 도 사용자 표면이라 예외가 아니다. 라벨은 전부 `t()` 이고 단축키(key equivalent)는 별도 정책([key-mapping](../design/policies/key-mapping.md))이라 서로 독립이다.

| 표면 | 키 | 코드 |
|------|----|------|
| macOS 메뉴바(NSMenu) + Dock 메뉴 | `menu.macos.*` | `src/platform/macos_delegate.rs` |
| 시스템 트레이 메뉴·툴팁(3 OS) | `tray.*` | `src/platform/system_tray.rs` |
| Windows 작업표시줄 Jump List | `jump_list.*` | `src/platform/jump_list.rs` |

- 앱 이름을 결합하는 macOS 항목(About / Hide / Quit)은 키 값에 `{}` 를 두고 `t_fmt(key, &process_name)` 로 채운다 — 언어별 어순("About Tasty" / "Tasty 가리기" / "Tastyを非表示")을 리터럴 결합으로는 맞출 수 없다.
- ko/ja 의 macOS 메뉴 값은 OS 표준 메뉴 관용 표기(Apple 용어집)를 따른다 — 옆에 놓이는 다른 앱 메뉴와 같은 말을 써야 한다.
- Windows `w!()` 는 컴파일 타임 리터럴이라 번역 문자열에 쓸 수 없다 — 런타임에 null-terminated `Vec<u16>` 로 만들어 `PCWSTR` 로 넘기고, 호출이 끝날 때까지 버퍼를 살려 둔다. 실행 인자 토큰(`"new-window"`)만 `w!()` 로 남는다.
- 모든 호출 지점은 `locale::init()` 이후(macOS delegate 주입 / `resumed()`)라 부팅 순서 문제는 없다.

## Plugin 네임스페이스

활성화 시 `register_namespace(plugin_id, &lang_dir)` 로 overlay 합류. 키 충돌 방지를 위해 plugin 은 자기 키를 `<plugin_id>.<...>` 로 prefix 한다. 비활성/제거 시 `unregister_namespace` 로 정리. (문자열은 `Box::leak` 으로 `&'static` 을 만족 — 활성화 빈도가 낮아 누수는 무시할 수준.)

## CLI 출력 문자열

`tasty <subcommand>` 의 client 모드는 본 바이너리와 **같은 프로세스**에서 돌아(부팅 시 `locale::init()`), GUI 와 동일한 번역 테이블을 쓴다. `tasty-cli` 에서 `tasty_i18n::{t, t_fmt, t_args}` 를 직접 호출한다.

- 키 prefix 는 `cli.<명령>.<항목>` (예: `cli.remote_check.not_found`).
- 인자 3+ 메시지는 `t_args(key, &[...])`.

### 하드코딩 허용 예외

번역하면 의미가 변하는 고유명사·고정 식별자는 허용:

- 수식키 이름(`Ctrl`/`Alt`/`Shift`/`Cmd`), 단축키 조합 표시(`Ctrl+Shift+P`)
- 폰트 프리뷰 텍스트(`AaBbCcDdEeFfGg`), 언어 이름 자체(`English`/`한국어`/`日本語`)
- 내부 진단 `tracing::*` 로그(사용자 표면 아님)
- `clap` 파생 매크로의 `about`/`help`(정적 메타데이터, 별도 도움말 i18n 체계 전까지 예외).
  clap 항목(서브커맨드 variant · `#[arg]` 필드)의 `///` doc comment 는 그대로 help 로
  노출되므로 **영어로만** 쓴다 — 한국어·일본어 혼재 금지. 개발자용 배경 설명(설계 근거,
  원칙 번호 인용 등)은 help 가 아니라 `//` 주석이나 `docs/` 에 둔다
  ([`cli-structure.md`](cli-structure.md) "도움말 문구")
- JSON-RPC method 이름·프로토콜 토큰
- `tasty list` 계열(`workspaces`/`tree`/`panes`)의 구조 출력이 쓰는 고정 토큰 —
  `(id:N)`/`[mirror]`/`(N panes)`/`[ws:N name]`. 한 행 안에서 기계 파싱 대상과
  나란히 놓이는 식별자라, 이 중 하나만 번역되면 그 행 자체가 로케일에 따라
  흔들린다(`crates/tasty-cli/src/format.rs` 의 `format_workspace_list` 등 —
  이 파일은 `t()` 호출이 없는 것이 기존 컨벤션이다)

그 외 사람이 읽는 모든 문자열은 예외 없이 `t()`.

## 공용 위젯의 문자열 — 호출자 주입

`crates/tasty-ui-widgets` 는 `tasty-i18n` 을 **의존하지 않는다**(egui / tasty-icons /
tasty-egui-theme / tasty-type-* 만). 위젯은 번역 테이블에 접근할 수 없으므로 **자기 문구를
소유할 수 없다** — 문구가 필요한 위젯은 호출자가 `t()` / `t_fmt()` 로 만든 문자열을 파라미터로
주입받고, 위젯은 *어느 문구를 쓸지 고르는 판정*만 한다.

선례: `multi_select` 의 트리거 요약 라벨.

```rust
// 호출자(본체) — 번역은 여기서
let labels = MultiSelectLabels {
    none: t("dag_list.filter_none"),
    some: t("dag_list.filter_some"),   // "{} selected" — 치환 자리는 위젯이 채운다
    all:  t("dag_list.filter_all"),
};
multi_select(
    ui, theme, "dag_status", &mut selected, &opts,
    None,      // 행 단위 disabled 마스크 — 없으면 전부 활성
    &labels,
    None,      // 일괄 토글 행 opt-in — 켜면 문구 2 개도 같이 주입한다(아래)
    width, true,
);
```

일괄 토글 행을 켜는 호출부는 문구를 **같은 방식으로** 주입한다 — "켬" 과 "문구" 가
한 값이라 어긋날 수 없다.

```rust
let all_toggle = MultiSelectAllToggle {
    select_all: t("some_screen.select_all"),
    clear_all:  t("some_screen.clear_all"),
};
// … multi_select(…, &labels, Some(all_toggle), width, true)
```

- 치환 규약은 본체 `t_fmt` 와 같은 `{}` — 위젯이 `replacen("{}", …, 1)` 로 한 번만 채운다.
  호출자는 `t_fmt` 로 미리 채우지 말고 **`{}` 가 남은 원문**을 넘긴다(개수를 아는 건 위젯이다).
- 갤러리 specimen 은 본체가 아니라 카탈로그라 영어 리터럴을 그대로 주입한다.
