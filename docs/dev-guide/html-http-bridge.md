# HTTP transport bridge

The `tasty-ipc` HTTP leaf defines an opt-in Control-frame family separate from file HTML transfer. It does not enable or advertise a remote HTTP viewer. The leaf is publicly exported for shared host/client integration. Export alone does not activate dispatch or advertise capabilities; those require working server and native routes.

`HttpRequest` and `HttpReply` preserve the six-field transfer identity, source generation and server-issued response serial. Only encoded chunks cross this wire. Complete carries both encoded and decoded byte lengths and SHA256 identities. Clients assemble and verify the encoded body, decode under a separate bounded worker quota, verify the decoded identity and scan before exposing a body to native rendering. Native must receive the same immutable encoded representation with matching status and end-to-end headers.

Both directions validate the complete serialized frame before enqueue. Header order, duplicate names and non-UTF8 value bytes are retained. Metadata, header counts/bytes, methods, chunk windows, decoded base64 and portable lengths are bounded. HTTP DTOs deliberately omit Debug implementations for request URLs, headers and payloads. Failure reasons must be sanitized by their producer; validation bounds their size and rejects control characters.

The HTTP and HTTPS capabilities additionally require the existing HTML transfer capability. Existing file wire messages and old-peer behavior remain unchanged. The server descriptor must not advertise an executor merely because these types compile. Native parsing, TLS exceptions, cache retirement and browser consent are separate integration obligations.

## Server ownership and flow

`remote::html_http_server::Server` receives an already constructed finite HTTP Backend and the same injected resource limits. Construct network/TLS clients on a setup worker. Server admission, commands and polling perform no network I/O, runtime construction or waiting joins.

The engine captures its actual registration, SSH grant, source Weak and generation before calling `admit(Capture)`. Capture contains the authoritative entry identity and reported URL plus the document's fixed client cross-origin policy. Retain that actual authority alongside the returned opaque OwnerToken. Pass that token and a current-authority predicate on every `handle` and `poll`; matching client numbers cannot manufacture this local token. A failed predicate retires the owner and drops queued core events. `retire` also handles disconnect, source replacement and fresh Reload. The caller remains responsible for invalidating frames already handed to its connection and fencing native publication by full identity.

GUI and headless consume one ordered inbound File/Http Control queue. A peer must declare both transfer and HTTP support before its validated HTTP commands enter this queue. The current host returns a fixed unsupported failure without constructing an executor or contacting upstream; it does not advertise HTTP/HTTPS support. StreamHub::admit_html_request owns the registration-scoped request and transfer high-watermarks and compares the captured binding under the same sink lock. Current file admission uses this allocator; the still-closed HTTP route must call it for new Begin only, after existing-document duplicate classification. Both counters must increase and a rejected claim advances neither. Registration replacement resets the new cursor without allowing the old binding to reset it back. Run it before new Begin admission; subsequent upload, commit, credit and lifecycle commands allocate no identity. An HTTP document's first Begin must name its captured entry and exact reported URL. Later requests stay subject to the core origin policy. Shared dispatch, descriptor advertisement and real GUI/headless collector activation belong to the integrating host.

Begin reserves one bounded request/tombstone slot and checks the declared upload size before assembly. Poll grants a single exact-offset upload window. Commit freezes the upload only after complete length and SHA verification, then calls the existing Document.open once. Duplicate admission uses the executor-equivalent normalized method, fragment-free URL, upload identity and ordered cleaned headers. Keep this admission signature aligned with the finite backend's header cleaner and fingerprint; differential component tests compare the public executor's pending/retired duplicate decisions. A failed or cancelled ID cannot be used for another POST.

Each running request retains only its core one-slot event channel. Poll returns at most one validated Control frame and keeps no additional encoded output queue. Reserve MAX_FRAME_LEN plus FRAME_HEADER_LEN in the connection's existing byte budget before polling; charge the actual payload plus framing after return. If that reservation is unavailable, poll leaves the event in the bounded core channel. The integrating host schedules polling through its existing pump/timer while work is pending; the bridge does not create a thread or event loop. Send errors retire that connection's captured owners. Synchronous command errors can be converted with failure_reply and sent through that same bounded connection queue; stale ownership does not authorize publication to a replacement owner.

## Connection sender accounting

StreamHub::reserve_frame captures the actual registration and an injected connection wire-byte limit before executor polling. Its non-cloneable reservation accounts for MAX_FRAME_LEN plus FRAME_HEADER_LEN alongside all queued/live frames and other reservations. Publish with push_reserved, which reconciles to actual payload length plus framing and rejects a replaced registration. Existing traffic keeps its frame-count admission policy and contributes to the reservation counter.

The production socket writer uses recv_held_timeout and holds the byte lease through write success or failure. Every held frame carries a weak registration identity; reserved frames may additionally capture the unique PublicationFence retained by their actual document/grant owner. The writer checks those identities before writing, so a replacement owner cannot authorize an old queued frame. The engine must drop the fence on actual source/grant loss; a socket write already started cannot be retracted by this check. Dropped reservations and failed queues release their charges; legacy raw-frame convenience methods release at dequeue.

This API is connected to the actual sender/writer, while the HTTP executor collector remains closed. The wire-byte counter is separate from decoded/retained memory capacity and encoded document consent accounting. HTTP/HTTPS capabilities remain unadvertised.

## Response lifecycle

Credit names the full ResponseId, exact offset and one outstanding window. Known large responses require their own Allow. Unknown responses stop at encoded byte100001; a positive EOF probe at exactly100000 may produce completion without an Allow question. Client aggregate reservations and Continue remain independent of response Allow. The server's transferred_bytes counter records actual encoded chunks only, including short-window reconciliation; it never counts reuse as network traffic. Core payload quotas remain independent resource bounds.

Complete leaves the immutable response retained in the core. Reuse emits the identical Head and both Complete identities without Chunk or network traffic; the client must already retain verified bodies. Release records the core tombstone. Stop cancels pending uploads and operations, blocks new requests and preserves successfully completed retention. Close retires the whole owner. Cancellation drops the operation without waiting; the core task retains its worker permit until actual network/decode termination. The owner of the injected runtime must complete asynchronous retirement before shutting that runtime down.

Component tests cover real finite Backend requests through a loopback HTTP fixture, upload windows and commit SHA, full identities, duplicate normalization, encoded gzip identities, exact size thresholds, cancellation and stale authority with a real completion already queued, and bounded admission. A standalone module harness does not establish actual App dispatch, negotiated native routes, native certificate challenge behavior, client aggregate consent or browser rendering. Those require the integrating host's reachable GUI/headless/native checks before capability advertisement.
