# ADR 재번호

`docs/adr/` 의 ADR 을 새 번호로 옮기고, 레포 전체에서 그 번호를 부르는 자리를 **한 번에** 고치는
도구(`adr-renumber` bin)다. 문제는 번호가 아니라 인용이다 — 번호는 수천 자리에서 불리고, 한
자리라도 틀리면 죽은 링크나 **엉뚱한 ADR 을 가리키는 링크**가 된다. 뒤쪽은 어떤 가드도 못 잡는다.

판정 규칙은 `crates/tasty-doc-guards/src/adr_renumber.rs`, 파일 · git 부수효과는
`crates/tasty-doc-guards/src/bin/adr-renumber.rs`, 합성 레포 시험은
`crates/tasty-doc-guards/tests/adr_renumber_bin.rs` 에 있다.

번호 변경을 명시적으로 요청받은 대규모 재정리에 사용한다. 평소에는 기존 번호를 유지한다.
[ADR 작성과 관리](../adr/0050-architecture-decision-records.md)에 따라 이전 번호와 새 번호의 대응표를
보관하고, 저장소 안의 인용을 모두 갱신한다. 다른 브랜치나 외부 링크의 옛 번호는 자동으로 바뀌지 않는다.

## 명령

```bash
cargo run -p tasty-doc-guards --bin adr-renumber -- <매핑 파일> --report <보고 경로>          # dry-run (기본)
cargo run -p tasty-doc-guards --bin adr-renumber -- <매핑 파일> --write --report <보고 경로>  # 쓴다
```

`--report` 를 빼면 보고가 표준 출력으로 나온다. 요약 한 줄은 늘 표준 오류로 나온다. `--root
<디렉토리>` 로 레포 루트를 준다(생략하면 현재 디렉토리). 보고 파일은 레포 밖(세션 scratchpad 등)에
둔다 — 레포 안에 두면 다음 `--write` 가 작업 트리가 더럽다고 거절한다.

**쓰기는 `--write` 로만 한다.** `--write` 는 작업 트리가 깨끗할 때만 돈다 — 되돌릴 수 있어야 하고
diff 가 이 도구의 것만이어야 해서다.

## 매핑 파일

한 줄에 `<옛 번호> <새 번호|DELETE>`. 빈 줄과 `#` 로 시작하는 줄은 무시한다.

```text
# 살아남는 것은 새 번호로
0005 0001
0009 0002
# 제자리도 적는다
0003 0003
# 규칙 문서로 흡수된 것
0004 DELETE
```

거절하는 것(rc 2): 칸이 둘이 아닌 줄 · 지금 없는 옛 번호 · 옛 번호 중복 · 새 번호 중복 · `0000` ·
**매핑에 빠진 ADR.** 모든 ADR 이 한 번씩 나와야 한다 — 빠진 것을 제자리로 두면 누군가의 새 번호와
겹칠 수 있고, 그 겹침은 같은 번호에 파일이 둘인 상태로만 드러난다.

## 하는 일 (`--write`)

1. 고치는 형태(아래 표)에 든 자리를 **한 번에** 새 번호로 바꾼다. 교환(A↔B)이 연쇄로 되돌아가지
   않는다.
2. `DELETE` 인 ADR 을 `git rm` 한다.
3. 살아남는 ADR 을 `git mv` 로 새 번호로 옮긴다(slug 는 그대로). 늘 임시 이름을 거쳐 두 단계로
   옮긴다 — 새 경로가 아직 옮기기 전의 다른 파일 자리일 수 있다.
4. `docs/adr/index.md` 의 생성 구역을 `adr-index` 와 같은 함수(`render_index`)로 다시 만든다.
   생성 구역 안은 1 단계에서 안 건드린다 — 행의 순서가 번호순이라 자리에서 고치면 순서가 틀린다.

끝나면 `cargo run -p tasty-doc-guards --bin adr-index -- --check` 와
`cargo test -p tasty-doc-guards` 를 돌린다. 앞쪽은 인덱스, 뒤쪽은 링크 · 앵커 · 결정 사슬이
풀리는지 본다(`cited_coordinates_exist` · `cited_anchors_resolve` · `adr_index_parity`).

## 형태 — 무엇을 고치고 무엇을 안 고치나

도구는 **좌표를 스스로 들고 있는 형태만** 고친다. 문맥으로 "이 네 자리는 ADR 이다" 를 추론하지
않는다 — 그 추론은 양방향으로 틀리고 틀린 쪽이 조용하다.

| 형태 | 예 | 고치나 |
|---|---|---|
| 파일명 | `NNNN-slug.md` — 앞에 `](` · `](../adr/` · `docs/adr/` 가 붙은 것, 뒤에 앵커가 붙은 것, 확장자 없는 `NNNN-slug` | 고친다. slug 가 그 번호의 실재 파일과 **끝까지** 같을 때만 — 앞에 무엇이 붙었든(상대 경로 깊이 · 백틱 · 따옴표 · 주석) 같은 형태다 |
| 접두 | `ADR-NNNN` · `[ADR-NNNN]` · 헤더 `# ADR-NNNN:` · Tags 의 `adr-NNNN` · 앵커 안 `adr-NNNN` · 시험 함수 이름 `adr_NNNN_…` · `ADR NNNN` · `ADR #NNNN` | 고친다(대소문자 무관, 앞이 영숫자면 안 본다) |
| 접두 목록 | `ADR-NNNN/MMMM` · `ADR-NNNN·MMMM` · `ADR-NNNN+MMMM` · `[ADR-NNNN]/MMMM` | 고친다. 쉼표 · `~` 범위는 목록으로 안 본다 |
| 링크 텍스트 | `[NNNN]` · `` [`NNNN`] `` — 바로 뒤 링크 대상의 마지막 마디가 `NNNN-slug.md` | 고친다 — 링크 대상 파일명의 번호와 같을 때만 |
| 인덱스 머리말 | `docs/adr/index.md` 생성 구역 밖의 `0019 → 0022` | 고친다 — 인덱스 가드(`preamble_violations`)와 같은 술어 `bare_numbers` 로 |
| 인덱스 생성 구역 | `\| NNNN \| [제목](NNNN-slug.md) \|` | 자리에서 안 고치고 **다시 만든다** |
| 맨 네 자리 | 산문 속 `NNNN 의 결정은` · `(NNNN · MMMM)` · `NNNN~MMMM` · `ADR-NNNN, MMMM` 의 뒤쪽 | **안 고친다** — 보고의 "맨 네 자리" 절에 줄째 나온다. 날짜 · 측정값 · 코드포인트와 가를 표지가 없다 |
| slug 가 다른 파일명 | `NNNN-x.md`(실재 파일 없음) | **안 고친다** — 이미 죽은 링크거나 픽스처다 |
| vendored 사본 | `site/vendor/**`(그 README 제외) | **안 고친다** — 원격 디자인 킷의 사본이다. 원격을 고치고 다시 받는다([`site/vendor/README.md`](../../site/vendor/README.md)) |
| 픽스처 파일 | 가짜 ADR 을 문자열로 담은 시험 · 판정기 파일(bin 의 `FIXTURES`) | 파일명 형태만 고친다. 나머지는 보고만 — 픽스처의 짝(`[ADR-NNNN](NNNN-x.md)` 과 기대값)이 한쪽만 바뀌면 시험이 깨진다 |

훑는 범위는 `git ls-files` 전체다. UTF-8 이 아닌 파일은 건너뛰고 그 수를 보고에 적는다.

## 보고

보고는 형태 표(형태마다 **매핑에 있는 번호를 본 자리** · 그중 고칠 자리) 뒤에 절 여섯을 낸다.
각 줄은 `경로:줄: [형태 옛→새] 그 줄`.

- **삭제되는 ADR 을 부르는 자리 (막는다)** — 아래.
- **매핑 밖 번호가 새 번호와 겹치는 자리** — 지금 없는 번호(이미 죽은 인용)인데 재번호 뒤 다른
  ADR 이 그 번호를 받는다. 고치기 전까지 그 자리는 엉뚱한 ADR 을 가리킨다.
- **맨 네 자리** · **slug 가 다른 파일명** · **vendored 사본** · **픽스처 파일의 파일명 밖 형태** —
  위 표의 "안 고친다" 칸들.

## 삭제되는 ADR 을 부르는 자리

`DELETE` 인 ADR 을 고치는 형태로 부르는 자리가 하나라도 남아 있으면 dry-run 은 rc 1 로 그
목록을 내고, `--write` 는 **아무것도 안 쓰고** rc 1 로 끝난다. 그 자리를 남긴 채 번호를 옮기면 옛
번호 `ADR-NNNN` 이 그 번호를 새로 받은 **다른 ADR 을 조용히 가리킨다** — 파일명 형태는 죽은
링크로 가드에 걸리지만, 접두 형태에는 판정할 좌표가 없다. 그래서 순서는 둘이다.

1. dry-run 으로 목록을 받아, 그 자리를 **흡수된 규칙 문서를 가리키는 링크나 내용**으로 사람이
   바꾸고 커밋한다. 삭제 대상 ADR 자신의 본문과 인덱스 생성 구역은 목록에 안 나온다(함께
   사라진다).
2. 목록이 비면 `--write` 를 돌린다.

맨 네 자리 형태로 삭제 대상을 부르는 자리는 막지 않는다(판정할 수 없다) — 보고의 "맨 네 자리"
절에 같이 나오니 1 단계에서 함께 읽는다.

## 도구가 못 보는 것

- **맨 네 자리 인용.** 산문 속 번호(`NNNN 의 결정`), 쉼표 목록의 뒤쪽, `~` 범위. 보고에 줄째
  나오지만 고치는 것은 사람이다. 안 고치면 조용히 다른 ADR 을 가리킨다.
- **git 이 추적하지 않는 것.** 미커밋 새 파일(그래서 `--write` 는 깨끗한 트리를 요구한다), 다른
  브랜치 · worktree 의 진행 중 작업, 커밋 메시지, 이미 발행된 사이트 · 외부에 붙은 링크. 재번호 뒤
  병합되는 브랜치는 **옛 번호로 쓴 인용**을 가져온다 — 파일명 형태는 죽은 링크로 가드에 걸리지만
  접두 형태는 안 걸린다.
- **코드가 조립하는 번호.** `format!("ADR-{num}")` 처럼 실행 중에 만드는 인용.
- **vendored 사본.** 보고만 한다. 원격 킷이 고쳐져 다시 받기 전까지 사이트 컴포넌트 주석이 옛
  번호를 든다.
- **픽스처 파일 안의 실제 인용.** 판정기 파일의 주석이 실제 ADR 을 접두 형태로 부르면 그 자리는
  보고에만 나온다.
