# ADR 인덱스 관리

[ADR 인덱스](../adr/index.md)의 표 행은 ADR 헤더에서 생성한다.
그룹 목록과 그룹 설명은 사람이 쓴다. 결정 이유는
[ADR 작성과 관리](../adr/0649-architecture-decision-records.md)에 있다.

## 파일 구조

각 그룹은 제목, 짧은 설명, 생성 구역으로 구성한다.

```text
## <그룹 제목>

<현재 규칙을 설명하는 문서와 관련 결정>

<!-- adr-rows:begin <slug> -->
<생성된 표>
<!-- adr-rows:end <slug> -->
```

ADR 헤더의 `Group`은 이 slug 하나를 가리킨다.
생성기는 제목의 강조 표시와 중복 공백을 정리하고, Status의 괄호 밖 첫 ` — ` 뒤 설명을 줄인다.
Date와 Tags는 헤더에서 가져오며 행은 번호순으로 만든다.
마커 밖에는 ADR 표 행을 직접 쓰지 않는다.

## 명령

```bash
cargo run -p tasty-doc-guards --bin adr-index -- --write
cargo run -p tasty-doc-guards --bin adr-index -- --check
cargo test -p tasty-doc-guards --test adr_index_parity
```

| 종료 코드 | 뜻 |
|---|---|
| 0 | 인덱스가 생성 결과와 같고 모든 ADR이 한 행씩 있음 |
| 1 | 행 차이, 누락·중복, 생성 구역 밖 표 행이나 충돌 표지 등 정리할 내용이 있음 |
| 2 | 인자·마커 구조·파일 접근 문제 등으로 생성할 수 없음 |

`--write`는 생성 구역만 바꾼다. Group이 없거나 알 수 없는 slug면 ADR이 빠질 수 있어
생성 결과와 현재 파일이 같더라도 실패한다. 헤더를 먼저 고쳐야 한다.

## 언제 돌리나

ADR을 추가하거나 제목·상태·날짜·태그·그룹을 바꾸면 생성기를 실행한다.
병합 충돌은 다음 순서로 해결한다.

1. ADR 본문의 충돌부터 해결한다. 헤더가 잘못되면 생성 결과도 잘못된다.
2. 인덱스의 마커가 한 쌍씩 있는지 확인한다. 중복되거나 충돌이 마커를 가로지르면 먼저 정리한다.
3. `--write`로 생성 구역을 다시 만든다.
4. 구역 밖의 설명은 양쪽 변경 내용을 읽고 합친다. 남은 충돌 표지와 구역 밖 표 행도 정리한다.
5. `--check`와 인덱스 가드를 실행한다.

인덱스 파일 전체를 ours/theirs 중 하나로 받으면 자동 병합된 상대의 설명까지 잃을 수 있다.
생성기는 사람의 설명을 복구하지 못한다. 구역 밖에 남은 표 행을 지우기 전에는 해당 ADR이
생성 구역에 실제로 들어갔는지 확인한다.

## 가드가 보는 것

`adr_index_parity`는 번호 유일성, 제목과 파일명의 번호 일치, 필수 헤더,
생성 결과 일치, 그룹 존재·단일 소속, 결정 관계의 양쪽 참조, 머리말의 ADR 번호와
충돌 표지를 확인한다. 의미가 같은 두 결정인지는 판단하지 않는다.

기존 관계를 유지할 때는 `개정 대상:` ↔ `부분 개정:`, `통합 대상:` ↔ `중복 조항 통합:`을
양쪽에 적는다. 전체 대체라면 Superseded 상태와 대체한 문서의 참조를 확인한다.
괄호 안의 부연 링크는 관계 선언으로 세지 않는다.

## 채널

자동 실행 경로는 [CI 가이드](ci-gates.md)에서 확인한다.
커밋 전에 바로 확인하려면 위 명령을 직접 실행한다.
라이브러리 검사와 생성기 실행 결과는 다르므로 생성기 종료 코드도 읽는다.

## 착지 때 새 ADR 끼리 대조

여러 작업을 병합하기 전에 추가·변경·이동한 ADR을 함께 읽는다.
각 작업에서 검색할 때는 다른 작업의 새 문서를 볼 수 없었을 수 있기 때문이다.

```bash
bash scripts/adr-landing-report.sh <base> <tip>
bash scripts/adr-landing-report.sh --candidates-only <base> <tip>
```

도구는 제목과 Decision의 심볼·파일·설정 키에서 겹침 후보를 찾는다.
후보는 사람이 같은 주제의 기존 ADR과 함께 읽고 선택·적용 범위·근거를 비교한다.
흔한 심볼의 일치는 중복의 증명이 아니고, 후보가 없다는 것도 중복이 없다는 증명이 아니다.
중복은 [템플릿](../adr/template.md)의 기준으로 정리하고 인용과 인덱스를 갱신한다.

보고 도구는 후보 유무와 관계없이 정상 조회면 0, rev·객체·Git 조회 실패면 2로 끝난다.
CI가 자동으로 중복을 해결하거나 이 보고를 읽는다고 가정하지 않는다.
