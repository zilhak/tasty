# 착지 때 새 ADR 끼리 대조하기

여러 lane 의 산출물을 `main` 에 착지시킬 때(병합 · cherry-pick 통합 · 롤업 커밋) **이번 착지로
들어오는 ADR 끼리, 그리고 같은 주제의 기존 ADR 과 같은 조항을 결정하지 않는지** 대조하는 절차다.
근거·대안·재검토 조건은 [ADR-0508](../adr/0508-landing-lines-up-incoming-adrs-before-the-commit.md).

## 왜 착지 때인가

작성 시점의 탐색([`adr/template.md`](../adr/template.md) "새 ADR 을 쓰기 전에")은 **작성하는
트리에 이미 있는 ADR** 만 본다. 두 lane 이 같은 base 에서 동시에 갈라져 서로의 ADR 을 한 번도
트리에 갖지 않은 채 같은 조항을 쓰면, 작성 시점 탐색은 원리적으로 상대를 못 만난다. 두 문서가
처음 한 트리에 놓이는 순간이 착지다. 이 절차는 그 빈칸만 메우는 **보조 층**이다 — 주 방어는
작성 시점 탐색이다.

번호 충돌은 `crates/tasty-doc-guards/tests/adr_index_parity.rs` 가 잡는다. 인덱스(`docs/adr/index.md`)가 충돌했으면 행은 손으로 합치지 말고 생성기로 다시 만들되, 머리말(생성 구역 밖)은 양쪽을 사람이 합친다 — 파일째 한쪽을 받으면(`git checkout --ours` 등) 상대 쪽 머리말이 조용히 사라진다. 순서는 [adr-index](adr-index.md) 의 "언제 돌리나". 번호가 다르고 조항이
같은 것은 git 도 충돌로 보지 않고(서로 다른 파일이다) 어떤 가드도 안 본다. lane 소스 교집합으로
재완주 생략을 판정할 때도 ADR 끼리는 파일이 달라 교집합 0 으로 통과한다.

## 절차 — 착지마다 한 번

롤업이든 개별 병합이든 **착지 커밋을 만들기 전에** 돈다.

1. **목록을 뽑는다.** 이번 착지로 추가·변경·이름이 바뀐 ADR 전부다. `A` 만 보면 기존 ADR 을
   부분 개정·보강하는 lane 끼리의 겹침(같은 ADR 을 두 lane 이 서로 다르게 고친 것)이 빠진다.

   ```bash
   bash scripts/adr-landing-report.sh <base> <착지 tip>
   bash scripts/adr-landing-report.sh --candidates-only <base> <착지 tip>   # 범위가 클 때 요약만
   ```

   도구는 ADR 마다 제목과 Decision 절의 백틱 인용 이름(심볼 · 파일 · 설정 키)을 찍고, 같은 뿌리
   이름에 둘 이상 걸린 것을 **겹침 후보**로 모은다. `M` 은 References 한 줄 errata 도 포함하므로
   사람이 걸러 읽는다.
2. **후보를 읽는다.** 같은 이름에 걸린 ADR 들의 Decision 을 나란히 읽고 같은 조항을 결정하는지
   판단한다. 흔한 이름(`#[cfg(test)]` · `src/` 같은 것)은 대부분 우연이다 — 후보는 판정이 아니다.
3. **기존 ADR 과도 본다.** 후보가 아닌 새 ADR 도 [`adr/index.md`](../adr/index.md) 의 같은 주제
   그룹을 열어 제목을 훑는다. 의심되면 그 결정 대상 심볼로 `git grep -l '<심볼>' <착지 tip> --
   docs/adr/` 를 돌린다.
4. **겹치면 착지 전에 고친다.** 처리는 template 의 "같은 결정이 두 ADR 에 적혀 있을 때" 를 따른다
   (조항이면 통합 ADR, 결정 전체면 한쪽 Supersede). **착지 뒤에 고치면 두 번호가 다 인용되기
   시작해** 정리 비용이 커진다. 고칠 수 없는 사정이면 착지하되 겹침을 로컬 TODO 로 남긴다.

## 도구의 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 보고 완료. 겹침 후보가 있든 없든 0 이다 — 후보는 판정이 아니라서 실패로 내지 않는다. |
| 2 | 판정 불가. 없는 rev · 얕은 clone 으로 객체 부재 · git 오류. 목록을 **못 뽑은** 것과 목록이 **빈** 것을 가른다. |

겹침으로 실패를 내지 않는 이유는 겹침 판정이 텍스트로 안 되기 때문이다 — 실패를 내면
"실재하지 않는 중복" 을 처방하게 된다. 자동 채널(CI · 훅)에 걸려 있지 않다. 착지하는 사람이 직접
돌린다.
