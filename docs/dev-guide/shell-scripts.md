# 셸 스크립트 규약

빌드·패키징 스크립트(`scripts/`)와 git 훅(`.githooks/`)에 적용된다. 판정은
`tests/no_early_exit_consumer_in_shell_pipes.rs` 가 한다.

## 조기에 끝나는 소비자를 파이프의 오른쪽에 두지 않는다 (필수)

`grep -q` 는 첫 매치에서, `head -N` 은 N 줄에서 파이프를 닫는다. 그때 아직 쓰고 있던
producer 가 SIGPIPE 로 죽어 141 을 남기고, `set -o pipefail` 이 그것을 파이프라인의 종료
상태로 올린다 — **소비자가 원하는 것을 찾았는데도 실패로 판정된다.**

증상은 그 자리의 문맥에 따라 갈린다.

| 형태 | `set -e` | 증상 |
|------|---------|------|
| `VAR=$(producer \| head -1)` | 발동 | 스크립트가 그 자리에서 죽는다 |
| `producer \| head -40` (단독) | 발동 | 스크립트가 그 자리에서 죽는다 |
| `if producer \| grep -q P` | 면제 | **조건이 조용히 뒤집힌다** |
| `producer \| grep -q P \|\| {…}` | 면제 | **오류 분기가 잘못 발화한다** |

뒤쪽 둘이 더 나쁘다 — 서명 인증서를 손에 쥐고 "없다" 고 하거나, 설치된 rust 타깃을
"안 깔렸다" 고 한다.

**실현 여부는 grep 이 끝난 시점의 잔여 출력량에 달려 있고, 큰 출력에서는 비결정이 아니라
결정적이다.** 실측(이 레포, bash): 8.6MB producer 의 첫 줄에 매치를 두면 파이프는 20/20 이
141 을 내고 히어스트링은 20/20 이 0 을 낸다. 작은 출력에서는 값이 흔들려 언젠가 들키지만,
큰 출력에서는 매번 같은 실패라 flake 로도 안 보인다.

### 축은 파이프가 아니라 소비자다

| | 명령 |
|---|---|
| **대상** | `head` · `grep -q` · `grep -m` · `sed -n '…q'` · `awk '…exit'` |
| **축 밖** | `tail` · `wc` · `sort` · `cat` · `grep -c` · `grep -o` · `exit` 없는 `awk` |

`tail` 은 마지막 N 줄을 알려면 정의상 전량을 읽어야 하므로 producer 를 못 죽인다. 금지를
파이프 전체로 넓히면 무해한 줄까지 걸려 규칙이 지켜지지 않는다.

### 고치는 법 — 둘 다 비용 0

- producer 를 변수로 완전히 받은 뒤 히어스트링: `out=$(producer); grep -q PAT <<<"$out"`
- 애초에 파이프를 만들지 않는다: `grep -m1 PAT FILE` — 파일을 직접 읽으므로 producer 가
  없다. 그래서 파이프의 **왼쪽**에 오는 `grep -m1` 은 규칙 위반이 아니라 권장 처방이다.

`rustup`/`security` 처럼 실패할 수 있는 producer 를 변수로 받을 때는 `|| true` 를 붙여
`set -e` 아래의 동작을 원래대로 유지한다 — 원본이 `if … | grep -q` 였다면 producer 의
실패가 스크립트를 죽이지 않고 조건만 거짓으로 만들었기 때문이다.

## 가드가 판정하지 않는 것

- **셸 스크립트 밖의 파이프.** 터미널에서 `bash mut.sh | head -8` 을 치면 그 파이프는 어느
  파일에도 없다. 실제로 그 형태로 피해가 났다 — 변이 스크립트가 되돌리기 단계 전에
  SIGPIPE 로 죽어 작업 트리에 뮤턴트가 남았고, 이때 `pipefail` 은 무관하다(producer 가
  죽는 것 자체가 피해다). **자동 채널 없음** — 이 축은 절차로만 지킨다.
- **`pipefail` 이 켜져 있는가.** 실현 조건이지만 판정에 넣지 않는다. 켜는 것은 언제든
  일어나는 한 줄짜리 변경이고, 그때 위반이 조용히 되살아난다.
- **`sed`/`awk` 의 조기 종료.** `q` · `exit` 라는 낱말로 보는 근사다.
