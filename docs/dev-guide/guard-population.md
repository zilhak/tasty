# 정적 모수를 쓰는 가드 — 목록을 손으로 유지하지 않는다

스캔 가드의 **모수**(무엇을 읽을 것인가)를 어떻게 고정하는지는
[ADR-0133](../adr/0133-guard-scan-population-is-pinned-not-enumerated.md) 이 정본이다 —
강도 서열(하한 < 건수 고정 < 집합 동등), 경로 목록을 디렉터리로 쓰는 이유, 하한을
연기 검사로만 쓰는 규칙이 거기 있다. 이 문서는 그 ADR 이 다루지 않는 한 갈래만 다룬다.

## 모수가 걷기에서 오지 않을 때

| | 모수의 출처 | 조용히 비는 경로 |
|---|---|---|
| **동적** | 실행 중 트리를 걷는다 | 루트가 틀리면 예외가 아니라 0 이 된다 |
| **정적** | 소스의 `const` 배열, `include_str!` 로 박은 fixture | 없다 — 사람이 지워야 빈다 |

ADR-0133 의 처방은 동적 모수를 겨눈다. 정적 모수에는 그대로 맞지 않는다. `const` 배열
옆에 그 배열의 하한을 두면 상수 옆에 상수를 두는 것이라 거의 동어반복이고, 이 자리의
실제 위험은 "비는 것" 이 아니기 때문이다.

**정적 모수의 위험은 drift 다.** 목록이 "소스의 무엇과 동기" 라고 주석에 선언하고, 그
동기를 아무도 검사하지 않는 형태. 소스가 바뀌어도 목록은 그대로 있고, 가드는 낡은
목록을 상대로 계속 초록이다. 대상이 `#[cfg]` 로 게이트돼 CI 가 컴파일조차 안 하는
코드면 다른 축에서도 안 잡힌다.

정적 모수도 **비면 조용히 통과한다.** 걷기가 깨져서가 아니라, 검사할 것이 없어져서다.
목록을 비우고 돌려 보면 그 가드의 테스트가 전부 초록으로 남는다 — 그것이 이 형태의
판정 방법이다.

## 처방 — 목록을 소스에서 뽑아 동적으로 바꾼다

손으로 유지하는 목록을 없애는 것이 아니라, **그 목록이 소스와 어긋나면 빨개지게** 한다.

1. 목록이 미러링한다고 선언한 소스에서 같은 것을 추출한다. 추출 루트는 개별 파일이
   아니라 디렉터리다(ADR-0133 ①).
2. **양방향으로 대조한다.** 소스에 있는데 목록에 없는 것과, 목록에 있는데 소스에 없는 것.
   한 방향만 보면 사라진 대상의 잔재가 목록에 영원히 남는다.
3. 방향이 원래 한쪽뿐인 자리(예: 동결된 스냅샷을 상대로 한 부분집합 검사)는 집합 동등이
   틀린 형태다. 그때는 **모수의 건수를 고정**한다 — 동결돼 있으므로 하한으로 물러설
   이유가 없다.
4. 모수 단언은 목록을 **만드는 자리**에 둔다. 테스트마다 두면 소비자가 하나 늘 때 구멍이
   다시 열린다.
5. 걷기와 목록이 **동시에** 빌 수 있는 형태면 집합 동등만으로 부족하다 — 양쪽이 빈 집합
   이라 동등이 성립한다. 그 경우에만 파일 수 하한을 연기 검사로 함께 둔다.

이 저장소의 사례는 `the_required_key_list_matches_what_the_platform_sources_ask_for`
(양방향 대조 + 연기 하한)와 `baseline_methods` 의 건수 고정(동결 스냅샷)이다.

## 추출기를 쓸 때

- **바늘을 좁게 잡는다.** `t(` 를 그냥 찾으면 `insert(` · `expect(` 처럼 같은 글자로
  끝나는 다른 이름이 전부 걸린다. 앞 글자가 식별자 문자가 아닐 것을 요구한다.
- **주석을 건너뛴다.** 소스 머리말이 자기가 쓰는 키를 산문으로 예시하는 일이 흔하고,
  안 걸러내면 그 예시가 키로 잡힌다.
- **추출기 자신의 극성을 픽스처로 못박는다.** 무엇을 잡고 무엇을 안 잡는지. 이것이
  없으면 "추출기가 아무것도 안 잡는다" 와 "목록이 비었다" 가 같이 통과한다.
- **추출기가 찾는 패턴을 자기 소스가 담는다.** 픽스처가 그렇다. 스캔 루트가 자기 파일을
  삼키면 자기 픽스처를 실제 값으로 센다. 자기 제외 면제를 두지 말고 **루트를 좁게
  유지하고 그 조건 자체를 테스트로 고정**한다.

## 판정은 변이로만 한다

"이 가드가 모수를 지키는가" 를 소스 패턴으로 분류하면 **양방향으로 틀린다.** 무관한
`is_empty()` 단언이 매칭돼 안 지키는 것을 "지킨다" 로 분류하고, 반대로 하한이 명명
상수가 아니라 **없는 파일을 읽다 나는 panic** 인 것을 "안 지킨다" 로 분류한다. 실측으로
양쪽 다 나왔다. 답하는 것은 모수를 비우고 돌리는 변이뿐이며, 이 판단은 ADR-0133 과
같다.

정적 모수의 변이는 동적 모수와 다르다 — 루트를 옮기는 것이 아니라 `const` 배열을 `&[]`
로 만들거나 fixture 를 0 줄로 만든다. 스캔 루트를 빈 디렉터리로 돌리는 전수 변이는 이
형태에 **닿지 않는다.**

## 범위

`tests/` 는 경계가 아니다. 같은 형태가 `crates/*/src/` 의 `#[cfg(test)]` 모듈 안에도
산다. 기준은 파일 위치가 아니라 **모수가 무엇인가**다.

## 가지치기 기준 — 이름은 성질이 아니다

모수를 **무엇으로 좁히는가**도 같은 축이다. 스캔 가드는 빌드 산출물을 건너뛰어야 하는데,
종전 수단은 디렉토리 **이름**(`"target"`)이었다. 이름은 옮기면 따라오지 않는다 —
`CARGO_TARGET_DIR` 로 다른 이름을 주면 그 디렉토리가 통째로 모수에 들어온다.

실측(2026-09-05)으로 그 상태를 만들어 재면, 영향은 **좁고 깊다**. 가드 27 타깃 중 둘만
움직였다.

| 가드 | 전 | 후 |
|---|---|---|
| `no_early_exit_consumer_in_shell_pipes` | 0.05s | 89.17s |
| `no_todo_file_citation` | 1.30s | 86.30s |
| 나머지 25 | — | 변화 없음(≤1.4 배) |

**결과가 바뀐 가드는 없었다** — 통과 수도 판정도 그대로다. 즉 이 결함의 대가는 위양성이
아니라 시간이다. 25 개가 무사한 이유는 순회 시작점이 하위 디렉토리(`root.join("src")` 등)
여서 최상위 산출물에 닿지 않기 때문이고, 둘이 유독 비싼 이유는 **레포 루트에서 시작해
파일 내용을 읽기** 때문이다.

판정은 `tasty_doc_guards::is_build_cache_dir` 로 모았다 — `CACHEDIR.TAG` 의 서명 줄을
확인한다. 후보 셋을 관측으로 갈랐다.

- **`.gitignore` 준수** — 탈락. `.gitignore` 자신이 이름 기반이다(`/target`·`/site/target`
  같은 앵커 규칙). 다른 이름의 빌드 디렉토리는 `git check-ignore` 가 무시하지 않는다.
  고치려는 결함을 그대로 물려받는다.
- **`cargo metadata` 의 `target_directory`** — 탈락. 지금 설정된 한 곳만 답한다. 이전
  빌드가 남긴 디렉토리는 못 본다.
- **`CACHEDIR.TAG`** — 채택. cargo 가 빌드할 때 실제로 만든다(`cargo metadata` 만으로는
  안 만든다). 디렉토리 자신이 갖는 성질이라 개명해도 따라온다. 규격이라 cargo 밖
  도구에도 통한다.

**이름 가지치기를 대체하지 않고 보탠다.** `PRUNE_DIRS` 는 목적이 둘 섞여 있다 — 산출물
배제와, 추적되지만 우리가 쓰지 않은 콘텐츠 배제(vendored `assets/`). 후자는 표식이 없고
git 도 구분하지 못하므로 이름이 여전히 유일한 근거다. 성질이 다른 문제이고, 같은 처방이
닿지 않는다.

`git ls-files` 로 모수를 통째로 갈아타는 선택지도 있다. 오늘 두 모수는 **완전히 같다**
(이름 가지치기 1194 = `git ls-files` 1194, 대칭차 공집합). 그래도 갈아타지 않은 이유는
위의 둘째 목적 때문이다 — git 은 `assets/` 를 추적하므로 그 배제를 대신해 주지 못하고,
가드마다 두 기준을 섞어 쓰게 된다.
