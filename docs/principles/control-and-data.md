# 사용자 통제와 데이터

## 본체와 기반 기술

Tasty는 터미널에서 기반 기술을 사용하는 데 필요한 제한조건을 따르며, 그 위에 불필요한 보호조치를 최대한 추가하지 않는다. 터미널에서 할 수 있는 작업은 Tasty에서도 할 수 있도록 한다. 별도의 실행 보안·신뢰 경계를 제공하는 제품을 지향하지 않는다.

Tasty 본체가 권한을 자동 획득하거나 시스템·외부 도구의 보안 설정을 자동으로 바꾸지는 않는다. SSH 포트 개방이나 방화벽 예외 추가가 필요하면 사용자 또는 AI 에이전트가 해당 기술의 정상적인 설정 수단으로 처리한다. Tasty는 필요성을 안내하거나 설정 화면을 열어 조치를 돕는 정도로 지원한다.

쉽게 우회할 수 있는 보안 요소라도 Tasty가 임의로 우회하지 않는다. 사용자·에이전트가 터미널에서 실행하는 작업과 본체의 자동 처리는 구분한다. 플러그인은 [별도 정책](plugins.md)을 따른다.

## 사용자·에이전트·원격 사용자

사용자는 터미널로 할 수 있는 모든 작업을 할 수 있다. AI 에이전트도 같은 작업 범위를 갖는다. 다만 release 빌드에서는 Tasty 자체의 포커스를 빼앗는 동작을 제공하지 않는다. debug 빌드에서는 포커스 변경을 포함한 사용자 조작 재현도 가능해야 한다.

원격 사용자는 에이전트와 동일한 동작 권한을 가지며, 로컬 사용자는 원격 연결을 끊을 수 있다. 에이전트가 원격 사용자를 쉽게 끊는 전용 CLI·IPC는 제공하지 않는다. 원격 작업 중 서버의 에이전트 때문에 연결이 끊기는 상황을 줄이기 위한 사용성 기준이며, 우회법까지 막는 보안 격리가 아니다.

대상·선택·입력 전달의 현재 계약은 [포커스 정책](../design/policies/focus.md)과 [attach 동작](../dev-guide/attach-behavior.md)에 있다.

## 터미널 기록과 개인정보

터미널 기록은 복구에 필요한 정도로 저장한다. 어떤 내용이 들어 있는지 검사하여 별도 개인정보 보호나 내용 제한을 적용하지 않는다.

터미널에 표시된 데이터는 Tasty의 취급 기준에서 전체 공개로 본다. 에이전트가 읽거나 다른 곳에 전송하는 것을 Tasty가 별도로 제한하지 않는다. 터미널에서 읽을 수 있는 개인정보도 그대로 둔다. 제한이 필요하면 에이전트 설정이나 OS 권한 설정으로 처리한다. 이는 Tasty가 데이터를 자동으로 인터넷에 게시하라는 뜻이 아니다.

향후 마켓플레이스 로그인 등 Tasty 자체 인증이 생기면 Tasty가 발급한 인증정보를 다르게 취급할 수 있다. 이 예외는 판단 보류이며 현재의 Passkey나 IPC 토큰을 자동으로 이 항목에 포함하지 않는다.

## 오류 안내와 포커스

심각한 복원 실패도 포커스 탈취의 예외가 아니다. [피드백과 복구](feedback-and-recovery.md)에 따라 포커스를 가져가지 않는 팝업으로 알린다.
