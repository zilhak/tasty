# ADR-0105: 추적되는 파일에는 git 에 없는 경로를 적지 않는다 — 로컬 작업 폴더의 위치는 로컬 지침이 정한다

- **Status**: Accepted
- **Date**: 2026-09-04
- **Tags**: docs, conventions, hygiene, dead-reference, gitignore, local-workspace, guard-test, adr-0027, adr-0096

## Context

에이전트가 쓰는 로컬 작업 폴더(임시 산출물 · 작업 계획 · 번호 붙은 작업 티켓 · 로컬 전용
지침)는 `.gitignore` 대상이다. 커밋되지 않고, 완료된 항목은 관례상 파일 자체가 삭제되며,
번호는 다음 세션에서 재사용된다. 그런데 커밋되는 파일 쪽에서 그 경로를 좌표로 적어 온
관행이 있었다. 저장소를 새로 clone 한 사람에게 그 좌표는 **존재한 적이 없고**, 번호 재사용
탓에 살아 있는 것처럼 보이면서 *무관한 문서* 를 가리키기까지 한다. 죽은 참조를 넘어
오도하는 참조다. ADR-0027 이 Figma 기획 기록에서 같은 증상을 "세션/트랙 식별자 누수" 로
이미 진단했다.

**이전 규정 상태는 두 갈래였고 둘 다 좁았다.**

| 규정 | 범위 | 한계 |
|---|---|---|
| [`template.md`](template.md) "외부(비-git) 위치 문서 참조 금지" | ADR 및 committed 문서가 비-git 위치의 *문서를 SoT 로 참조/링크* 하는 것 | **예외**: "폴더의 존재·용도(컨벤션) 자체를 정의/설명하는 서술은 허용" |
| 루트 `CLAUDE.md` "소스 주석의 TODO 파일 및 디자인 changelog 인용 금지" | 소스 주석·문자열의 *티켓 번호 인용* 과 디자인 changelog slug | 경로 서술 일반이 아니라 번호/slug 형태에 한정 |

그 예외는 어느 ADR 에도 근거가 없었다. 그리고 예외가 있는 한 누수는 계속됐다 — 임시 파일
기본 위치를 설명한다는 명목으로 절차 문서·개발 가이드·벤치 스크립트·README 에 로컬 경로가
스며들었다. 예외가 정확히 그 통로였다는 것이 실측으로 확인됐다.

같은 축의 선례가 [ADR-0096](0096-unit-tests-isolated-from-user-environment.md) 이다 —
커밋되는 산출물(그때는 테스트)이 로컬 머신 상태에 의존하지 않게 만든 결정이다. 이 ADR 은
같은 원칙을 *문서·소스에 적힌 좌표* 에 적용한다.

## Decision

**git 이 추적하는 모든 파일은 `.gitignore` 로 제외된 레포 로컬 작업 폴더의 경로를 적지
않는다.** 대상에는 코드·테스트·스크립트·`docs/`·루트 `CLAUDE.md`·README·CI 설정·plugin
매니페스트가 모두 포함된다. **폴더 이름을 단독으로 언급하는 것도 금지에 포함되며, 컨벤션
설명 예외는 이 ADR 로 폐지한다** — `template.md` 의 "폴더의 존재·용도 설명은 허용" 항목은
효력을 잃는다(문구 정리는 아래 "집행" 참조).

**대신 위임한다.** 추적 문서는 규칙의 *내용* 만 쓰고 *위치* 는 쓰지 않는다: "임시 산출물과
작업 계획은 프로젝트 루트나 소스 디렉토리에 만들지 않는다. 구체적 위치는 커밋되지 않는
로컬 전용 지침이 정한다." 실제 경로는 그 로컬 지침 파일에만 존재한다 — 그 파일 자신이
gitignored 이므로 clone 한 사람에게 죽은 좌표를 남기지 않는다.

**범위 밖(적어도 되는 것) 네 가지를 확정한다.**

1. **빌드가 생성·소비하는 gitignored 산출물** — `target/`, `dist/`, plugin 번들 서명 파일,
   사이트 생성물. 문서에 적힌 절차대로 빌드하면 clone 한 사람의 트리에도 *실제로 생긴다*.
   재현 가능한 좌표이므로 죽은 참조가 아니다.
2. **사용자 홈의 런타임 경로** — `~/.tasty/` 같은 데이터 루트나 외부 도구의 홈 설정 경로.
   레포 트리가 아니라 제품이 런타임에 읽고 쓰는 위치이며, 그 자체가 명세해야 할 동작이다.
3. **경로가 아닌 식별자** — plugin id, 워크스페이스 이름, 설정 키 등. 파일시스템 좌표가
   아니므로 이 규칙의 대상이 아니다.
4. **`.gitignore` 자신** — 제외 항목을 적는 것이 그 파일의 본질이다.

**툴링이 그 이름을 데이터로 보유해야 하는 경우는 "인용" 이 아니라 "입력" 이다.** 하이진
가드의 탐지 상수·순회 가지치기 목록, 경로 해석 테스트의 픽스처 문자열이 여기 해당한다.
지우면 검사·테스트가 검증하려던 것 자체가 사라진다. 이 파일들은 가드의 allowlist 로
관리하며, allowlist 에 넣는 판단 기준은 **"금지 형태를 담는 것이 그 파일의 본질인가"** 다.

**집행은 후속 트랙이다.** 지금 강제하는 것은 `tests/no_todo_file_citation.rs` 이고, 그
탐지 범위는 번호 인용·경로 인용·changelog slug·앵커 슬러그다 — 위에서 새로 금지한 "폴더
이름 단독 언급" 과 스캔 대상 파일 집합의 확대는 아직 잡지 못한다. 가드 확장과
`template.md` 예외 문구 삭제는 이 ADR 을 근거로 별도 트랙에서 처리한다.

## Consequences

- **얻은 것**: clone 한 사람 기준으로 추적 파일의 모든 경로 참조가 해소 가능해진다. 규칙이
  "어떤 형태의 인용인가" 가 아니라 "그 경로가 git 에 있는가" 하나로 판정되므로, 새로운
  누수 형태(경로 서술·기본값 안내·스크립트 기본 인자)가 나와도 같은 기준이 그대로 적용된다.
- **얻은 것**: 정책과 위치가 분리된다. 로컬 폴더 배치를 바꿔도 추적 문서를 고칠 일이 없다 —
  로컬 지침 한 곳만 고치면 된다.
- **잃은 것**: 추적 문서만 읽어서는 임시 파일을 *어디에* 두는지 알 수 없다. 로컬 지침을
  함께 로드하지 않는 독자(웹에서 레포만 보는 사람)에게는 한 단계 간접이 생긴다. 그 대가로
  얻는 것이 "적힌 경로는 전부 실재한다" 는 보장이라, 간접 쪽을 택했다.
- **잃은 것**: 이 ADR 본문 자신도 규칙을 지켜야 해서 폴더 이름을 적지 못한다. 그래서 서술이
  "레포 로컬 작업 폴더" 같은 기술(descriptive) 표현이 된다 — 규칙의 자기 적용이므로 의도된
  결과다.
- **운영 비용 / 유지 부담**: 가드가 확장되기 전까지는 사람·에이전트 판단에 의존한다. 그
  기간에 새 위반이 유입될 수 있다. 또 allowlist 는 늘어나기만 하는 목록이라, 항목마다
  "본질인가" 를 다시 묻지 않으면 우회 통로가 된다.

## Alternatives Considered

- **컨벤션 설명 예외를 유지한다** — 가장 작은 변경이지만, 이번 위반 목록이 곧 그 예외가
  통로였다는 증거다. "폴더의 용도를 설명한다" 와 "그 폴더의 경로를 좌표로 쓴다" 는 실제
  문장에서 구분되지 않았다.
- **금지 대신 "존재하면 경고" 수준의 권고로 둔다** — 권고는 이미 두 규정으로 존재했고
  누수를 막지 못했다. 판정이 이분법이어야 기계가 강제할 수 있다.
- **로컬 작업 폴더를 git 추적 대상으로 바꾼다** — 참조가 살아나긴 하지만, 세션마다 생기고
  지워지는 티켓·임시 산출물이 히스토리에 영구히 쌓인다. 폴더를 gitignored 로 두는 이유
  자체를 없애는 선택이라 기각. (다만 이것이 재검토 트리거다.)
- **레포 안에 추적되는 별칭 문서를 두고 그것만 참조한다** — 별칭이 실제 위치와 어긋나는
  순간 같은 드리프트가 재발한다. SoT 를 하나로 두는 편(로컬 지침)이 낫다.
- **범위를 `docs/` 로만 한정한다** — 실제 위반의 절반 이상이 스크립트·테스트·README 에
  있었다. 문서만 정리하면 같은 좌표가 코드 쪽에 남는다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- 로컬 작업 폴더가 git 추적 대상으로 바뀐다 — "clone 에 존재하지 않는다" 는 전제가 깨져
  금지 근거가 사라진다.
- 하이진 가드가 정당한 참조를 반복 오탐한다 — allowlist 가 계속 늘어난다면 판정 기준
  자체(경로 존재 여부)가 실무와 맞지 않는다는 신호다.
- 위임 구조가 실패한다 — 로컬 지침을 로드하지 않는 경로(CI, 외부 기여자)에서 임시 파일이
  레포 루트에 계속 생긴다면, 위치를 추적 문서에 되돌리는 대신 다른 전달 수단을 찾는다.
- "범위 밖" 네 항목 중 하나가 실제로 죽은 참조를 만든다 — 예컨대 빌드 산출물 경로가
  프로필마다 달라져 문서에 적힌 좌표가 재현되지 않게 되는 경우.
