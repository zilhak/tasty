# ADR-0649: ADR은 중요한 선택을 기록하고 현재 규칙은 가이드에서 관리한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: documentation, adr, architecture
- **Group**: rules

## Context

작은 작성 규칙과 일회성 실험까지 각각 ADR로 만들면 중요한 설계 선택을 찾기 어렵다.
같은 조항을 여러 문서가 나누어 개정하면 Accepted라는 상태만으로 적용 범위를 알 수 없다.
현재 규칙과 결정 이유의 역할을 나누고, 같은 주제의 선택을 읽기 쉬운 크기로 묶을 필요가 있다.

## Decision

ADR에는 오래 유지할 중요한 선택, 그 선택의 제약과 이유, 기각한 대안과 재검토 조건을 남긴다.
현재 동작·명령·개발 절차·검증 방법은 해당 가이드나 명세에서 관리한다.
측정 결과만 생겼거나 작은 작성 규칙 하나를 정한 경우에는 기존 문서를 갱신한다.

새 ADR을 쓰기 전에 인덱스의 해당 주제와 결정 대상의 심볼·파일·설정 키로 기존 기록을 찾는다.
같은 선택이면 기존 ADR을 사용하고, 같은 주제에서 이유가 보강되면 기존 설명에 통합한다.
내용이 충돌하면 현재 구현과 후속 결정을 확인해 현재 적용할 선택을 명확히 쓴다.

번호는 식별자이며 빈 번호를 다시 쓰지 않는다.
재작성으로 문서 수가 줄어도 번호를 촘촘하게 다시 매기지 않는다.
인덱스의 행은 ADR 헤더에서 생성하고 그룹 설명은 사람이 관리한다.

대규모 정리는 기존 기록을 별도 보관한 뒤 내용을 전부 읽어 새 ADR과 운영 문서에 배분한다.
원본별 이동 위치와 제외 이유를 남기며, 단순 개수 맞추기 때문에 독립적인 결정을 감추지 않는다.
현재 문서가 서로를 따라가야만 유효한 조항을 알 수 있는 형태를 줄인다.

## Consequences

현재 규칙을 읽기 위해 여러 부분 개정 기록을 추적하는 부담이 줄어든다.
원본의 모든 조사 과정은 새 ADR에 반복하지 않으므로 이전 실험의 세부 경위는 보관 기록이나
Git 이력에서 확인해야 한다.

사실 정정과 문장 개선은 결정 변경과 구분한다.
실제 선택을 바꾸는 경우에는 이전 선택과 바뀐 이유를 추적할 수 있게 한다.
개정 문서는 현재 유효한 범위를 처음에 알리고 인용도 현재 위치로 갱신한다.

## Alternatives Considered

- 모든 기록을 그대로 두고 인덱스만 고치면 본문의 중복과 긴 개정 관계가 남는다.
- 제목이 비슷한 문서를 기계적으로 합치면 서로 다른 조건과 기각 이유가 사라질 수 있다.
- 모든 작은 규칙에 새 ADR을 만들면 작성 가이드보다 관리 규칙이 더 커진다.
- 빈 번호를 재사용하면 옛 인용이 전혀 다른 결정을 가리킬 수 있다.

## Reconsideration Triggers

정리된 ADR에서 하나의 결정과 현재 적용 범위를 찾기 어렵다면 주제 구분을 다시 조정한다.
새 결정의 빈도가 늘어 번호 충돌이 나면 번호 배정 도구를 검토한다.
