# ADR-0165: 파일 SLOC 게이트는 출하되는 줄을 잰다 — 파일 전체가 아니라

- **Status**: Accepted
- **Date**: 2026-09-05
- **Tags**: complexity-gate, guards, measurement, adr-0037, adr-0131, adr-0150

## Context

파일 SLOC 게이트([ADR-0037](0037-complexity-gate.md))는 Rust 파일의 code SLOC 이 1000 을
넘으면 차단한다. 게이트가 겨냥하는 것은 **한 파일이 감당하는 복잡도**이고, 그 전제는
"파일에 있는 줄 = 그 파일이 감당하는 것" 이다.

**인라인 테스트에서 그 전제가 깨진다.** `#[cfg(test)] mod tests { … }` 는 출하 빌드에
한 줄도 안 들어가는데 게이트는 그것을 출하 코드와 같은 잣대로 잰다. 게이트 스크립트는
자기 의도를 "테스트 모듈·생성/전사 코드는 제외" 라고 적어놓고 구현은 **파일명 관례**
(`*/tests.rs`·`*_tests.rs`)뿐이라, 한 파일 **안에** 있는 테스트 모듈은 애초에 걸릴 여지가
없었다.

실측(2026-09-05, main `428ab045`, `.rs` 1178, tokei):

    임계 초과 (원본 기준)                 51 = allowlist 43 + skip 8, 미면제 0
    임계 초과 (인라인 cfg(test) 제외 시)  32
    내려가는 것                           19  ← 전부 allowlist 등재분

즉 **동결 목록 43 중 19(44%)는 프로덕션 복잡도가 임계 아래**이고, 등재 사유가 인라인
테스트다. 면제율은 100% 그대로인데 그 수가 뜻을 잃은 상태였다 — 면제의 절반 가까이가
복잡도 부채가 아니다.

발현도 실제로 있었다: `crates/tasty-plugin-markdown/src/main.rs` 에 기능 하나(테스트 3 건
동반)를 더하자 944 → 1003 으로 게이트가 막았는데, 프로덕션만 세면 830 이었다. 그때는
테스트를 형제 파일로 옮겨 통과시켰다 — 회피지 해결이 아니다.

## Decision

**게이트가 재는 대상은 원본 파일이 아니라 인라인 `#[cfg(test)]` 범위를 빈 줄로 지운
사본이다.** 판정(무엇이 출하되는가)과 계측(몇 줄인가)을 가른다 — 판정은
`crates/tasty-doc-guards` 의 `strip-cfg-test` 가 하고, 계측은 tokei 가 그대로 한다.

지운 줄은 **빈 줄로 남긴다**: 줄 번호가 보존돼야 tokei 의 보고를 원본 좌표로 읽을 수
있고, 사본이 짧아지면 "지운 결과" 와 "안 읽힌 결과" 가 구분되지 않는다.

**파일 전체가 출하 밖인 경우(별도 파일 테스트 모듈·cargo 통합 타깃)의 판별은 이번에
바꾸지 않는다.** 그 축은 판정이 한 건도 안 바뀐다 — 이름 글롭이 과다 면제하는 것은 0 건,
과소 면제하는 40 건의 최대 code SLOC 이 727 로 임계에 안 닿는다. 이름을 보는 성질이
이론상 틀려도 모수 안에서 답이 같으면, 게이트에 파서를 하나 더 들이는 값이 없다.
그 대리인은 `src/source_guards/sloc_gate_skip_proxy.rs` 가 선언 기반 정본에 양방향으로
못박아 두고 있다.

**동결 목록에서 내려간 19 건은 지운다.** [ADR-0150](0150-a-zero-difference-exemption-is-not-dead.md)
의 표에서 이 면제는 "이 파일이 지금 X 때문에 위반한다" 형태이고 X(임계 초과)가 사라졌으므로
**죽음**이다 — 정책 잠복이 아니다. 목록 파일 자신의 래칫 조항("1000 이하로 줄면 해당 줄을
삭제")과 같은 처방이다.

## Consequences

- **얻은 것**: 게이트가 "이 파일이 감당하는 복잡도" 를 실제로 잰다. 인라인 테스트를 더한
  것과 프로덕션 코드를 더한 것이 갈린다 — 앞의 것은 통과하고 뒤의 것은 막힌다(양극성
  실측: 인라인 1100 줄 추가 → exit 0, 프로덕션 1100 줄 추가 → exit 1). 동결 목록이
  24 건으로 줄어 남은 항목이 전부 진짜 부채가 된다.
- **잃은 것**: 지운 19 건에 프로덕션 코드를 더하면 이제 게이트가 운다. 그중 넷은 여유가
  작다 — `src/state.rs` 2 · `src/app/ipc/app_methods.rs` 5 · `src/adapters/ui/tab_bar.rs` 12
  · `crates/tasty-plugin-git-viewer/src/render.rs` 38. **이것이 이 결정의 값이자 동시에
  비용이다**: 그 파일들은 프로덕션만으로도 임계 근처이고, 게이트가 거기서 말하는 것이
  옳다.
- **운영 비용**: 게이트가 바이너리 하나를 요구한다. `tasty-doc-guards` 는 의존이
  0 이라([ADR-0138](0138-doc-guards-live-in-a-dependency-free-crate.md)) 콜드 빌드가 초 단위고,
  CI 잡에 빌드 스텝 한 줄이 붙는다. 게이트는 **스스로 빌드하지 않는다** — 이 스크립트가
  `cargo test` 안에서도 불리므로(`tests/file_sloc_gate_fails_loudly.rs`) 중첩 cargo 가
  빌드 디렉토리 잠금에서 서로를 기다린다. 호출자가 경로를 주거나
  (`TASTY_STRIP_CFG_TEST_BIN`) 이미 빌드된 산출물을 쓰고, 둘 다 없으면 **exit 2**(측정
  실패)다 — 통과가 아니다.
- **관측된 부작용 하나**: 사본이 원본보다 **크게** 세지는 파일이 6 개 있다. 줄을 지웠는데
  code 가 늘 수는 없으므로 **원본 쪽 tokei 파스가 틀린 것**이다(원본이 과소계수 중).
  기전을 `crates/tasty-remote-profiles/src/ssh_config.rs` 에서 특정했다 — 601 행의 문자열
  리터럴 안에 있는 `/*` 가 tokei 를 블록주석 모드로 넣고 파일 끝까지 안 나온다(그 줄에서
  `/*` 만 지우면 458 → 461 로 정상화, 그 줄이 있으면 뒤의 모든 줄이 comment 로 센다).
  같은 줄만 떼어 최소 재현하면 재현되지 않으므로 **앞선 문맥이 트리거의 일부**다.
  사본 쪽 값이 더 정확하며, 이 6 건 중 새로 임계를 넘는 것은 **0 건**이라 판정에 영향이
  없다. tokei 자체의 결함이라 이 ADR 의 범위 밖이다.

## Alternatives Considered

- **A: 임계 1000 을 올린다** — 기각. 면제의 절반이 부채가 아니라는 관측은 **임계가
  빡빡하다는 근거가 아니라 분류가 틀렸다는 근거**다. 부채를 무효화하려는 상향은
  [ADR-0131](0131-file-sloc-gate-needs-a-firing-trigger.md) 이 이미 기각했고, 이 결정은
  그 형태와 갈린다 — 여기서 바뀌는 것은 **무엇을 세느냐**지 **얼마까지 봐주느냐**가 아니다.
- **B: 파일명 관례를 넓힌다(`*_guard.rs` 등 추가)** — 기각. 같은 결함의 다른 형태다.
  이름을 보는 성질이 그대로이고, 인라인 테스트는 이름을 갖지 않으므로 애초에 안 닿는다.
- **C: 셸에서 인라인 범위를 직접 판정한다** — 기각. `#[cfg(...)]` 범위 판정은 이미
  Rust 정본이 있다. 셸에 두 번째 구현을 두면 같은 물음에 판정기가 둘이 되고, 갈린 쪽은
  면제하는 방향으로 조용히 틀린다.
- **D: 측정 프로토타입을 그대로 게이트에 넣는다** — 기각. 프로토타입은 파이썬 일회용
  계측 도구였다. 판정기로 쓸 것이면 정본(`cfg_predicate`)을 부르는 형태여야 하고, 그래서
  승격하면서 다시 썼다.
- **E: `프로덕션 = min(사본, 원본)` 보수 규칙** — 기각. 위 6 건의 기전을 특정하기 전의
  안전장치로 준비했으나, 기전이 tokei 의 원본 파스 오류로 밝혀져 **사본 쪽이 더 정확한
  값**임이 확인됐다. 더 정확한 값을 덮어쓸 이유가 없다.

## Reconsideration Triggers

- 사본이 원본보다 크게 세지는 파일 중 **새로 임계를 넘는 것이 생기면** — 지금은 0 건이라
  판정에 영향이 없다는 근거로 tokei 결함을 안고 간다. 그 전제가 깨지는 시점이다.
- 이름 글롭이 과소 면제하는 파일 중 **임계에 닿는 것이 생기면** — 지금은 최대 727 이라
  전체-파일 판별을 선언 기반으로 바꿀 값이 0 이다. `sloc_gate_skip_proxy` 의 (나)가 그날
  실패한다.
- 인라인 테스트를 지운 뒤에도 임계를 넘는 파일이 **동결 목록 없이** 늘기 시작하면 —
  그때는 임계 자체의 유도가 없다는 문제([ADR-0037](0037-complexity-gate.md) 이 파일 축에
  대해서는 유도를 안 적었다)를 따로 열어야 한다.
