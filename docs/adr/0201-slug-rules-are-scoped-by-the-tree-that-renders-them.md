# ADR-0201: 슬러그 규칙은 그것을 렌더하는 트리가 정한다 — 통일하지 않는다

- **Status**: Superseded by ADR-0247
- **Date**: 2026-09-09
- **Tags**: documentation, anchors, slug, guards, site, github, two-judges, adr-0139, adr-0142

## Context

이 저장소에는 마크다운 헤딩에서 앵커 슬러그를 만드는 규칙이 **둘** 있고, 그 사실이
어디에도 적혀 있지 않았다.

- **GitHub 렌더러의 규칙** — `docs/`·루트 `*.md`·`crates/**/*.md` 를 읽는 사람은 GitHub
  에서 읽는다. 그 규칙은 밑줄을 단어 문자로 보아 **`_` 를 남기고**, 슬러그 양끝의 `-` 를
  **안 뗀다**.
- **사이트 생성기의 규칙** — `site/content/` 는 `site/src/md.rs` 의 `slugify` 가 렌더하고,
  그것은 **`_` 를 `-` 로 바꾸고** 양끝 `-` 를 **뗀다**.

두 규칙이 갈리는 자리를 셌다. 모수는 `git ls-files '*.md'` 다 — 레포 루트부터 훑는 순회는
worktree 와 원본 저장소에서 값이 갈리므로(커밋되지 않는 로컬 작업 폴더가 한쪽에서는
심볼릭 링크다) 이 물음의 모수는 순회가 아니라 git 이 정해야 어느 트리에서 재도 같은 수가
나온다.

| 모수 | 파일 | 헤딩 | 갈리는 헤딩 |
|---|---|---|---|
| `site/content/` | 36 | 440 | 0 |
| 그 밖 | 399 | 3866 | 102 |

102 의 원인은 둘뿐이다(전각·기호·연속 하이픈·한글에서는 안 갈린다): 밑줄 101 건, 양끝
하이픈 trim 1 건.

**그 102 가 지금 무엇을 깨고 있는가도 셌다.** 앵커 인용 160 건을 훑어, 갈리는 헤딩을
GitHub 규칙 형태로 인용한 것이 4 건이고 사이트 규칙 형태로 인용한 것이 **0 건**이다. 즉
**이 갈림 때문에 지금 깨져 있는 링크는 없다.** 102 는 잠재값이지 부채가 아니다.

문제는 링크가 아니라 **판정**이었다. 앵커를 판정하는 가드
(`crates/tasty-doc-guards/tests/cited_anchors_resolve.rs`)를 지으면서 어느 규칙으로 판정할
것인지를 골라야 했고, 한쪽 규칙을 레포 전체에 쓰면 다른 쪽 트리에서 틀린다.

## Decision

**슬러그 규칙은 통일하지 않는다. 그 앵커를 실제로 푸는 렌더러가 그 트리의 규칙을 정한다.**

판사는 트리 이름이 아니라 **그 링크를 실제로 푸는 렌더러**로 정한다. 조합이 넷이고,
사이트가 푸는 것은 그중 하나뿐이다.

| 링크 | 누가 푸는가 | 판사 | 지금 건수 |
|---|---|---|---|
| `site/content/` → `site/content/` | 발행된 사이트 | `--strict` (`broken anchor in ...`) | 36 |
| `site/content/` → 트리 밖 | 사이트가 GitHub blob URL 로 내보낸다 | GitHub (`cited_anchors_resolve`) | 0 |
| 트리 밖 → `site/content/` | **GitHub** — `docs/` 는 발행되지 않으므로 그 링크를 여는 사람은 GitHub 에서 `.md` 를 연다 | GitHub (`cited_anchors_resolve`) | 0 |
| 트리 밖 → 트리 밖 | GitHub | GitHub (`cited_anchors_resolve`) | 162 |

즉 사이트에 넘기는 조건은 **두 끝이 모두 content 트리 안일 때**다. 두 판사가 같은 자리를
보면, 규칙이 갈리는 날 한쪽이 반드시 틀린 답을 낸다 — 그리고 그 틀린 답은 **멀쩡한 문서에 대한 빨강**이라 처방이
"문서를 고쳐라" 로 나간다. 실측으로 그 크기가 잡혀 있다: `docs/` 에 사이트 규칙을 쓰면
지금 동작하는 앵커 4 건이 빨강이 된다.

## Consequences

- **얻은 것**: 각 트리에서 판정이 그 트리의 독자와 일치한다. 겹치는 자리가 0 이라 "두
  가드가 같은 물음에 다른 답" 이 원리적으로 안 생긴다. 규칙 둘이라는 사실이 값과 함께
  기록돼, 다음 사람이 "통일하면 되지 않나" 를 재지 않고 묻지 않는다.
- **잃은 것**: 규칙이 하나가 아니다. 헤딩 하나가 어느 트리에 있느냐로 앵커가 달라질 수
  있고, 문서를 트리 사이로 옮기면 앵커가 바뀐다(102 자리에서만).
- **운영 비용 / 유지 부담**: 사실상 없다. 두 판정기는 이미 각각 자동 채널을 갖고 있다 —
  `doc-guards.yml`(경로 필터 없음)과 `pages.yml`(`site/**`). 후자는 main push 마다 돌지는
  않지만, 그 트리의 앵커가 깨지는 길(링크 수정·헤딩 수정)이 둘 다 `site/**` 라 사각이
  안 생긴다.

## Alternatives Considered

- **A: 사이트 `slugify` 를 GitHub 규칙에 맞춘다** — 규칙이 하나가 된다. 안 고른 이유:
  생성된 사이트의 앵커 URL 이 바뀐다. 그 URL 은 외부에 노출된 주소이고, 바뀌면 바깥에서
  걸어둔 링크가 조용히 깨진다. 얻는 것(내부 판정기 하나)에 비해 잃는 것이 바깥에 있다.
- **B: 가드를 사이트 규칙으로 통일한다** — 판정기가 하나가 된다. 안 고른 이유: `docs/` 의
  독자는 GitHub 이라 판정이 독자와 어긋난다. 실측으로 지금 동작하는 앵커 4 건이 빨강이
  된다 — 실재하지 않는 결함에 대한 처방을 내는 가드가 된다.
- **C: 102 개 헤딩에서 `_` 를 없앤다** — 두 규칙이 같은 답을 내게 만든다. 안 고른 이유는
  재서 적는다.

  | 줄이는 비용 | 값 |
  |---|---|
  | 고쳐야 할 헤딩 | **102** (밑줄 101 · 양끝 하이픈 1) |
  | 그 밑줄이 코드 식별자·좌표인 것 | **101 / 101** — 하나도 예외가 없다. 64 건은 백틱으로 코드 스팬 표시까지 돼 있고(`file_watch`·`set_context`), 나머지 37 건은 표시가 없을 뿐 역시 식별자다(`api_version`·`tiny_http`·`z_seq`·`shipping_scope::test_only_files`). 헤딩에서 밑줄을 빼면 **가리키는 대상이 그 이름이 아니게 된다** |
  | 그 편집이 즉시 깨는 내부 인용 | **4** — 같은 변경에서 함께 고쳐야 한다 |
  | 레포 밖 링크 파손 | **미측정** — 원리적으로 이 저장소에서 못 잰다 |

  | 두는 비용 | 값 |
  |---|---|
  | 지금 깨져 있는 링크 | **0** |
  | 판정기 유지 부담 | 둘 다 이미 있고 자동 채널도 각각 있다. 겹치는 자리 **0** |
  | 남는 위험 | "누군가 한쪽으로 통일한다" 하나. 그 처방을 본 ADR 과 가드 모듈 주석이 막는다 |

  ⇒ 줄이는 쪽은 확실한 손해(식별자 이름 훼손 102 · 링크 수선 4 · 바깥 파손 미측정)를
  치르고 **지금 0 인 문제**를 없앤다. 두는 쪽이 싸다.
- **D: 아무것도 정하지 않고 둔다** — 지금까지의 상태. 안 고른 이유: 규칙이 둘이라는 사실이
  안 적혀 있으면 다음 사람이 가드를 "고쳐서" 한쪽으로 통일하고, 그 순간 다른 트리가
  빨개진다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- **사이트 생성기가 슬러그 규칙을 바꾼다** — `site/src/md.rs` 의 `slugify` 가 밑줄이나
  양끝 하이픈 처리를 바꾸면 이 결정의 전제(두 규칙이 무엇에서 갈리는가)가 낡는다. 그때
  다시 세야 하는 값은 위 표의 갈림 수와 인용 수 둘 다다.
- **GitHub 이 앵커 슬러그 규칙을 바꾼다** — 같은 이유로 반대편 전제가 낡는다.
- **사이트 규칙 형태로 인용된 앵커가 0 이 아니게 된다** — 지금은 0 이라 "잠재값" 이지만,
  0 이 아니면 그 순간부터 실재하는 깨진 링크가 있다는 뜻이고 이 결정의 "부채가 아니다"
  가 거짓이 된다.
- **`site/content/` 안에서 두 규칙이 갈리는 헤딩이 0 이 아니게 된다** — 그 트리의 배제가
  예방적이라는 서술이 낡는다.
- **문서가 트리를 넘나들며 옮겨지는 일이 상시화된다** — 트리로 규칙을 가르는 비용이
  올라가므로 통일(대안 A)의 손익이 달라진다.
