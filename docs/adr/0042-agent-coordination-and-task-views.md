# ADR-0042: 에이전트 작업 조율과 DAG 화면은 호스트가 맡는다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: agents, tasks, concurrency, dag
- **Group**: agents

## Context

여러 에이전트가 같은 인스턴스에서 작업하면 실행 순서와 공유 자원을 조율해야 한다.
호스트는 작업 상태와 의존 관계를 이미 보관하며 IPC와 CLI로 조회·조작할 수 있다.
사람에게는 CLI를 반복 조회하는 대신 실행 상황을 계속 보거나 잠깐 확인할 화면이 필요하다.

## Decision

작업 실행과 조율 상태는 호스트가 소유한다. 화면은 같은 작업 조회 모델을 사용한다.
DAG 그래프는 탭에 두는 내장 `dag_graph` 서피스와 워크스페이스 범위의 목록 popup으로 제공한다.
서피스는 지속적인 관찰에, popup은 목록에서 작업을 골라 잠깐 확인하는 데 사용한다.
대상 DAG는 ID로 지정하며 에이전트 명령은 사용자의 포커스를 바꾸지 않는다.

화면이 보일 때만 갱신을 예약한다. 작업 러너가 별도 스레드에서 상태를 바꾸므로 화면은
자체적으로 재조회해야 하지만, 숨겨진 화면까지 계속 그릴 필요는 없다.

세마포어 한도는 삭제·재생성 없이 원자적으로 바꾼다. 한도를 줄여도 이미 작업 중인
홀더를 강제로 회수하지 않으며 반납될 때까지 새 획득을 제한한다.
홀더 만료는 기본으로 끈다. 호출자가 TTL을 주면 자동 회수가 가능하지만 실행 중 만료로
다른 작업이 같은 자원을 사용할 수 있으므로 작업의 최대 소요시간을 고려해야 한다.

이름을 저장 키에 직접 넣는 작업·barrier·semaphore·rate-limit은 키를 만들기 전에
호출자 입력을 검사한다. 오류 위치는 내부 접두사를 붙인 키가 아닌 입력한 이름 기준이다.
기존 저장 키는 유지하며, 이름 인코딩을 사용하는 lease와 규칙을 억지로 통일하지 않는다.

Claude의 Stop 게이트는 본문·종료 표시 문자열·반복 상한을 이름으로 등록한다.
게이트별·세션별로 반복 수를 분리하고, 프로필 이름으로 부착할 수 있게 한다.
프로필과 게이트의 이름 충돌은 등록할 때 거절한다.

계속 진행할 범위는 해당 서피스에 설정된 goal로 제한한다.
본문에 `{{goal}}`을 넣은 게이트만 훅이 goal을 직접 읽어 전달한다.
goal이 없거나 조회할 수 없으면 추가 계속 지시를 넣지 않는다.
충족 여부를 판정하는 주체는 여전히 모델이므로 goal 문장만으로 종료를 보장하지는 않는다.

## Consequences

사람이 작업 진행을 확인하기 쉬워지고, 화면과 CLI가 같은 상태를 보여준다.
작업 상태나 그래프 관계가 달라지면 화면과 조회 응답도 함께 갱신해야 한다.
내장 서피스는 레이아웃 저장·복원과 번역·갤러리 예시를 함께 유지해야 한다.
TTL을 쓰지 않은 외부 점유는 수동 복구가 필요할 수 있고, 이름의 허용 문자 제한도 남는다.
Stop 게이트는 반복 작업을 재사용하기 쉽게 하지만 목표 충족을 직접 증명하지는 못한다.
게이트와 프로필이 이름을 공유하므로 동명으로 따로 등록할 수 없다.

## Alternatives Considered

- 화면을 계속 보류하면 실행 모델이 바뀔 때의 수정 비용은 줄지만 반복 조회 부담이 남는다.
  현재는 작업 모델과 조회 기능이 갖춰져 있어 보류를 유지하지 않는다.
- 플러그인 화면은 호스트가 가진 데이터를 IPC로 다시 받아야 하고 렌더링 버전 관리도 더한다.
  현재 데이터와 실행 주체가 모두 호스트에 있으므로 내장 화면으로 둔다.
- HTML 화면은 문서 표현에는 적합하지만 노드 이동과 pan/zoom을 위한 추가 연동이 필요하다.
- 서피스나 popup 하나만 제공하면 지속 관찰과 잠깐 확인 중 한 용도가 불편해진다.

- 기본 TTL이나 한도 축소 시 강제 회수는 오래 걸리는 정상 작업과 새 작업이 같은 자원을
  동시에 쓰게 할 수 있어 채택하지 않는다.
- 러너가 매번 TTL을 갱신하면 멈춘 작업의 점유도 계속 연장된다. 현재는 자동 갱신 대신
  호출자가 만료 여부와 시간을 정한다.
- 모든 이름을 인코딩하면 허용 문자를 늘릴 수 있지만 기존 저장 키의 마이그레이션이 필요하다.
  하위 저장소의 모든 키 오류를 입력 오류로 바꾸면 호스트가 만든 키의 결함도 숨길 수 있다.

- 고정 체크리스트 하나만 바꾸거나 프로필 파일에 전용 필드를 섞으면 게이트를 독립적으로
  등록·재사용하기 어렵다. 게이트 레지스트리를 별도로 두고 프로필의 부착 경로를 사용한다.
- 후속 작업이 있으면 무조건 계속하라고 지시하면 요청 범위 밖의 작업을 늘릴 수 있다.
  goal은 서피스별로 두며 부모의 goal을 자식에게 자동 상속하지 않는다.
- 모든 본문에 goal을 덧붙이면 등록한 저자의 내용을 바꾸므로 명시한 placeholder만 치환한다.

## Reconsideration Triggers

- 두 화면 중 하나가 실제 작업에서 쓰이지 않아 유지 비용만 남을 때.
- 작업 모델이 자주 바뀌어 현재 화면 범위를 유지하기 어려울 때.
- 플러그인이 호스트 데이터와 렌더링을 더 적은 비용으로 공유할 수 있을 때.

- TTL 없는 점유의 수동 복구가 반복되거나 한도 초과 상태가 장기간 해소되지 않을 때.
  용도별 만료 기본값이나 반납 요청을 먼저 검토한다.
- 대기열·공정성 정책이나 lease 만료 의미가 바뀔 때.
- 실행 중 TTL 만료와 멈춘 작업의 점유 연장 중 실제 문제가 확인될 때.
- 새 저장소가 공용 이름 검사를 우회하거나 저장 키 규칙·허용 문자 요구가 달라질 때.

- Stop 외 이벤트나 다른 플러그인이 게이트를 사용하거나 이름 충돌이 반복될 때.
- goal이 있어도 반복 상한에 계속 도달하거나 더 많은 실행 시점 값이 필요할 때.
