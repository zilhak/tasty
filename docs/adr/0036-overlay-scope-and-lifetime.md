# ADR-0036: 오버레이의 입력과 수명은 종류와 소유 범위로 정한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: popup, scope, lifecycle
- **Group**: ui

## Context

기능 창, 잠깐 보이는 알림, 안내 버튼을 가진 배너는 입력과 수명이 다르다. 모두 같은 팝업으로 표현하면 예외 옵션이 늘고 포커스 규칙이 불분명해진다.

## Decision

Popup·Toast·Banner는 각자의 관리자를 둔다. 배너는 마우스 입력과 버튼을 지원하지만 키보드 포커스를 가져가지 않는다. 부모 영역 상단에 표시하며, 사용자가 닫거나 TTL이 끝날 때 사라진다. 배너의 종류는 각 안내의 고유 ID로 구분한다.

### 요청과 닫힘 처리

플러그인이 호스트의 대화형 팝업을 요청하면 호스트는 요청 ID를 즉시 응답하고, 사용자 선택은 나중에 요청자에게만 결과 이벤트로 보낸다. 사용자가 선택할 때까지 동기 호출을 붙잡지 않는다. 팝업마다 입력·결과 구조가 달라 메서드는 개별적으로 유지한다.

호스트 팝업을 닫는 모든 경로는 `PopupManager::close()`를 거친다. 팝업별 정리는 `on_close` 훅에 두고 다음 그리기 단계에서 한 번 호출한다.

### 그리기 순서와 네이티브 메뉴

호스트와 플러그인 팝업은 열기·클릭 순번을 공유한다. 셸 레이어 순서와 GPU 콘텐츠 합성 순서 모두 이 순번에 맞춘다. 그리기 함수 호출 순서만 바꿔서는 raw painter 레이어 순서를 보장할 수 없다.

네이티브 컨텍스트 메뉴는 `Ready`와 `Pending`을 가진 공통 반환형을 사용한다. macOS·Windows는 기존 동기 결과를 즉시 처리하고, Linux는 메뉴 핸들을 반환한 뒤 프레임에서 비차단 폴링한다. 결과 처리 직전에 대상이 여전히 존재하는지 확인한다.

### 부모와 소속 범위

플러그인이 연 호스트 팝업의 부모는 `owner_popup_instance`로 명시한다. 관계는 자식의 요청자 기록에만 저장한다. 자식이 열린 동안 부모의 바깥 클릭 닫힘을 막고, 부모가 닫히면 아직 확정하지 않은 자식 결과를 취소로 완료한다. 부모를 모달로 잠그지는 않는다.

플러그인 팝업은 매니페스트에서 window 또는 surface 범위 종류만 선언한다. 실제 surface는 팝업을 여는 호스트가 지정한다. context의 임의 키를 해석하거나 플러그인이 다른 surface를 지정하게 하지 않는다. 대상이 없는 진입점과 오래된 매니페스트는 window로 동작한다.

숨은 범위의 팝업은 그리기·합성·히트테스트·Esc·키 입력 차단에서 제외하되 인스턴스 상태를 보존한다. 같은 인스턴스를 재사용하면 처음 context와 범위 대상을 함께 유지한다.

자식 파일 피커는 첫 그리기 전에 부모의 선언 종류와 실제 대상에서 범위를 계산해 상속한다. 숨김과 닫힘을 구분하며, 숨겼을 때 초안·선택·요청·포커스 의도는 유지하고 드래그·크기 조절 캡처만 해제한다. 부모가 닫히면 숨은 자식의 draw를 기다리지 않고 셸을 닫고 결과를 정리한다.

scrim은 팝업 소속 범위를 덮고, 같은 범위에서는 한 번만 칠한다. 창 scrim이 있으면 그 안의 좁은 scrim은 생략한다. scrim 여부는 범위만으로 정하지 않고 해당 팝업의 종류에 따른다. Surface 팝업은 범위 안쪽 간격을 두고 배치하며 셸이 더 크면 줄인다.

### 토스트를 허용하는 경우

원격 연결의 끊김·재연결·손실은 사용자가 보고 있는 mirror의 신뢰도에 관한 상태이므로 사용자 조작 없이도 토스트로 알릴 수 있다. 창 없는 parked engine에는 표시하지 않는다. 에이전트 IPC의 직접 성공·실패 결과는 이 허용 범위에 포함하지 않는다.

사용자 intent의 적용 실패는 토스트로, 에이전트 intent의 실패는 경고 로그로 알린다. 비동기 원격 요청도 실패 회신까지 origin 정보를 유지한다. 직접 Core를 호출하는 IPC 구조 요청과 image.open에도 같은 원칙을 적용한다. markdown.reload로 요청한 원문이 잘려도 토스트 대신 로그를 남긴다.

## Consequences

팝업의 타이틀바·이동·포커스 규칙과 토스트의 입력 통과 규칙을 유지하면서, 배너에 필요한 행동만 구현할 수 있다. 큐·배치·TTL은 배너 관리자가 일관되게 처리한다.

결과 대기 중에도 플러그인이 입력과 렌더링을 계속 처리한다. 요청과 결과의 ID를 양쪽에서 관리해야 한다. 닫힘 정리는 다음 draw까지 지연될 수 있다.

현재 그리기 순서 보정은 호스트 묶음과 플러그인 묶음의 비교다. 여러 플러그인 팝업의 셸끼리 순서를 완전히 해결하지 않으며, `set_sublayer` 중첩에도 한계가 있다. 마우스 입력 소유 판정과 이 렌더링 한계는 별개다.

이미 surface A에 묶인 단일 인스턴스가 숨은 상태에서 B로 다시 열기를 요청하면 보이지 않을 수 있다. 범위 대상만 B로 바꾸면 플러그인의 기존 context와 어긋나므로 기존 단일 인스턴스 정책을 유지한다.

숨은 자식도 단일 파일 피커 슬롯을 차지한다. 좁은 surface에서는 기존 경계 제한으로 피커가 작아질 수 있다.

scrim 중복 제거는 현재 host·plugin 그리기 경로 안에서 각각 이루어진다. 두 경로가 같은 범위에 scrim을 그리는 새 조합에는 공통 계획이 필요하다. 매니저의 clip은 셸에 적용되며 내부 egui 패널이 자체 clip을 넓히면 내용이 밖으로 나갈 수 있다.

accepted 응답 뒤에 실행하는 작업은 적용 실패를 기존 IPC 응답으로 돌려줄 수 없다. 로그만으로 부족하면 완료 응답 설계를 별도로 바꿔야 한다. origin을 모르는 기존 사용자 경로까지 조용한 실패로 바꾸지는 않는다.

## Alternatives Considered

팝업의 기능을 여러 플래그로 끄는 방식은 기본 규칙의 상당 부분을 무효로 만든다. 토스트에 버튼을 붙이면 입력 통과와 자동 소멸을 기대하는 사용 방식이 깨진다. 범용 심각도만으로 배너를 분류하면 안내마다 다른 조치를 표현하기 어렵다.

결과를 동기 응답으로 기다리면 플러그인의 이벤트 처리가 멈추고 호출 타임아웃이 사용자 선택 시간에 걸린다. 파일 피커를 특정 플러그인으로 옮기면 공용 호스트 UI의 재사용성과 attach 상태 관리 경계가 흐려진다.

닫는 호출부마다 정리를 복사하면 빠진 경로가 생긴다. 열린 상태만으로 정리 여부를 계산하는 방법도 닫힌 뒤 유지할 결과와 초안을 구분하지 못한다. z-order 문제 하나를 해결하려고 두 팝업 관리자를 합칠 필요는 없다.

Linux의 GTK 대기 루프에서 winit을 다시 실행하는 방법은 이벤트 루프 재진입을 안전하게 보장하지 못한다. 타임아웃을 줄여도 멈춤이 짧아질 뿐이다. 문제가 없는 macOS·Windows까지 비동기로 재작성할 이유도 없다.

숨김을 취소로 처리하면 탭 전환만으로 작업을 잃는다. target ID만 복사하면 window 선언과 surface 선언을 구분하지 못한다. 숨김 때 focused를 지우면 돌아왔을 때 이전 입력 상태를 복원하지 못한다.

손실 토스트를 없애고 재연결 성공만 알리면 복구가 실패하거나 지연될 때 낡은 화면을 최신으로 오해할 수 있다. 각 토스트를 개별 예외로 열거하면 새 연결 상태를 판단할 기준이 없다.

모든 실패의 기본값을 조용하게 바꾸면 origin 표시가 빠진 사용자 경로가 알림을 잃는다. focus 보정용 user_triggered를 대신 쓰면 일부 사용자 convert를 에이전트로 잘못 구분한다.

## Reconsideration Triggers

종류별 입력·수명·배치가 실제로 같아지면 공통 구현을 늘릴 수 있다. 에이전트 동작에서 배너를 표시할 필요가 생기면 사용자 화면을 유지하는 원칙과 함께 검토한다.

같은 비동기 패턴을 세 번째 호스트 팝업에서 사용할 때 공통 API 추출을 검토한다. 동시 요청 충돌이 반복되거나 결과 이벤트 이름 중복이 유지보수 문제를 만들 때도 확인한다. 닫힘 정리가 즉시 완료되어야 하거나 정상 사용이 정리 반복 상한에 걸리면 큐 처리 방식을 바꿔야 한다.

여러 플러그인 셸의 겹침이나 modifier hint와의 레이어 중첩이 실제 기능에 필요해지면, egui의 레이어 등록과 GPU 합성을 함께 검토한다. egui 업그레이드 때도 그리기 순서를 다시 확인한다.

Wayland 지원이나 macOS·Windows 메뉴의 동기 대기 문제가 생기면 해당 백엔드를 다시 검토한다. Linux grab 실패의 원인이 해결되면 바깥 클릭 보완과 워치독이 여전히 필요한지도 확인한다. 컴파일 성공만으로 플랫폼별 런타임 동작을 확인했다고 판단하지 않는다.

여러 호스트 팝업을 자식으로 동시에 열거나 host끼리 Esc 중재가 필요해지면 공용 소유 관계 관리와 Esc 처리를 검토한다. CallerContext가 다른 이유로 popup 인스턴스를 전달하게 되면 중복 파라미터도 정리한다.

플러그인이 직접 연 팝업에 surface 범위가 필요하거나 pane·tab·workspace 범위 소비자가 생기면 대상 지정과 소유 검증을 확장한다. 네이티브 WebView가 팝업을 가리는 문제는 OS 화면 캡처로 확인한다.

화면 전환 뒤 잘못된 파일 대상이 선택된다는 보고가 반복되면 부모 입력·자식 선택을 유지한 채 workspace/tab을 왕복해 실제 실행 대상을 비교한다. 좁은 surface에서 경로·목록·확정 버튼이 보이지 않으면 해당 크기의 디자인과 대조한다.

surface radius가 바뀌거나 pane·tab 팝업에 scrim을 추가할 때 범위 경계와 inset을 다시 확인한다. 새 surface 팝업은 좁게 분할한 화면에서 열고, 팝업이 없을 때와 범위 바깥 픽셀을 비교해 내용 유출을 확인한다.

손실과 재연결 토스트가 반복되어 방해되면 느린 연결에서 같은 창의 발생 빈도를 측정하고, 배너·사이드바·문서 안 표시로 옮길지 검토한다.
