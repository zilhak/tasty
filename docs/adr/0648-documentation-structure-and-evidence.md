# ADR-0648: 문서는 현재 동작을 설명하고 근거를 다시 확인할 수 있게 쓴다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: documentation, architecture, evidence
- **Group**: rules

## Context

Tasty는 GUI 없이도 동작하며 사용자와 에이전트가 서로 다른 경로로 기능을 사용한다.
화면 설명에 내부 동작을 종속시키면 headless 기능과 여러 화면이 공유하는 동작을 설명하기 어렵다.
또한 현재 규칙에 작업 기록과 오래된 측정값이 섞이면 무엇을 따라야 하는지 알기 어렵다.

## Decision

기능 문서는 내부 동작을 먼저 설명하고 화면은 그 기능의 절이나 하위 문서로 둔다.
호스트 기능은 `features/`, 플러그인이 제공하는 기능은 `plugins/`, 개발 절차는 `dev-guide/`에 둔다.
여러 기능이 공유하는 정책과 시스템은 `design/`, 용어는 `concepts/`, 구조는 `architecture/`에서 설명한다.

현재 동작과 사용 규칙은 해당 가이드가 설명한다.
중요한 선택의 이유와 기각한 대안은 ADR에 남긴다.
일회성 작업 계획이나 실험 과정을 현재 규칙 문서에 계속 덧붙이지 않는다.

시각 값은 Claude Design의 산출물을 기준으로 한다.
화면 문서는 요소와 상태별 표시를 설명하고 토큰·픽셀 값을 복제하지 않는다.
다른 기능의 동작도 해당 문서로 연결한다.

문서의 근거는 새 clone에서도 따라갈 수 있어야 한다.
로컬 작업 티켓과 임시 폴더는 영구 근거로 인용하지 않는다.
자주 바뀌는 개수는 계산 방법이나 관리하는 정본을 연결하고,
과거 측정이 필요한 경우에는 시점·대상·방법과 한계를 함께 적는다.

## Consequences

독자는 기능 동작과 개발 절차를 현재 문서에서 찾고, 판단 이유가 필요할 때 ADR로 이동한다.
같은 값을 여러 곳에서 고치는 일을 줄일 수 있다.

측정 명령만 있는 문서는 규모를 즉시 보여주지 못할 수 있다.
독자가 실제로 필요한 수치라면 생성·정합 검사로 유지하거나 측정 시점을 명확히 적는다.
모든 숫자에 새 검사를 만들지는 않는다.

## Alternatives Considered

- 화면을 기준으로 모든 설명을 묶으면 headless 기능과 여러 화면의 공통 동작이 중복된다.
- 디자인 값을 문서에 복제하면 시안과 문서의 값이 따로 변한다.
- 모든 측정값을 현재값처럼 남기면 날짜를 붙여도 현재 보장으로 오독하기 쉽다.
- 로컬 작업 기록을 영구 추적하면 일회성 자료가 제품 문서와 저장소 이력에 쌓인다.

## Reconsideration Triggers

제품의 디자인 소유 방식이나 기능 제공자가 바뀌면 문서 배치를 다시 판단한다.
값 대신 명령을 제공해 독자의 필요한 판단이 막히면 그 수를 유지할 방법을 정한다.
