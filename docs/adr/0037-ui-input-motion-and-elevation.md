# ADR-0037: UI 입력과 시각 피드백은 공용 동작으로 맞춘다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: ui, input, motion
- **Group**: ui

## Context

행을 누르려는데 글자가 선택되거나 메뉴를 열었는데 앱이 멈추면 화면은 보여도 의도한 조작을 할 수 없다. 같은 위젯의 입력 규칙은 소비 화면마다 달라지지 않아야 한다.

## Decision

행 선택을 제공하는 공용 Table은 본문 셀의 기본 텍스트 선택을 끈다. 행 선택·우클릭·더블클릭을 유지하며, 읽기 전용 표와 헤더의 명시적인 클릭 동작은 유지한다.

### 스크롤 표시

새로 만들거나 수정하는 스크롤 영역은 스크롤바를 숨기고 가장자리 페이드로 남은 내용을 알린다. 스크롤바 폭이 콘텐츠 치수 계산에 필요하고, 컨테이너가 바 표시 설정이나 뷰포트 좌표를 제공하지 않는 경우에만 폭 예약 예외를 둔다.

스크롤 영역은 드래그 패닝 여부를 명시한다. 기본 정책은 끄는 것이며, 켜는 곳에는 `drag_to_scroll(true)`와 이유를 적는다. 이 정책은 테마 설정으로 만들지 않는다.

### 모션 설정과 단위

모션 감소 설정은 `Settings::theme_runtime()`에서 UI 배율과 함께 `ThemeRuntime`으로 전달한다. 모션 위젯은 Theme의 값을 기본으로 읽는다. 위젯별 override는 갤러리에서 회전·정지 예제를 나란히 보여 주는 용도로 남긴다.

디자인 모션의 지속시간은 Theme 접근자에서 `Millis` 타입으로 반환한다. 외부 API를 호출할 때 초나 `Duration`으로 변환하며, UI 배율을 곱하지 않는다. 이 타입을 폴링·타임아웃 등 모든 시간 처리로 확대하지 않는다.

### 그림자 선택

떠 있는 UI의 그림자는 popover·modal 두 토큰 중 표면의 형태에 맞게 선택한다. 트리거 옆에 붙고 scrim이 없는 표면은 popover, 화면 중앙을 차지하는 표면은 modal, 어느 쪽도 아닌 표면은 그림자 없음으로 둔다. scrim 유무만으로 선택하지 않는다.

## Consequences

행 선택 표에서는 셀 텍스트를 드래그해 복사할 수 없다. 필요한 값은 행 메뉴의 복사 동작으로 제공한다. 공용 위젯에서 처리하므로 새 화면도 같은 규칙을 따른다.

페이드는 내용이 더 있다는 사실만 보여 준다. 전체 중 현재 위치와 분량은 알려 주지 못한다. 기존 영역을 이 결정만으로 일괄 변경하지 않는다.

호출부마다 모션 감소 설정을 넘기는 실수를 줄이는 대신 Theme가 런타임 설정도 담게 된다. 직접 만든 Theme에는 설정이 자동 적용되지 않으며, 현재 ThemeWire에는 reduced_motion이 없어 플러그인 프로세스로 전달되지 않는다.

`Millis`는 ms와 초의 혼동을 막는다. 대응 토큰이 없는 지속시간까지 자동으로 정리하지는 않으며, 원시 ms가 필요한 계산에는 단위를 드러내는 변환을 남긴다.

modal 그림자는 어두운 배경에서도 카드 경계를 드러낸다. scrim은 배경을 균일하게 어둡게 할 뿐 경계를 그리지 않으므로 더 큰 그림자를 사용한다. 음수 spread는 타입으로 표현하지만 egui 경로에서 근사하지 않고 미구현으로 남긴다.

## Alternatives Considered

소비처마다 라벨 sense를 바꾸면 빠진 화면이 생긴다. 앱 전체의 텍스트 선택을 끄면 로그·설명문 복사도 막는다. painter로 모든 셀을 다시 그리면 줄바꿈과 정렬을 각 소비처가 구현해야 한다.

폭 예약을 기본으로 삼으면 폭·DPI·아이콘 배치가 바뀔 때 겹침이 재발할 수 있다. 클릭이 통과하는 스크롤바는 잡을 수 없는 컨트롤이 되고, 전역 solid 스타일은 모든 화면의 콘텐츠 폭을 바꾼다.

호출부마다 모션 설정을 추가하거나 이를 검사하는 가드를 만드는 것보다 위젯 기본 동작에서 읽는 편이 누락을 줄인다. 설정용 전역 함수를 더 만들면 위젯의 의존성도 늘어난다. 시간값 이름에 `_ms`만 붙이면 단위 혼동이 컴파일을 통과하고, 모든 디자인 시간에 Duration을 쓰면 실수 밀리초와 const 생성이 불편해진다.

모든 표면에 popover 그림자를 쓰거나 모달을 1px 보더만으로 구분하면 어두운 테마에서 경계가 약해진다. 컴포넌트마다 별도 그림자를 두면 값 차이의 근거를 관리하기 어렵다. 음수 spread를 0으로 바꾸면 타이틀바 그림자가 리사이즈 영역 밖으로 퍼져 디자인을 재현하지 못한다.

문서만으로는 새 스크롤 영역이 egui 기본값을 다시 사용하는 일을 막지 못했다. 공용 래퍼는 더 강한 기본값을 제공하지만 ScrollArea·TableBuilder의 API와 소비처를 함께 옮겨야 하므로 현재는 선언 검사를 사용한다. false만 강제하면 예외 이유가 코드 밖 허용 목록으로 분리된다.

## Reconsideration Triggers

행 메뉴로 대체할 수 없는 셀 텍스트 복사가 필요하면 셀별 선택 허용 방식을 검토한다. egui의 라벨 hit-test가 바뀌면 글자 위 행 클릭과 헤더 정렬 테스트를 다시 확인한다.

스크롤 위치를 알려야 하는 긴 목록이나 공용 Table의 뷰포트·스크롤바 API 확장이 생기면 페이드와 폭 예약 예외를 다시 판단한다. 페이드 구현을 두 번째 화면에서 쓰게 되면 공용 위젯으로 옮기고 갤러리에 추가한다.

Theme에 시각 값 이외의 런타임 값이 셋 이상 필요하거나 제품에서 모션 override가 필요해지면 별도 컨텍스트를 검토한다. 플러그인 모션 위젯에도 호스트 설정을 적용하려면 ThemeWire와 Theme 재구성 경로를 함께 확장해야 한다. 원시 ms 변환이 많아지거나 지속시간이 테마별로 달라지면 타입·검사·접근자 범위를 다시 정한다.

세 번째 그림자 값이나 음수 spread의 실제 사용이 필요하면 토큰 명부·전사 검사와 렌더링 경로를 함께 검토한다. scrim이 경계를 표현하도록 바뀌면 mocha 화면에서 그림자 유무를 비교해 modal 그림자의 필요성을 다시 판단한다. 두 종류에 속하지 않는 표면이 많아져도 분류를 재검토한다.

터치 입력을 정식 지원하면 패닝 기본 정책을 재검토한다. egui 기본값이나 ComboBox API가 바뀌거나 텍스트 검사에서 빠지는 별칭·래퍼 사용이 나타나면 가드 범위 또는 공용 래퍼를 검토한다.
