# ADR-0614: 터미널 호환성은 실제 수요와 사용자 상태 보호를 기준으로 정한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: terminal, compatibility
- **Group**: terminal

## Context

이스케이프 시퀀스에는 텍스트 출력뿐 아니라 창 조작, 상태 조회, 이미지 렌더링 같은 서로 다른 기능이 섞여 있다. 파서가 인식한다는 이유만으로 모두 구현할 수는 없다.

## Decision

셀 기반 TUI에 필요한 동작부터 지원한다. PTY 프로그램이 사용자의 OS 창을 움직이거나 표시 상태를 바꾸는 XTWINOPS 명령은 지원하지 않는다. 창 위치·상태·제목 조회도 응답하지 않는다.

셀 크기 조회와 제목 push/pop은 지원한다. 픽셀 크기 조회는 현재 지원하지 않는다. 픽셀 크기는 렌더러의 폰트와 DPI 상태에 의존하며, 이를 위해 모든 터미널의 상태를 프레임마다 갱신하지 않는다.

Sixel·Kitty·iTerm 인라인 이미지와 관련 능력 조회는 보류한다. 구현할 때는 Kitty를 첫 후보로 비교한다. tmux 제어 모드 통합과 DECRQSS 설정 조회 응답도 보류한다. 일반 tmux 사용과 tmux 제어 모드 통합은 구분한다.

[터미널 기능 문서의 미지원 목록](../features/terminal/index.md#비-목표)에 있는 사설 입력 모드와 셀을 가로지르는 프로그래밍 합자도 보류한다. 번들 폰트에 합자 글리프가 들어 있다는 사실은 터미널이 합자를 지원한다는 뜻이 아니다. 실제 렌더링 지원 없이 설정 토글만 추가하지 않는다.

ED/EL로 지운 셀은 기본 문자 속성과 소거 당시 배경색만 가진다. 소거 뒤 pen은 원래대로 복원한다. `TERM=xterm-256color`가 선언하는 back color erase에 맞춘다. 소거는 커서 위치와 줄바꿈 대기 상태를 유지하며, 마지막 열 뒤에 있는 대기 커서는 지울 범위를 계산할 때 마지막 열로 취급한다.

## Consequences

지원하지 않는 명령은 무시되므로 일부 도구는 이미지가 보이지 않거나 응답을 기다린 뒤 기본값을 사용할 수 있다. 보류는 영구 거부가 아니며, 현재 지원 여부는 기능 문서에 명시한다.

## Alternatives Considered

- 모든 XTWINOPS를 무시하면 유용한 셀 크기 조회와 제목 복원까지 동작하지 않는다.
- 모든 조회에 응답하면 사용자 환경 정보와 렌더러 상태를 PTY 쪽에 추가로 노출한다.
- 이미지 전체 지원은 디코딩뿐 아니라 텍스처, 스크롤, 크기 변경, placement 수명을 함께 구현해야 한다.
- 이미지 미지원 응답만 먼저 넣는 방법과 DECRQSS만 구현하는 방법도 가능하지만 현재는 확인된 수요가 적다.

- UTF-8 마우스 등 모든 입력 변형을 구현하기보다 현재는 SGR 마우스와 일반 입력을 사용한다. Win32 raw 입력이나 픽셀 마우스가 필요한 프로그램은 개별 호환성 문제로 판단한다.
- 프로그래밍 합자는 셀을 묶는 shaping 외에도 커서·선택·색 경계에서 셀별 표시로 되돌리는 처리가 필요하다. 일부 surface만 지원하는 전역 토글도 동작을 이해하기 어려워 채택하지 않는다.

- BCE를 피하려고 TERM을 바꾸면 색과 키·마우스 등 다른 능력 선언까지 바뀐다.
- 분기별 기존 소거 결과를 유지하면 커서 행 번호에 따라 배경색이 달라지는 구현 오류를 규칙으로 굳히게 된다.
- 현재 pen 전체로 빈 셀을 채우면 밑줄 등 배경 이외의 속성도 남으므로 배경만 복사한다.

## Reconsideration Triggers

이미지·플롯·썸네일 또는 tmux 제어 모드의 실제 사용 요청이 생기면 재검토한다. DECRQSS 무응답으로 프로그램이 오동작하면 그 조회부터 따로 구현할 수 있다. 이미지 지원이나 안전한 렌더러 상태 전달 방법이 생기면 픽셀 크기 조회도 함께 검토한다. 창 상태 조회는 사용자 상태 보호 원칙을 지킬 정책이 마련되어야 한다.

ConPTY에서 특정 키가 누락되거나 픽셀 마우스·132열 전환이 필요한 사용 사례가 확인되면 해당 모드를 검토한다. 합자 수요가 있거나 cross-cell shaping 비용이 낮아지면 렌더링·설정·번역·UI를 함께 구현한다.

TERM의 BCE 선언을 바꾸거나 역상 화면의 소거 색 처리 방식을 바꿀 때 소거 규칙을 재검토한다. 줄 끝에서 곧바로 EL0/ED0을 보내는 앱이 다른 터미널과 다르게 보이면 화면을 비교한다. Tasty는 마지막 셀을 지우며, 과거 tmux 3.4 비교에서는 그 셀을 지우지 않았다.
