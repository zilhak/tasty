# ADR-0145: 길이 newtype 의 생성자는 당분간 열어 둔다 — 봉인의 이득이 정확성이 아니라 판정기의 정밀도이기 때문

- **Status**: Accepted
- **Date**: 2026-09-05
- **Tags**: typed-length, dpi, guard, tooling-cost

## Context

`PhysicalPx(pub f32)` / `LogicalPx(pub f32)` 는 튜플 필드가 공개돼 있어, 변환을 빠뜨린
생성이 그대로 컴파일된다.

```rust
PhysicalPx(rect.min.x * ppp)   // 올바름
PhysicalPx(rect.min.x)         // 변환을 빠뜨려도 컴파일된다
```

`docs/concepts/typed-length.md` 는 "변환에 scale factor 가 강제 인자라는 점이 핵심"
이라고 규정하는데, 생성자가 그 강제를 우회한다. 그래서 튜플 필드를 비공개로 만들고
raw 생성을 `from_raw()` 같은 명시적 이름으로만 허용하자는 안이 오래 검토돼 왔다.

**그 사이에 전제가 바뀌었다.** `src/dpi_conversion_guard.rs` 가 수동 DPI 산술을 소스
스캔으로 집행하고 있고, 현재 위반은 **0** 이다(`ALLOWED` 4 항목 외 0, `PENDING_PORT`
비어 있음). 즉 "변환이 타입 밖으로 샌다" 는 상태는 이미 해소돼 있고, 봉인은 **새는 것을
막는 수단이 아니라 이미 막힌 것을 다른 방식으로 막는 수단**이다.

봉인 규모를 컴파일러로 실측했다 — 튜플 필드를 `pub(crate)` 로 바꾸고
`cargo check --workspace --all-targets --keep-going`:

| 측정 | 값 |
|---|---|
| 생성자 접근 에러(E0423), 도달한 4 크레이트까지 | **214** (하한) |
| 비공개 필드 접근 에러(E0616) | **0** |
| 정의 크레이트 밖 생성자 호출(구문) | **455** (상한) |
| 그중 `src/` · `tasty-ui-widgets` · `tasty-gallery` | 177 · 36 · 11 |

214 는 총계가 아니라 **하한**이다 — `--keep-going` 도 실패한 크레이트의 의존자는
검사하지 못해, 가장 큰 소비자인 본체 바이너리에 도달하지 않았다. 진짜 값은 214 와 455
사이다. E0616 이 0 인 것은 `.0` 직접 접근이 드물기 때문이다(`.value()` 접근자 사용이
압도적이다).

## Decision

**튜플 필드를 지금 봉인하지 않는다.** 이유는 기술적 반대가 아니라 두 가지다.

첫째, **봉인이 주는 것은 정확성이 아니다.** `PhysicalPx::from_raw(x)` 는 여전히 틀린
수를 받을 수 있다 — 봉인은 "변환을 빠뜨린 생성" 을 컴파일 에러로 만들지 못하고,
raw 생성에 **이름을 붙일** 뿐이다. 진짜 이득은 그 다음이다: 가드의 바늘이
`* ppp` 같은 **줄 단위 휴리스틱**에서 `from_raw` 라는 **정확한 심볼**로 바뀐다. 그러면
현재 붙박아 둔 거짓 음성 셋(연산자와 식별자가 다른 줄로 갈리는 경우 · 매크로가 문자열
에서 코드를 만드는 경우 · 등재 파일 안에서 건수가 같은 자리 이동)이 함께 사라진다.
이득은 실재하지만 **판정기의 정밀도**이지 프로그램의 정확성이 아니다.

둘째, **비용이 통합 비용이다.** 214–455 자리는 `src/` · `tasty-ui-widgets` ·
`tasty-gallery` 를 포함해 워크스페이스 전역에 퍼져 있다. 병렬 lane 이 도는 동안 이
변경은 사실상 모든 lane 과 교집합을 갖는다 — 기계적이고 리스크가 낮은 변경이지만,
동시에 진행 중인 작업 전부를 리베이스 충돌에 노출시킨다. 그 비용은 위 이득보다 크다.

대신 **면제의 근거를 검사 가능하게 만드는 쪽**을 택했다. `ALLOWED` 의 사유 넷 중 사실
진술인 셋(`length.rs` 가 변환 API 를 정의한다 · `webview.rs` 가 왕복 양방향을 갖는다 ·
`tasty-plugin-sdk` 가 `tasty-type-geometry` 에 의존하지 않는다)을 테스트가 단정하고,
넷째(폰트 크기는 길이가 아니다)는 의미 판단이라 검사할 수 없음을 그 자리에 적는다.

## Consequences

- **얻은 것**: 진행 중인 병렬 작업이 전역 리네임에 노출되지 않는다. 면제가 근거를
  잃는 순간(예: plugin SDK 가 `tasty-type-geometry` 에 의존하게 되는 순간)을 가드가
  잡는다 — 이전에는 사유가 거짓이 되어도 가드는 초록이었다.
- **잃은 것**: 변환을 빠뜨린 생성이 여전히 컴파일된다. 가드의 거짓 음성 셋이 남는다 —
  줄이 갈린 산술 · 매크로 생성 코드 · 등재 파일 안의 건수 보존 이동. 셋 다 붙박아 뒀고
  각각의 대가가 적혀 있다.
- **운영 비용 / 유지 부담**: `ALLOWED` 표를 사람이 관리한다. 건수까지 고정하므로 이식
  으로 줄어들 때도 표를 갱신해야 한다. 그 마찰이 표가 부풀지 않게 하는 장치이기도 하다.

## Alternatives Considered

- **A. 지금 봉인한다** — 이득이 정확성이 아니라 판정기 정밀도인데 비용이 워크스페이스
  전역 리네임이다. 병렬 작업이 도는 동안에는 비용이 이득을 넘는다.
- **B. 단계 분할해 봉인한다**(크레이트 단위로 순차 봉인) — 튜플 필드의 가시성은
  크레이트 단위로 나눌 수 없다. 비공개로 바꾸는 순간 모든 외부 소비자가 동시에 깨진다.
  분할이 원리적으로 불가능하다.
- **C. `#[deprecated]` 로 유도한다** — 튜플 생성자에는 붙지 않는다(필드 속성이 아니라
  타입 속성이라 생성 자체를 겨냥할 수 없다). 경고를 낼 수단이 없다.
- **D. 아무것도 안 한다** — 면제의 사유가 거짓이 되는 것을 계속 아무도 안 본다. 이
  ADR 이 택한 쪽은 그 구멍만 닫고 봉인은 미룬다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- 병렬 lane 이 정리되어 워크스페이스 전역 기계적 변경의 통합 비용이 낮아진다.
- 가드의 붙박은 거짓 음성 중 하나가 **실제 결함을 놓친 사례**로 관측된다 — 그때는
  판정기 정밀도가 이론적 이득이 아니게 된다.
- `.0` 직접 접근이 늘어 `.value()` 접근자 경유라는 현재 관행이 깨진다(지금은 E0616 이
  0 이라 봉인 비용의 절반이 존재하지 않는다).
- 변환을 빠뜨린 생성이 실제 좌표 버그로 보고된다.
