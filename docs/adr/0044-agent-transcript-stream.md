# ADR-0044: 에이전트 응답은 transcript에서 수집해 별도 SSE로 중계한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: agents, transcript, sse, recovery
- **Group**: agents

## Context

터미널 화면에는 ANSI 처리와 화면 배치가 반영돼 응답·thinking·도구 호출을 구분하기 어렵다.
외부 소비자가 구조화된 응답을 받으려면 별도의 수집과 전달 방식이 필요하다.
본체 웹훅은 요청을 받는 용도이며 응답에 내부 실행 결과를 싣지 않는다.

## Decision

Agent Stream 플러그인이 명시적으로 지정한 서피스의 세션 transcript를 읽는다.
현재 지원하는 형식은 Claude Code JSONL이다. 세션 ID로 파일을 찾고 외부 project-slug
변환 규칙은 추측하지 않는다. 메타데이터가 없으면 최근 파일로 임의 대체하지 않고 거절한다.

수집은 플러그인 전용 스레드에서 수행한다. text·thinking·tool_use·turn_end를 구분하며
사용자 프롬프트·도구 결과·첨부 파일은 중계하지 않는다.
정상 종료뿐 아니라 오류·취소·해제·세션 교체도 종료 이벤트로 표시한다.
외부 stop_reason에는 `stop:`, 중계기가 만든 종료 사유에는 `stream:` 접두사를 붙인다.

watch와 저장 offset은 복구한다. 중복 재읽기는 허용하지만 재시작 시 무조건 파일 끝으로
이동해 중단 기간을 버리지는 않는다. 네트워크 재전송은 제한된 메모리 버퍼를 사용한다.
읽을 수 없는 구간은 gap으로 알리며, 버퍼 손실의 완전한 복구를 약속하지 않는다.

SSE 서버는 플러그인 프로세스에서 명시적으로 시작한다. 포트는 필수이고 기본 bind는
loopback이다. 그보다 넓은 주소에는 토큰이 필요하며 thinking은 구독자가 켜야 보낸다.
느린 구독자가 수집을 멈추지 않도록 제한된 큐를 사용하고 반복 손실 시 구독을 끊는다.
설정과 토큰은 재시작 복구를 위해 저장한다. TLS와 외부 연결 제한은 프록시에서 다룬다.

웹훅 요청자는 `request_id`를 만들고 turn_start 다음에 프롬프트 전송을 요청한다.
서피스당 열린 턴은 하나이며, 다음 요청은 이전 turn_end를 받은 뒤 보낸다.
턴 종료는 transcript를 사용하고 별도의 Claude idle 훅 의존성을 만들지 않는다.
진행 이벤트가 없는 턴은 타임아웃으로 닫되, 이는 에이전트 프로세스 종료를 뜻하지 않는다.

## Consequences

화면을 해석하지 않고 구조화된 응답을 얻으며, 본체의 웹훅 응답 계약을 유지한다.
외부 transcript 형식이 바뀌면 수집기가 따라가야 한다. 소비자는 중복·gap·재접속을 처리해야 한다.

토큰은 평문으로 저장되며 Unix에서는 0600, Windows에서는 기본 파일 ACL을 따른다.
호스트의 IPC 권한 검사는 이 플러그인의 자체 네트워크 서버까지 통제하지 않는다.
연결당 스레드와 HTTP 헤더 처리의 한계도 남으므로 토큰만으로 자원 제한이 해결되지는 않는다.

요청 시퀀스는 앞 단계 실패 뒤에도 다음 단계를 실행할 수 있다. 따라서 turn_start 거절이
프롬프트 전송을 막는다고 보장하지 않으며 요청 직렬화는 소비자의 책임이다.
출력이 없는 긴 작업은 타임아웃보다 오래 걸릴 수 있다. 열린 요청 턴은 재시작 후 복원하지 않는다.

## Alternatives Considered

- 화면 파싱이나 stdout 가로채기는 TUI 표현이 섞이며 구조화된 transcript의 장점을 잃는다.
- 본체나 Claude 플러그인에 수집기를 넣으면 렌더링·기존 통합 기능의 유지 범위가 커진다.
- 최신 transcript 자동 선택이나 전체 서피스 watch는 요청하지 않은 대화를 포함할 수 있다.
- 이벤트별 HTTP POST는 소비자별 재시도·순서·큐를 직접 관리해야 한다.
  WebSocket의 양방향 통신도 현재 요구에는 필요하지 않다.
- 웹훅 리스너의 응답을 확장하면 내부 실행 결과를 돌려주지 않는 신뢰 경계가 달라진다.
- 재개 없이 실시간 이벤트만 보내면 연결이 끊긴 구간을 소비자가 확인하기 어렵다.
- 토큰을 저장하지 않으면 재시작 후 같은 인증 설정으로 복구할 수 없다.
  키링은 headless 환경의 가용성이 달라 현재는 채택하지 않는다.
- 요청을 덮어쓰거나 자체 큐에 넣으면 늦게 도착한 이벤트의 요청 식별이 더 복잡해진다.

## Reconsideration Triggers

- 공식 세션 스트림이 제공되거나 transcript 형식·턴 경계가 바뀔 때.
- 다른 에이전트 형식, 동시 요청, 메시지 단위 식별, 더 강한 중복 제거가 필요할 때.
- 플러그인 샌드박스, 배포 포함 여부, 구독 규모, 소비자별 토큰·회수 요구가 달라질 때.
- HTTP 헤더·시간·연결 제한이 필요하거나 외부 노출 구성이 달라질 때.
- 웹훅 시퀀스가 실패 즉시 중단되도록 바뀌어 요청 매칭 보장이 달라질 때.
