# ADR-0040: 언어 설정과 번역 문구는 표시하는 프로세스가 일관되게 처리한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: i18n, locale, plugin
- **Group**: ui

## Context

호스트와 별도 플러그인 프로세스가 같은 언어 설정을 사용해야 한다. 위젯 밖의 기본 제목·오류·폴백 문구도 사용자에게 보인다. 표시문을 식별자로 쓰면 번역이 프로토콜 동작을 바꿀 수 있다.

## Decision

### 언어 전달

활성 언어는 general.language를 부팅 때 해석한 결과다. 호스트 번역 테이블과 자식 환경변수에 같은 실제 적용 언어를 전달한다. 환경변수는 스레드가 생기기 전 부팅 단계에서만 갱신하며 언어 변경은 재시작 후 적용한다.

### 표시문과 식별자

사용자 문구는 위젯 인자뿐 아니라 알림 제목·IPC 기본값·폴백 라벨까지 번역한다. 기계 식별은 event kind·source 등 별도 필드를 사용한다. 데이터·전송 크레이트는 값 없음이나 오류 조건을 반환하고 표시하는 쪽이 문구를 고른다.

### 언어팩과 카탈로그

새 언어팩은 코드별 디렉터리의 pack.toml과 필수 폰트 선언으로 구성한다. 내장 언어의 단일 TOML은 오버라이드 전용이다. 팩이 없거나 잘못되면 실제 적용 언어는 영어로 바꾸되 저장된 사용자 설정은 보존한다.

모든 번역 overlay에서 빈 문자열·공백뿐인 값은 번역 없음으로 처리해 직전 층을 유지한다. 팩은 영어, 내장 override는 해당 내장 언어, 플러그인 번역은 이전 카탈로그 층이 드러난다.

사용자 플러그인 번역은 설치 디렉터리와 분리된 호스트 언어 루트에 둔다. 호스트·SDK·CLI는 공용 카탈로그 로더로 설치 영어→설치 선택 언어→사용자 파일 순서로 읽는다. SDK는 TASTY_PARENT_HOME이 없으면 다른 홈이나 cwd를 추측하지 않는다.

폰트 선택은 글리프 커버리지를 제공한다. RTL 순서와 아랍 문맥 결합은 UI 텍스트 엔진의 기능이며 문자열 번역 단계에서 수동 재배열하지 않는다.

### CLI 표시와 프로토콜

CLI의 도움말·파싱 오류는 번역하되 명령·플래그·허용 값·JSON-RPC 오류의 wire 값은 유지한다. clap 오류는 ErrorKind·ContextKind로 분류하며 완성된 영어 문장을 치환하지 않는다. 플러그인 도움말 키는 선택 사항으로 두고 기존 문구를 폴백으로 사용한다.

## Consequences

플러그인은 호스트 설정 파일이나 번역 크레이트에 의존하지 않고도 언어·폰트를 받는다. 재시작 전에는 설정 변경이 즉시 반영되지 않는다.

표시 제목은 언어에 따라 달라지므로 외부 스크립트도 제목으로 이벤트 종류를 판단하면 안 된다. 팩 폴백 때 설정과 화면 언어가 다를 수 있어 로그와 GUI 경고로 알린다.

빈 문자열로 라벨을 숨기는 사용법은 지원하지 않는다. U+200B·U+2060 같은 폭 없는 문자는 남지만 NBSP 등 Unicode White_Space는 제거된다.

SDK 대신 자체 번역 로더를 쓰는 플러그인에는 사용자 override가 자동 적용되지 않는다. 호스트 카탈로그에 같은 plugin 키가 있으면 기존 호스트 우선 조회가 적용된다. 경로 컴포넌트 검사는 OS sandbox나 심볼릭 링크 격리를 뜻하지 않는다.

현재 egui 셸의 폰트 교체만으로 RTL을 정식 지원한다고 할 수 없다. CLI 하위 값 파서의 source 원문과 Rust Termination의 Error: 접두는 남을 수 있다. 비영어 파싱 진단 형식은 clap 영어 기본 형식과 다르므로 스크립트는 종료 코드·구조화된 응답을 사용한다.

## Alternatives Considered

플러그인이 설정 파일을 직접 읽으면 호스트 스키마·데이터 경로·폰트 해석을 복제한다. host-plugin이 전역 i18n에 의존하면 독립 테스트와 다른 호스트 사용도 영향을 받는다.

CLI와 호스트가 각각 기본 알림 제목을 채우면 문구의 소유가 중복된다. 데이터 크레이트에서 번역하면 원격 언어가 로컬 화면에 남거나 플러그인 번역 테이블과 어긋난다.

새 언어를 단일 파일로 허용하거나 폰트 선언을 생략하면 번역 문자열은 있어도 글리프가 빠질 수 있다. 폴백할 때 설정을 영어로 저장하면 사용자가 팩을 다시 설치해도 원래 언어로 돌아가지 못한다.

로드 경로마다 빈값 의미를 다르게 두면 같은 파일 작성 실수가 서로 다른 결과를 낸다. 모두 영어 폴백으로 맞추면 내장 언어 override의 원래 번역까지 잃는다. trim을 ASCII 공백으로 좁히면 탭·전각 공백이 빠져나간다.

플러그인 설치본을 수정하면 업그레이드에 지워진다. 호스트와 SDK가 각자 로더를 만들면 우선순위가 달라진다. 폰트 기능에서 RTL 문자열을 직접 재배열하거나 UI 텍스트 엔진을 교체하는 것은 별도 설계 범위다.

clap 출력을 통째로 영어 예외로 두면 제품 도움말이 번역되지 않는다. 문자열 치환은 사용자 입력·플러그인 번역까지 바꿀 수 있고, 서버 wire 오류를 번역하면 원격 소비자의 프로토콜 동작이 달라진다.

## Reconsideration Triggers

실행 중 언어 변경이 필요하거나 부팅 중 스레드 생성 순서가 달라지면 환경변수 대신 명시적인 프로세스 설정 전달을 검토한다. 폰트 선언·팩 배포 메타가 늘면 팩 형식을 확장한다. 번역된 제목 외의 언어 독립 분류가 필요하면 별도 식별 필드를 추가한다.

새 카탈로그 로드 경로가 생기면 빈값 규칙과 그 아래 폴백 층을 함께 확인한다. 의도적인 빈 라벨이 필요하면 폭 없는 문자가 실제 레이아웃에서 맞는지 검토한다. 플러그인 sandbox가 사용자 카탈로그 읽기를 막거나 host/plugin 동명 키 사용 요구가 생기면 해당 파일과 실제 lookup 결과로 우선순위를 검토한다.

egui의 BiDi·shaping 지원 또는 정식 RTL 요구가 생기면 UI 텍스트 엔진을 다시 검토한다. clap이 로케일 렌더러를 제공하면 기존 fixture의 출력·종료 코드·파싱 결과를 비교한다.
