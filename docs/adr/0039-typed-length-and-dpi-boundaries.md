# ADR-0039: 길이 타입으로 좌표계를 구분하고 변환 경계는 따로 검사한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: typed-length, dpi, guards
- **Group**: ui

## Context

PhysicalPx와 LogicalPx는 두 좌표계를 섞는 실수를 컴파일에서 막는다. 다만 원시 실수로 꺼낸 뒤 변환을 빠뜨리거나 수동 계산하는 실수까지 타입만으로 막지는 못한다.

## Decision

### 변환과 UI 배율

DPI 변환은 타입의 변환 메서드를 사용하고, 사각형과 WebView bounds는 짝 타입으로 전체를 한 번에 변환한다. 수동 DPI 산술은 소스 검사로 찾고 정당한 예외는 사유와 건수를 기록한다. 짝 타입의 왕복 변환은 테스트로 확인한다.

본체 UI 배율은 Theme에서 길이에 적용한다. 컨테이너 길이도 Theme 접근자를 사용해 내부 폰트·간격과 함께 커지게 한다. 토큰이 없는 길이는 원래 값을 유지하는 접근자를 두고 디자인 토큰이 생기면 연결한다.

갤러리는 egui 전역 배율을 사용하므로 리터럴과 토큰이 함께 커진다. 본체의 배율 누락 검사에 갤러리를 같은 조건으로 넣지 않는다.

### 생성자와 용도별 단위

길이 타입의 튜플 생성자는 공개로 유지한다. raw 생성에 다른 이름을 붙여도 잘못된 좌표값 자체를 막지는 못한다. DPI 가드의 허용 항목은 변환 API·왕복 변환·의존성 제한처럼 검증 가능한 근거도 함께 확인한다.

조작 영역과 디자인 치수는 논리 픽셀로 정하고, 의도적인 hairline은 물리 픽셀로 남긴다. pane 보더는 LogicalPx, surface 보더는 1 PhysicalPx다. 용도와 이유를 상수에 적고 배율 1뿐 아니라 2에서도 결과를 확인한다.

### 점진적인 타입 전환

길이 상수 전환은 이름 개수보다 영향받는 함수·호출부 범위로 나눈다. 파일 안에서 끝나는 변경부터 산술, 함수 경계를 넘는 변경 순으로 진행한다. const 계산에는 plus/minus/scaled를 사용해 타입을 벗기지 않는다.

장치가 이미 물리 좌표로 주는 입력과 상수에는 raw 생성이 필요하다. 이름 있는 생성자도 그 값의 단위를 검증해 주지 못하므로, 공개 생성자를 유지하는 이유를 단순한 이식 비용이나 동시 작업 충돌로 설명하지 않는다.

디자인 치수 검사는 디자인과 함께 바뀌어야 하는 값에 적용한다. 빈 사각형을 막는 1px 하한과 물리 픽셀 미만 비교는 값·표현 형태로 구분하고, UV처럼 0..1인 정규화 좌표는 파일·호출·건수·이유를 명부에 기록한다.

## Consequences

타입 검사와 소스 검사는 서로 다른 실수를 찾는다. 소스 검사는 실행되어야 효력이 있으며 줄 분리·매크로 생성·이름 변경 등의 누락 가능성이 있다.

Theme 접근자 검사는 접근자 내부의 배율 적용을 확인하지만 모든 호출부 리터럴을 찾지는 못한다. 갤러리가 같은 치수를 그린다는 사실만으로 본체 배율 동작을 검증할 수 없다.

선언 검사는 f32·f64 길이 const의 사용 흐름을 추측하지 않고 선언 형태를 확인한다. 아직 전환하지 않은 범위는 경로·건수·사유로 기록하고 건수가 늘지 않게 검사한다. 이는 정당한 DPI 산술 예외와 달리 제거할 잔여 작업이다.

## Alternatives Considered

생성자만 비공개로 바꾸어도 `.value()`를 꺼내 egui 좌표로 바로 보내는 계산은 그대로 가능하다. 타입이 이미 모든 변환을 보호한다고 설명하는 것도 실제 보장보다 넓다.

본체에 egui 전역 UI 배율을 적용하면 단순해지지만 native DPI 갱신 전에 계산한 낡은 배율이 남았던 문제가 있다. 호출부마다 배율을 곱하거나 범용 zoom_px로 감싸면 값의 소유와 검사 지점이 흩어진다.

모든 길이를 논리로 바꾸면 1 device-pixel hairline이 두꺼워진다. 모든 길이를 물리로 두면 고배율 조작 영역이 작아지고 인접한 논리 보더와 어긋난다. 상수 사용처를 문자열로 추적해 변경 난도를 자동 분류하면 같은 이름·여러 줄 호출·외부 API를 잘못 해석할 수 있다.

허용된 DPI 산술을 줄 번호로 고정하면 무관한 주석 수정도 검사 실패를 일으킨다. 정규화한 식 자체를 비교하는 방법은 검토 가능하지만 현재는 도입하지 않았다. UV와 화면 좌표는 같은 pos2 표현을 사용하므로 모든 1을 일괄 제외할 수 없다. 반대로 여러 파일의 1px 하한을 모두 개별 명부로 관리하면 불필요한 유지 비용이 생긴다.

## Reconsideration Triggers

수동 변환 누락이 반복되거나 검사 실행 경로가 사라지면 AST 검사·린트·타입 경계를 다시 검토한다. 본체 또는 갤러리의 배율 적용 위치가 바뀌면 검사 대상과 임시 접근자 범위를 다시 정한다.

생성자에서 직접 DPI 계산하는 코드가 늘거나 raw 장치 입력이 모두 타입을 갖게 되면 공개 생성자 결정을 다시 확인한다. 허용 산술·직접 필드 접근 증가와 실제 누락 사례를 함께 본다. 정규화 좌표 명부가 늘거나 하한 검사가 1 이외의 값까지 제외하게 되면 예외 기준도 다시 검토한다.
