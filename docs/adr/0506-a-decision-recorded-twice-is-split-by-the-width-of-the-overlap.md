# ADR-0506: 같은 결정이 서로 모르는 두 ADR 에 적혔으면 겹침의 폭으로 먼저 가른다 — 조항이면 새 ADR 로 모으고, 결정 전체면 한쪽을 Supersede 한다

- **Status**: Accepted
- **Date**: 2026-09-23
- **Tags**: adr-conventions, adr-duplication, documentation, supersede, adr-0239, adr-0030

## Context

병렬 lane 이 같은 물음에 각자 ADR 을 쓰고, 둘 다 `Accepted` 로 착지하는 일이 실제로 났다.
[ADR-0128](0128-dpi-conversion-guarded-by-source-scan-not-sealed-types.md) ·
[ADR-0145](0145-typed-length-constructors-stay-open-for-now.md) ·
[ADR-0169](0169-the-tuple-constructor-of-length-types-stays-open.md) 가 "`PhysicalPx`/`LogicalPx`
튜플 생성자를 봉인하지 않는다" 는 같은 조항을 서로 한 번도 인용하지 않은 채 결정한다.

그 상태를 정리하려고 [`template.md`](template.md) "작성 규칙" 을 보면 맞는 절차가 없다.
있는 예외 다섯은 전부 이 경우를 전제하지 않는다.

| 예외 | 전제 | 중복에 안 맞는 이유 |
|---|---|---|
| Supersede | 결정이 **바뀌었다** | 결정은 안 바뀌었다. 같은 결론이 두 번 적혔다 |
| 사실 정정 | 처음부터 사실과 어긋난 서술 | 중복은 사실 오류가 아니다 |
| 부분 개정 | 새 결정이 옛 조항을 **대체**한다 | 같은 조항이 같은 날 세 번 적힌 것을 어느 쪽이 대체하는지 말하지 않는다 |
| 구현 확정 보강 | 후속 구현이 확정한 세부를 같은 ADR 에 채운다 | 다른 ADR 의 근거를 옮겨 오는 것은 문면 밖이다 |
| References-only errata | References 만 고친다 | 근거·재검토 조건의 이전을 못 다룬다 |

그래서 중복을 고치려는 사람은 절차를 즉석에서 지어야 하고, 두 사람이 다르게 짓는다.

**남는 쪽을 고르는 기준도 하나로 안 선다.** 0128·0145·0169 에서 후보 기준 셋이 서로 다른 답을 낸다:
가장 이른 것은 0128, 운영 문서가 "현재 결정" 으로 인용하는 것은 0145
(`docs/ai-verification/dpi-scale-verification.md`), 근거·실측이 가장 두꺼운 것은 0169 다.

**겹침의 폭도 한 가지가 아니다.** 세 문서가 겹치는 것은 조항 하나이고, 각 문서에는 그 밖에
독립된 조항이 있다(0128 의 짝 타입·왕복 시험, 0145 의 면제 근거 검사, 0169 의 실측 표). 어느
한 문서를 통째로 `Superseded` 로 두면 그 독립 조항까지 죽은 것으로 읽힌다.

**의미 중복을 기계로 찾는 판정기는 짓지 않는다.** 번호 충돌은
`crates/tasty-doc-guards/tests/adr_index_parity.rs` 의 `an_adr_number_names_exactly_one_document` 가
잡지만, 번호가 다르고 결정이 같은 형태는 텍스트로 안 갈린다([ADR-0243](0243-not-building-a-judge-has-three-reasons-and-the-left-side-is-the-last-one.md)).
필요한 것은 발견됐을 때의 **처리 절차**다. 발견을 앞당기는 절차(작성 시점의 탐색 · 착지
시점의 대조)는 이 결정의 범위 밖이다.

## Decision

**겹침의 폭을 먼저 가르고, 폭에 따라 두 절차 중 하나를 쓴다.** 절차 본문은
[`template.md`](template.md) "작성 규칙" 의 "같은 결정이 두 ADR 에 적혀 있을 때" 가 운영 규칙으로
싣는다. 이 ADR 은 그 절차를 고른 근거를 남긴다.

1. **폭 판정.** 겹치는 ADR 각각의 Decision 을 조항으로 나눠 겹치는 조항과 겹치지 않는 조항을
   적는다. 어느 한쪽에라도 겹치지 않는 조항이 남으면 **조항 겹침**, 모두 겹치면 **결정 전체
   겹침**이다.
2. **조항 겹침 → 새 ADR 로 모은다(통합).** 원본 중 하나를 남는 쪽으로 고르지 않는다.
   - 새 ADR 의 제목에 `— ADR-A · ADR-B 의 <조항> 통합` 을 단다. Decision 은 그 조항의 현재 서술을
     적고, 원본들의 근거 중 **현재 판단으로 채택하는 것과 기각하는 것을 이름으로** 가른다.
     원본마다 **통합하지 않는 조항을 이름으로 열거하는 것이 필수다**(부분 개정과 같은 이유 —
     안 적으면 다음 사람이 원본 전체를 의심한다).
   - 재검토 조건은 원본들의 합집합에서 시작한다. 같은 조건은 하나로 합치고, 고유한 조건은
     살리며, 뺀 조건은 이유를 적는다. 원본끼리 재검토의 **출발점**이 다르면(한쪽은 "비용이
     줄면 다시 본다", 다른 쪽은 "막을 대상이 없다") 새 ADR 이 어느 근거가 현재 판단인지 정하고
     그 출발점 하나로 적는다.
   - 원본의 수치는 옮겨 적지 않는다 — 시점 값이라([ADR-0139](0139-numbers-in-docs-are-classified-by-lineage-not-by-name.md))
     지금 트리에서 **한 술어로 다시 재고** 그 술어를 문장으로 함께 적는다.
   - 원본은 `Accepted` 를 유지하고 References 에 `중복 조항 통합: [NNNN](<파일>) (<조항>)` 한 줄만
     더한다(부분 개정의 구 ADR 쪽과 같은 형태).
   - 새 ADR 의 References 에 `통합 대상: [ADR-A](<파일>) · [ADR-B](<파일>) (<조항>)` 를 적는다.
3. **결정 전체 겹침 → 한쪽을 남기고 다른 쪽을 Supersede 한다.**
   - 남는 쪽: 운영 문서(`docs/` 의 ADR 밖 문서)·소스가 근거로 인용하는 쪽. 둘 다거나 둘 다
     아니면 번호가 작은 쪽.
   - 지는 쪽: Status 를 `Superseded by NNNN — 같은 결정의 중복 기록` 으로 바꾼다. 인덱스 행도 같은
     값을 싣는다(가드의 `superseder()` 가 `Superseded by ` 뒤 네 자리를 대체 번호로 읽는다).
   - 지는 쪽의 **고유 근거**(남는 쪽에 없는 실측·대안·재검토 조건)는 남는 쪽 본문 끝에
     `### 흡수한 근거 — ADR-XXXX 에서` 소제목으로 옮긴다. 결정은 안 바뀌므로 Supersede 가 아니고,
     남는 쪽의 `Date` 는 그대로 둔다(새 예외 "중복 흡수 보강").
   - 지는 쪽의 근거가 남는 쪽과 **다른 전제**를 깔고 있으면 결정 전체 겹침이 아니다 — 2 로 간다.
4. **인용.** 그 조항·결정을 근거로 인용하는 **운영 문서와 소스 주석**은 새 ADR(2) 또는 남는
   쪽(3) 으로 옮긴다. 다른 ADR 본문 안의 인용은 그대로 둔다 — 원본의 References 줄(2) 이나
   Status(3) 가 한 단계로 길을 잇는다. 원본 파일은 지우지 않는다.
5. **흡수 후 삭제 · 번호 결번은 기본 절차가 아니다.** 여러 ADR 을 새 ADR 한 편으로 합치고 원본
   파일을 지우는 형태는 **사용자가 명시적으로 결정한 경우에만** 쓴다. 쓸 때는 새 ADR 의 References
   에 `흡수: ADR-A · ADR-B (파일 삭제, 번호 결번)` 을 적고, 옛 번호를 부르는 자리를 표기 변형
   (`ADR-NNNN` · `ADR NNNN` · 태그 `adr-NNNN` · 파일 경로) 전부로 세어 옮기며, 번호는
   [ADR-0239](0239-an-unused-adr-number-is-retired-not-recycled.md) 대로 재사용하지 않는다.

## Consequences

- **얻은 것**: 중복을 발견한 사람이 절차를 짓지 않는다. 조항 겹침에서 "누가 남는가" 를 고를
  필요가 없어 기준 충돌이 사라지고, 원본 어느 것도 본문을 고치지 않아 불변 원칙과 부딪히지 않는다.
- **잃은 것**: 조항 겹침마다 번호가 하나 는다(셋이 넷이 된다). 결정 전체 겹침에서는 남는 쪽의
  본문에 다른 ADR 에서 온 절이 붙는다 — 그 절이 어디서 왔는지 소제목이 말하게 해 둔 이유다.
- **운영 비용**: 발견 시점에만 든다.

## Alternatives Considered

- **(가) 조항 겹침에도 한쪽을 `Superseded` 로 둔다** — 기존 어휘·가드를 그대로 쓰지만 지는
  쪽의 독립 조항까지 죽은 것으로 읽힌다. 0128·0145·0169 가 정확히 그 형태라 안 골랐다.
  결정 전체 겹침에서는 독립 조항이 없으므로 이 형태를 쓴다(3).
- **(나) 중복을 드러내는 새 Status 값** — 뜻은 정확하지만 `superseder()` 가 모르는 형태라 인덱스
  행의 대체 번호 보존 검사(`tolerated_too_much`)를 못 받는다. 같은 뜻을 `Superseded by NNNN` 뒤
  사유로 실으면 검사도 받고 뜻도 남는다.
- **(다) 두 문서를 합친 새 ADR 로 둘 다 Supersede** — 조항 겹침이면 (가) 와 같은 결함이고, 결정
  전체 겹침이면 번호 하나를 더 쓰는 것 말고 (3) 보다 나은 점이 없다.
- **조항 겹침에서 남는 쪽을 골라 거기에 흡수** — 고르는 기준이 사례마다 다른 답을 낸다(Context).
  기준을 정하지 못하는 선택을 절차에 넣으면 절차가 다시 즉석 판단이 된다.
- **(마) 흡수 후 삭제를 기본으로** — 결정의 흔적이 git 이력과 `흡수:` 한 줄로만 남는다.
  인용을 전부 옮겨야 하므로 비용도 가장 크다. 사용자 결정으로만 쓰는 예외로 둔다(5).

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

**원리적으로 안 붙는 것** — 사람이 관측해야 한다. 재는 법을 함께 적는다.

- 조항 겹침 통합 ADR 이 늘어 한 조항에 통합 ADR 이 둘 이상 생기면(통합의 통합). 재는 법:
  `git grep -l '중복 조항 통합:' -- docs/adr/` 의 대상 번호를 모아 한 조항이 두 번 나오는지 본다.
- 폭 판정에서 조항 경계가 사람마다 갈려 같은 사례가 두 절차로 처리되면. 재는 법: 이 절차를 쓴
  사례의 Decision 에 적힌 "통합하지 않는 조항" 목록을 다른 사람이 원본과 대조해 본다.
