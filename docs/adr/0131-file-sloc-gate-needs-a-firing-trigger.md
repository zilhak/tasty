# ADR-0131: 파일 SLOC 게이트는 발화하는 트리거를 갖는다 — 채널 없이 쌓인 26 건은 부채로 동결하고 래칫으로 갚는다

- **Status**: Accepted
- **Date**: 2026-09-04
- **Tags**: ci, quality-gate, complexity, tokei, file-size, ratchet, trigger, drift, adr-0037

## Context

ADR-0037 이 복잡도 게이트를 축 둘로 세웠다 — 함수 cognitive(clippy `deny`)와 파일 SLOC
(`scripts/check-file-size.sh`, tokei 로 code SLOC > 1000 인 Rust 파일 차단). 앞 축은 컴파일
단계에 얹혀 있어 자동 잡이 볼 때마다 강제된다. 뒤 축은 `complexity-check.yml` 이라는 별도
워크플로에 있고, 그 워크플로의 트리거는 `pull_request` + `workflow_dispatch` 였다.

**이 저장소는 PR 을 열지 않는다.** 통합 지점이 로컬 `main` 이고 거기에 직접 push 한다.
실측(2026-09-04): 최근 200 run 의 이벤트 분포가 `push 48 · schedule 8 · workflow_dispatch 1`
로 `pull_request` 가 **0** 이다. 그 결과 `complexity-check` 은 **등록 이래 run 이력이
0 건**이다(워크플로 자체는 `active` 로 등록돼 있다 — 조회 실패가 아니라 실제 0).

게이트가 안 도는 동안 무슨 일이 일어났는지를 쟀다. 게이트 도입은 2026-07-06(`8b8030c1`)
이고 그때 기존 대형 파일 18 건을 allowlist 로 동결했다. 그 파일은 **도입 커밋 이후 한 번도
바뀌지 않았다.** 2026-09-04 현재 임계 초과인데 allowlist 에 없는 파일은 **26 건**이고,
그 26 건을 도입 시점 트리(`8b8030c1`)에서 다시 재면:

- 도입 시점에 이미 1000 을 넘던 것: **0 건**
- 그때는 임계 이하였다가 넘은 것: **21 건**
- 그때는 아예 존재하지 않던 파일: **5 건**

즉 **오늘의 위반은 전부 게이트가 한 번도 실행되지 않은 60 일 사이에 쌓였다.** 동결 대상이
18 에서 44 로 늘어난 것이 채널 부재의 값이다. "가드를 만들어 두면 드리프트를 막는다" 가
아니라 "가드를 **돌려야** 막는다" 는 것이 이 측정의 내용이다.

이 게이트에는 재검토를 미룰 이유로 **러너 점유**가 걸려 있었다(`docs/dev-guide/ci-gates.md`
가 "트리거를 고칠지는 러너 점유가 걸린 별개 판단" 으로 유예해 뒀다). 그 근거도 쟀다 —
이 잡은 컴파일이 없고 tokei 실행뿐이라 초 단위로 끝나며, `cargo install tokei` 스텝은
러너에 이미 있으면 no-op 이다(부재 시 로컬 실측 39 초, 1 회). self-hosted Linux X64 한 대를
`check-headless` 전체 스위트와 공유하지만 **추가 점유가 분 단위가 아니라 초 단위**다.

## Decision

**`complexity-check.yml` 에 `push: branches: [main]` 을 추가한다.** PR 트리거는 남겨두되
실질 채널은 main push 다. `paths-ignore` 는 `crossplatform-check` 와 같은 세 경로
(`docs/**` · `site/**` · `**/*.md`)를 쓴다 — 이 게이트는 `.rs` 의 code SLOC 만 보므로 문서만
담은 push 는 판정을 바꿀 수 없고, 레포 전체를 훑는 문서 가드와 달리 여기서는 그 제외가
사각을 만들지 않는다.

**트리거를 켜는 것과 같은 커밋에서 위반 26 건을 allowlist 에 동결한다.** 켜기만 하면 다음
main push 가 즉시 빨개지고, 잡을 넓히는 변경은 그것이 실제로 초록인지 확인한 뒤에 내야
한다. 26 건을 지금 쪼개는 것은 이 결정의 범위 밖이다(파일 하나가 3444 SLOC 이다).

**다만 그 26 건은 기존 18 건과 같은 것이 아니다.** allowlist 안에서 구분된 블록으로 두고,
그 블록에 "정당화된 예외가 아니라 부채 대장" 이라고 적는다. 위 18 건은 게이트 도입 시점의
기존 자산이고, 아래 26 건은 게이트가 안 도는 동안 새로 생긴 위반이다. ADR-0037 이 이미
세워 둔 래칫 조항(리팩터로 1000 이하가 되면 줄을 삭제)이 이 블록의 유일한 정상 종료다.

## Consequences

- **얻은 것**: 파일 SLOC 축에 **실제로 발화하는 자동 채널**이 처음 생겼다. 이제 27 번째
  위반은 main push 에서 즉시 빨개진다. 그리고 "채널 없는 가드에 드리프트가 쌓인다" 가
  추측이 아니라 **60 일 / 26 건**이라는 수로 기록됐다.
- **잃은 것**: 동결 목록이 18 → 44 로 늘었다. 그중 26 건은 정당화 없이 들어간 것이라,
  allowlist 를 "정당한 예외 목록" 으로 읽던 독법이 더는 통하지 않는다. 블록 주석이 그
  독법을 갈라주지만, 주석은 코드가 아니다 — 두 블록의 차이를 게이트가 강제하지는 않는다.
- **운영 비용 / 유지 부담**: self-hosted Linux X64 러너의 main push 당 추가 점유가 초 단위로
  늘어난다. 이 러너는 `check-headless`(전체 스위트) · `semver-guards` · `supply-chain-check`
  · release 빌드가 공유하며, 같은 ref 의 중복 실행은 `concurrency` 로 취소된다.
- 부채 26 건은 갚기 전까지 남는다. 래칫이 **한 방향**이라 새 위반은 못 들어오지만, 기존
  26 건이 저절로 줄지는 않는다.

## Alternatives Considered

- **A. 트리거를 그대로 두고 26 건을 먼저 쪼갠다** — 순서가 뒤집혀 있다. 쪼개는 동안에도
  게이트는 안 돌아 27 번째가 계속 들어온다. 게다가 26 건 분해는 그 자체로 대형 작업이고
  (최대 3444 SLOC), 그것이 끝날 때까지 채널이 없다는 상태가 유지된다.
- **B. 트리거를 켜되 게이트를 비차단(보고 전용)으로 둔다** — 채널이 생긴 것처럼 보이지만
  아무것도 막지 않는다. "잡이 초록이다" 와 "게이트가 강제한다" 를 갈라 놓는 형태를 새로
  들이는 것이라, 이 ADR 이 고치려는 문제(채널의 존재와 채널의 효과를 혼동하는 것)를 한
  겹 더 만든다.
- **C. `pull_request` 트리거를 살리려 PR 워크플로로 전환한다** — 통합 방식 자체를 바꾸는
  결정이고 이 게이트 하나가 근거가 될 수 없다. 게다가 그 전환 전까지는 여전히 채널이 없다.
- **D. 임계(1000)를 올려 26 건을 위반이 아니게 만든다** — 측정된 드리프트를 임계 조정으로
  지우는 것이라 ADR-0037 의 래칫이 의미를 잃는다. 동결은 부채임이 드러나지만 임계 상향은
  드러나지 않는다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- 부채 블록 26 건이 래칫으로 모두 사라지면 — 블록 주석과 이 ADR 의 구분이 불필요해진다.
- 이 저장소가 PR 을 실제로 열기 시작하면 — `pull_request` 트리거가 장식이 아니게 되고,
  main push 와 중복 실행이 되므로 어느 쪽을 남길지 다시 판단한다.
- self-hosted Linux X64 러너의 점유가 문제가 될 만큼 커지면 — 이 잡은 초 단위지만 그
  러너를 쓰는 잡이 늘면 합이 문제가 된다.
- 파일 SLOC 축이 clippy 처럼 컴파일 단계에 얹히는 수단이 생기면 — 별도 워크플로와 그
  트리거 자체가 불필요해진다.
