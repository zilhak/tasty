# ADR-0615: 마우스와 입력 상태는 실제 입력 경로에서 판단한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: input, mouse, busy
- **Group**: terminal

## Context

TUI가 마우스를 사용하는 동안에도 사용자는 터미널 텍스트를 선택하거나 메뉴를 열 수 있어야 한다. 입력 전달, 입력 기록, 상태 추정이 서로 다른 대상을 보면 오작동하기 쉽다.

## Decision

마우스 트래킹을 켠 앱에는 클릭·릴리스·드래그·휠을 보고한다. SGR 인코딩을 우선하고 협상되지 않으면 X10을 사용한다. 휠·버튼·debug 주입은 같은 인코더를 사용한다.

사용자가 Shift와 함께 좌클릭하거나 우클릭하면 로컬 선택 또는 메뉴를 사용한다. 이 선택은 누른 순간 결정해 릴리스까지 유지한다.

Shift 우회 방법은 마우스 캡처 안내 배너로 알린다. 캡처 자체를 끄는 설정과 안내만 숨기는 설정은 구분한다. Shift는 세 OS에서 같은 조작으로 사용할 수 있고 Alt/Option의 Meta 입력과 충돌하지 않는다.

버튼 없는 hover는 OS 창과 surface가 모두 포커스된 경우에만 보고한다. 분할선·창 리사이즈 가장자리·분할선 드래그 중에는 보고하지 않는다. hover 때문에 포커스를 옮기지 않는다. 버튼 드래그는 press 시점의 surface를 계속 사용한다.

앱별 캡처 설정과 배너 설정은 별도 목록으로 보관한다. 배너의 더보기 메뉴와 Settings는 같은 목록을 수정한다. 안내를 숨기더라도 앱 입력은 유지할 수 있어야 한다.

휠 한 칸의 논리 포인트 거리는 같은 창의 host·plugin·overlay에서 동일하게 계산한다. `GeneralSettings.wheel_line_scroll`을 egui `Options::line_scroll_speed`에 적용하고 모든 변환이 이 값을 읽는다. 기본값 50pt는 기존 plugin 전달값을 유지한 선택이다. 시각 테마나 단축키 설정에 넣지 않는다.

실행 중(busy) 표시는 이전에 확인한 상태를 사용한다. 키 입력은 idle에서 busy가 되는 것을 잠시 막을 수 있지만, 이미 busy인 프로그램을 idle로 바꾸지는 않는다. foreground가 셸로 돌아오거나 출력이 일정 시간 없을 때 해제한다. 락 경합 때문에 임시로 busy라고 응답한 값은 다음 판단의 근거로 저장하지 않는다.

`surface.is_typing`은 사용자가 초안을 입력했을 가능성을 알리는 상태다. 키보드·IME·붙여넣기를 기록하고 에이전트 send/tell, 마우스 보고·휠·클릭 커서 이동·새 탭을 여는 파일 드롭은 기록하지 않는다. 붙여넣기는 단축키와 명령 팔레트가 공유하는 `run_paste` 진입점에서 포커스된 surface에 기록한다.

## Consequences

TUI의 마우스 기능과 사용자의 로컬 조작을 함께 제공한다. 앱에 press를 보내지 않은 드래그는 motion과 release도 보내지 않아야 한다. macOS의 미들클릭 보고 구현과 대상 앱의 paste 동작 확인은 별개이며, 후자는 확인되지 않았다.

Shift+클릭 자체는 앱에 전달되지 않는다. 앱이 이 조합을 요구하면 설정 가능한 우회 키나 앱별 예외를 검토한다. 드래그 중 Shift 상태를 다시 판단하면 선택이 끊기거나 앱에 잘못된 release가 전달되므로 최초 판단을 유지한다.

빈 클립보드나 붙여넣기를 지원하지 않는 surface에서도 사용자의 시도를 기록한다. 이는 에이전트 전송을 잠시 늦출 수 있다. 원격 이미지 업로드는 시작 시점에 기록하므로 업로드가 5초를 넘으면 실제 경로 삽입 시점의 typing은 false일 수 있다. 턴 시작 뒤 사용자 입력 여부를 보는 idle_seconds 기록은 남는다.

## Alternatives Considered

항상 로컬 선택으로 처리하면 앱 마우스 기능을 잃는다. 우클릭만 항상 가로채면 앱마다 입력이 다르게 전달된다. Shift를 선택적으로 사용하면 기본 앱 입력을 유지하면서 로컬 조작을 요청할 수 있다.

- 커서 아래 모든 surface로 hover를 보내면 사용자가 고르지 않은 배경 앱에 입력이 전달된다. focus-follows-mouse는 키 입력 대상까지 바꾸므로 채택하지 않는다.
- 배너 억제를 캡처 목록의 enum으로 합치면 기존 설정 형식과 이행 과정이 복잡해진다.
- 배너 content 콜백에는 surface ID가 없으므로 더보기 동작은 대상 scope를 아는 BannerManager와 popup 연결부에서 처리한다.

- 휠 값을 일부 overlay만 맞추면 host 위젯과 plugin의 차이가 남는다. egui 기본값 40을 그대로 따르면 이미 사용하던 plugin 전달 거리까지 바뀐다. 고정값만 바꾸고 설정을 숨기면 사용자가 속도를 되돌릴 수 없다.
- busy 판정에 출력 바이트·청크 수를 쓰면 PTY 읽기 크기에 따라 결과가 달라진다. 입력 텍스트 비교와 화면 재그리기 감지도 TUI의 에코와 실제 작업을 구분하지 못한다. OSC 133 실행 구간 역시 vim과 빌드를 구별하지 못하므로 대체하지 않는다.

- 실제 PTY 쓰기 지점만 기록하면 plugin 붙여넣기와 빈 클립보드 시도를 놓친다. 모든 사용자 SendToSurface를 기록하면 휠·마우스까지 타이핑으로 취급하고 IME preedit는 놓친다.

## Reconsideration Triggers

앱 호환성 보고가 들어오면 인코딩과 입력 대상, 로컬 우회 여부를 각각 확인한다. macOS 미들클릭은 실제 앱에서 붙여넣기가 가능한 조건으로 검증해 문서의 확인 상태를 갱신한다.

비포커스 surface의 hover 요구가 있으면 모든 pane의 분할선 판정을 먼저 마련한다. 셀별 중복 제거만으로 입력량이 많으면 프레임별 묶음을 검토한다. 두 앱 목록을 함께 관리하기 어렵다는 의견이 많으면 UI 통합을 검토한다. 원격 앱별 설정이 필요하면 서버의 foreground 정보 전달이 선행되어야 한다. 다른 배너에서도 더보기가 필요할 때 공통 메뉴 설정을 도입한다.

OS 휠 설정을 읽을 수 있거나 egui가 시스템 설정을 반영하게 되면 기본값의 소유자를 재검토한다. plugin이 포인트 대신 줄 단위를 요구할 때는 전달 규약도 다시 정한다. busy가 드문 출력 때문에 깜빡이면 1Hz로 30초 상태를 수집해 2초 출력 기준을 평가한다. 대화형 작업을 구별하는 신호나 `last_input_at`의 새로운 소비자가 생기면 busy 판단을 다시 검토한다.

새 입력 또는 붙여넣기 경로, 입력창에 경로를 넣는 파일 핸들러가 생기면 사용자 입력 기록 대상인지 판단한다. 빈 붙여넣기로 전송이 지연되는 문제가 보고되면 시도 시점 기록 정책을 검토한다.
