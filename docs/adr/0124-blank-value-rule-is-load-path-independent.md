# ADR-0124: 빈 값이 "번역 없음" 이라는 규칙은 로드 경로와 무관하다 — 언어팩·내장 오버라이드·plugin 언어파일이 같은 규칙을 쓰고, 폴백 대상만 다르다

- **Status**: Accepted
- **Date**: 2026-09-04
- **Tags**: i18n, language-pack, blank-value, unicode, trim, adr-0114

## Context

[ADR-0114](0114-language-pack-directory-shape-and-english-fallback.md) 가 **팩의** 빈 값을 "번역 없음" 으로 정하고 overlay 에서 걷어냈다. 그런데 번역 테이블에는 로드 경로가 **셋**이다.

- **언어팩** — `~/.tasty/lang/<code>/pack.toml`. 영어 베이스 위에 얹힌다.
- **내장 오버라이드** — `~/.tasty/lang/<builtin>.toml`. 영어 베이스 → 내장 `<code>` 문자열 위에 얹힌다.
- **plugin 언어파일** — `<plugin>/lang/<code>.toml`(`register_namespace`). 그 plugin 의 `en.toml` 위에 얹힌다.

규칙이 팩에만 걸려 있어, **같은 `key = ""` 가 로드 경로에 따라 정반대로 해석됐다.** 팩에 쓰면 아래 층이 보이고, 오버라이드에 쓰면 빈 문자열이 그대로 문자열 테이블에 들어가 화면에 라벨 없는 버튼이 그려졌다.

이 갈림은 의도가 아니라 관성이었다. 오버라이드 경로는 i18n 최초 도입(2026-03-22)부터 있었고, 빈 값 규칙은 5 개월 뒤 언어팩 기능과 함께 들어왔다. 그 커밋의 diff 는 오버라이드 코드를 리팩터링해 `builtin_strings`/`read_user_toml` 을 만들면서도 새 규칙은 팩에만 걸었다 — 다르게 두기로 한 기록은 ADR·문서·주석 어디에도 없다.

두 번째 문제는 **탈출구 서술이 처음부터 틀렸다**는 것이다. ADR-0114 를 포함한 문서·주석이 "의도적으로 비우려면 trim 이 먹지 않는 공백 문자(예: NBSP)를 쓰라" 고 안내했는데, `str::trim` 은 유니코드 `White_Space` 속성을 가진 문자를 전부 먹고 NBSP 가 거기 포함된다. 안내대로 하면 값이 그냥 사라진다.

## Decision

**빈 값 규칙은 로드 경로와 무관하다.** 값이 비었거나 공백뿐인 키는 어느 경로로 들어오든 overlay 에서 걷어내고, 걷힌 개수를 `tracing::warn!` 한 줄로 알린다. 규칙의 근거가 *파일 형상*이 아니라 *그 아래 층*이기 때문이다 — 빈 값이 문자열 테이블에 도달하면 경로와 무관하게 라벨 없는 UI 가 되고, 화면에는 어느 키가 비었는지 알 단서가 남지 않는다. 저작자가 실수로 키를 비우는 빈도가 의도적으로 비우려는 빈도보다 훨씬 높다는 ADR-0114 의 판단도 파일 형상에 의존하지 않는다.

**드러나는 것은 다르다 — 그것이 이 결정의 정확한 범위다.** 팩은 영어 베이스 위에 얹히므로 걷힌 키가 영어로 보이고, 오버라이드는 내장 `<code>` 문자열 위에 얹히므로 **그 언어의 원래 문구**로, plugin 언어파일은 그 plugin 의 `en.toml` 위에 얹히므로 **그 plugin 의 영어**로 보인다. 같아야 하는 것은 "빈 값이 화면에 도달하지 않는다" 이지 "같은 문자열이 보인다" 가 아니다.

**세 경로는 한 함수를 공유한다.** 빈 값 제거와 warn 은 `drop_blank_values_warned` 한 곳에 있고 세 로더가 모두 그것을 호출한다 — 규칙이 다시 갈라지려면 호출을 지워야 하고, 그것은 아래 가드가 잡는다. `crates/tasty-i18n` 의 단위 테스트가 **같은 입력을 세 경로에 각각 넣어** 전부 빈 문자열을 내지 않는지 고정한다. 일부만 검사하는 테스트는 이 결정을 지키지 못한다 — 애초에 팩 쪽 테스트만 있었기 때문에 오버라이드의 비대칭이 5 개월간 발견되지 않았고, 그 뒤 팩·오버라이드만 검사하는 테스트를 붙였기 때문에 **plugin 경로가 한 번 더 남았다.** 같은 실수가 두 번 났다는 것이 "일부만 검사하면 남는다" 의 증거다.

**의도적으로 빈 텍스트를 두는 탈출구는 폭 없는 문자다.** `str::trim` 이 유니코드 `White_Space` 를 전부 먹으므로 "공백처럼 보이는 문자" 는 탈출구가 되지 못한다. 실측(2026-09-04, `drop_blank_values` 에 직접 투입):

| 입력 | 결과 |
|---|---|
| `""` (빈 문자열) | 걷힘 |
| `" "` (SPACE U+0020) | 걷힘 |
| `"\t"` (TAB U+0009) | 걷힘 |
| `"\u{00A0}"` (NO-BREAK SPACE) | 걷힘 |
| `"\u{2007}"` (FIGURE SPACE) | 걷힘 |
| `"\u{3000}"` (IDEOGRAPHIC SPACE) | 걷힘 |
| `"\u{200B}"` (ZERO WIDTH SPACE) | **남는다** |
| `"\u{2060}"` (WORD JOINER) | **남는다** |

즉 탈출구는 **U+200B · U+2060** 이며, 이 표 자체가 결정의 운영 조건이라 테스트로 고정한다.

## Consequences

- **얻은 것**: 같은 입력이 같은 의미를 갖는다 — "팩에서는 되는데 오버라이드에서는 안 된다" 는 설명 불가능한 차이가 사라졌다. 규칙이 코드 한 곳에 있어 다음 로드 경로가 생겨도 그 함수를 부르면 자동으로 규칙 안이다. 문서가 안내하는 탈출구가 실제로 동작한다.
- **잃은 것**: `~/.tasty/lang/<code>.toml` 에서 값을 빈 문자열로 두어 특정 문구를 화면에서 지우던 사용법이 더 이상 통하지 않는다 — 이제 그 언어의 원래 문구가 다시 보인다. 폭 없는 문자로 우회할 수 있으나 **동작이 바뀌는 변경**이라 CHANGELOG 의 `Changed` 에 탈출구와 함께 적는다.
- **운영 비용 / 유지 부담**: 오버라이드 병합이 `apply_user_override` 로 분리됐다(빈 값 처리가 들어가며 `builtin_strings` 가 복잡도 게이트 20 을 넘었기 때문). 결과적으로 "규칙이 한 곳" 이라는 형태와 일치하므로 `#[allow]` 동결은 쓰지 않았다.

## Alternatives Considered

- **A. 팩 쪽을 오버라이드에 맞춘다(빈 값을 그대로 반영)** — ADR-0114 의 대안 G 를 뒤집는 것이다. 실수와 의도를 구분할 수 없고 결과가 "UI 가 깨져 보이는데 원인을 화면에서 못 찾는" 상태라는 판단은 그대로 유효하며, 파일 형상과 무관하다.
- **B. 갈린 채로 두고 문서만 조건부로 고친다** — "팩은 걷고 오버라이드는 안 건다" 를 정확히 적는 선택. 그러려면 그 차이를 정당화하는 근거가 있어야 하는데, 규칙의 인과(아래 층이 가려진다)가 양쪽에 똑같이 성립해 근거를 만들 수 없다. 문서만 정확해지고 사용자가 겪는 비대칭은 남는다.
- **C. 오버라이드는 걷되 폴백을 영어로 맞춰 "완전히 같은 결과" 로 만든다** — 두 경로의 결과 문자열까지 같아지지만, 한국어를 쓰는 사용자가 오버라이드 한 줄을 비웠다고 그 자리만 영어가 되는 것은 명백한 퇴행이다. 오버라이드의 아래 층은 원래 그 언어다.
- **D. 빈 값에 경고만 하고 값은 반영** — 라벨 없는 UI 를 그대로 두고 로그에만 남긴다. GUI 사용자는 로그를 보지 않으므로 "화면에서 원인을 못 찾는" 상태가 그대로다.
- **E. NBSP 를 탈출구로 유지하기 위해 `trim` 대신 `trim_matches(' ')` 로 좁힌다** — 탈출구 문서를 사실로 만드는 대신 `\t`·전각 공백 등이 빈 값 판정을 빠져나간다. 판정 기준을 유니코드 표준(`White_Space`)에 맡기고 탈출구 쪽을 정정하는 편이 예측 가능하다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- **네 번째** 로드 경로가 생길 때(예: 원격 팩) — 그 경로의 아래 층이 무엇인지에 따라 "폴백 대상만 다르다" 의 서술을 확장한다. 이 항목은 원래 "세 번째 로드 경로가 생길 때(예: plugin 자체 언어팩)" 라고 적혀 있었다 — plugin 경로를 **미래형으로 적었지만 이미 존재했고**, 그래서 이 결정이 처음 들어갈 때 그 경로만 규칙 밖에 남았다. 새 경로를 셀 때는 있는 것을 먼저 세어라.
- 재시작 없는 언어 전환이 생겨 overlay 를 런타임에 다시 얹게 될 때 — 걷어낸 키를 되돌리는 경로가 필요해진다.
- 의도적으로 빈 문자열이어야 하는 UI 문구가 실제로 요구될 때(예: 특정 로케일에서 접두사를 지워야 하는 경우) — 폭 없는 문자 우회가 그 자리에서 실제로 성립하는지(레이아웃·폭 계산) 확인해야 한다.
- Rust 의 `str::trim` 이 기준으로 삼는 `White_Space` 집합이 바뀔 때 — 위 표가 결정의 운영 조건이므로 테스트가 먼저 깨진다.
