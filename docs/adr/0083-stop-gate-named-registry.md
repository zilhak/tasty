# ADR-0083: Stop-훅 게이트를 이름으로 등록하는 레지스트리로 일반화한다

- **Status**: Accepted
- **Date**: 2026-08-24
- **Tags**: claude-plugin, registry, stop-hook, gate, session-profile, cli, ipc, i18n

## Context

Claude Code 의 `Stop` 훅이 `{"decision":"block","reason":"<본문>"}` 을 내면 세션 종료가
막히고 `reason` 이 지시로 주입된다. tasty 는 이 위에 게이트 하나를 얹어 두었다 —
`continue-checklist` 세션 프로필을 부착하면 그 훅이 심기고, 세션별 라운드 카운팅 ·
센티넬 판정 · 라운드 상한 백스톱 · 마커 파일 즉시 토글이 함께 따라온다.

문제는 그 게이트를 구성하는 3요소가 전부 컴파일 타임에 고정돼 있었다는 것이다.
본문은 plugin 기동 시 1회 읽는 번역 키(`claude.checklist.body`), 센티넬은 소스 상수,
라운드 상한은 plugin Settings 항목 하나, 게이트 이름 자체는 세션 프로필 조회 함수의
`match` 팔이었다. 사용자가 자기 체크리스트를 쓰려면 자기 프로필에 자기 스크립트를
Stop 훅으로 직접 심는 수밖에 없었고, 그러면 위 인프라를 통째로 재구현해야 했다.

한편 그 아래층인 **세션 프로필 레지스트리는 이미 사용자 등록을 지원**한다 —
short-name 규칙, `<owner>/<short>` id, plugin 전용 데이터 디렉토리 하위 저장,
등록/조회/해제 CLI+IPC 가 갖춰져 있다. 즉 "이름으로 등록하는 레지스트리" 라는 형태는
이 plugin 안에 이미 확립돼 있었고, 게이트만 그 형태를 따르지 못하고 있었다.

## Decision

Stop-훅 게이트를 **(본문, 센티넬, 라운드 상한) 3요소를 이름으로 등록하는 프리미티브**
로 일반화하고, `continue-checklist` 를 그 위의 host 기본 인스턴스 하나로 재정의한다.
레지스트리는 세션 프로필 레지스트리의 형태를 미러링하되 타입은 공유하지 않는다.
게이트 정의는 plugin 데이터 디렉토리 하위 `gates/registered/<name>.json` 에, 본문은
등록 시 복사한 `gates/bodies/<name>.md` 에 둔다. host 기본 게이트는 파일로 실체화하지
않고 조회 함수로만 존재한다. 노출은 CLI + IPC 양면이며 GUI 는 범위에 넣지 않는다.

게이트 이름은 세션 프로필 이름과 **같은 평면**이다 — 게이트를 등록하면 동명 프로필로
그대로 부착 가능해지고, 별도 attach 문법을 만들지 않는다. 그 대가로 같은 이름이 양쪽에
생길 수 있으므로, 조용한 shadowing 을 만드는 대신 **등록 시점에 양방향으로 거부**한다.

등록 본문은 그 게이트의 실효 센티넬을 포함해야 한다. 포함하지 않으면 모델이 종료를
선언할 방법을 안내받지 못해 라운드 상한까지 무조건 도달하고, 게이트가 "N턴 강제 연장"
장치로 변질된다. 이 불변식은 host 기본 본문에 대해 이미 로케일별 컴파일 타임 테스트로
강제되고 있었으므로, 사용자 본문에 대해서는 같은 불변식을 등록 시점 런타임 검증으로
옮긴다.

## Consequences

- **얻은 것**: 사용자가 자기 게이트를 이름으로 등록해 쓸 수 있고, 그때 세션별 라운드
  카운팅 · 센티넬 판정 · 상한 백스톱 · 마커 토글을 재구현하지 않아도 된다. 게이트가
  독립적으로 조회·열거되므로 "지금 어떤 게이트가 있고 각각의 실효 센티넬/상한이
  무엇인가" 를 한 번에 볼 수 있다. `continue-checklist` 가 고유명에서 인스턴스 하나로
  내려오면서 게이트 코드에 그 이름이 박히는 자리가 사라진다.
- **잃은 것**: 이름 공간이 프로필과 한 평면이라, 사용자는 두 레지스트리를 합쳐 하나의
  이름 집합으로 관리해야 한다. 동명 등록이 거부되므로 "프로필과 게이트에 같은 이름을
  쓰고 싶다" 는 요구는 만족시킬 수 없다.
- **운영 비용 / 유지 부담**: 저장 디렉토리가 하나 늘고(`gates/`), 정의와 본문이 두
  파일로 나뉘어 해제 시 **둘 다** 지워야 하는 불변식이 생긴다(본문만 남으면 다음
  등록이 옛 본문을 조용히 덮어쓰는 것처럼 보이는 orphan 이 된다). host 기본 게이트를
  추가할 때는 조회 함수와 이름 목록 상수를 함께 고쳐야 한다.

## Alternatives Considered

- **A — 본문만 사용자 파일로 교체**: 인스턴스 전역 본문 파일 하나를 두고 set/clear
  CLI 만 붙이는 안. 변경 표면이 가장 작지만 체크리스트가 인스턴스 전역 하나로 고정돼
  프로필/세션별로 다른 게이트를 걸 수 없다. 센티넬과 라운드 상한은 여전히 고정이라
  "게이트를 정의한다" 는 요구의 3분의 1만 충족한다.
- **B — 프로필별 사이드카 메타에 체크리스트를 얹음**: `registered/<name>.tasty.json`
  같은 파일을 프로필 옆에 두는 안. 게이트를 프로필의 부속물로 만들기 때문에 게이트를
  독립적으로 조회·열거할 수 없고("지금 어떤 게이트들이 있나" 에 답하려면 모든 프로필을
  훑어야 한다), 게이트만 재사용하고 싶을 때 프로필을 함께 복제해야 한다.
- **C(기각) — 프로필 JSON 자체에 tasty 확장 필드 주입**: 저장 파일이 하나로 줄어 가장
  단순하지만, `registered/<name>.json` 은 Claude Code 에 `--settings` 로 **그대로**
  넘어가는 파일이다. 미지 필드가 섞이면 외부 도구가 거부할 위험이 있다.
  ⚠️ 이 위험 자체는 외부 런타임(Claude Code)의 동작이라 **이 저장소에서는 검증할 수
  없다** — 확인된 사실이 아니라 회피한 위험으로 기록한다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- 게이트가 `Stop` 외의 Claude Code 훅 이벤트(예: `PreToolUse`)로 확장될 때 — 3요소
  스키마가 이벤트 종류를 담지 않으므로 정의 스키마 자체를 다시 봐야 한다.
- 게이트 소비자가 claude plugin 밖으로 늘어날 때(예: codex plugin — 현재 codex
  매니페스트에는 프로필 개념 자체가 없다). 두 plugin 이 같은 게이트를 공유해야 하면
  저장 위치가 plugin 전용 데이터 디렉토리에 머물 수 없다.
- 이름 공간을 프로필과 공유하는 비용이 실제로 문제가 될 때 — 동명 거부가 잦은 마찰로
  드러나면 게이트 id 에 별도 prefix 를 주고 attach 문법을 나누는 쪽을 다시 검토한다.
