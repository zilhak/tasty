## 작성 규칙

이 절은 새 ADR에 복사하지 않는다.

### 새 ADR을 쓰기 전에

[제품 원칙](../principles/index.md)을 먼저 읽는다. 원칙을 준수하는 일반 구현은 해당 가이드를 갱신한다. 중요한 선택이거나 대안이 있다는 이유만으로 ADR을 만들지 않는다.

원칙 간 충돌은 원칙 문서에서 충돌과 우선순위를 해소한 뒤 진행한다. 원칙을 바꾸면 최신 본문으로 갱신하고 별도 개정 이력을 누적하지 않는다.

ADR은 원칙의 예외·미충족을 채택하는 경우에만 쓴다. 같은 원칙·범위를 다루는 기존 ADR과 실제 구현을 확인한다. 개발·검증·디자인 운영 규칙의 세부 허용을 제품 원칙의 예외로 자동 승격하지 않는다.

### 번호와 상태

파일명은 NNNN-<kebab-case-slug>.md다. 새 체계의 첫 결정은 0001이며 이후에는 현재 체계에서 사용한 최대 번호 다음을 쓴다. 평소에는 기존 번호나 빈 번호를 재사용하지 않는다. 재정리에서 재번호를 명시적으로 요청받으면 [재번호 절차](../dev-guide/adr-renumber.md)에 따라 대응표와 인용을 함께 바꾼다.

Proposed는 미채택 예외, Accepted는 채택한 예외, Deprecated는 더 이상 적용하지 않는 결정이다. 다른 결정으로 대체하면 Superseded by ADR-NNNN과 대체 문서를 연결한다.

부분 개정 관계를 유지할 때는 개정 대상:과 부분 개정:을 양쪽에 적는다. 전체 대체 문서는 대체 문서와 같은 Group을 쓴다.

### 인덱스에 행을 추가할 때

Group은 예외가 적용되는 주제 하나로 정한다. 첫 결정 추가 시 빈 집합 표식을 제거하고 해당 그룹의 생성 구역을 만든다. 행은 직접 쓰지 않고 adr-index --write로 생성하고 --check로 확인한다.

### 내용과 근거

[문서 모델](../documentation-model.md)에 따라 현재 계약과 예외 결정의 이유를 분리한다. 실제 채택하지 않은 대안·보완 조치·검증 결과를 만들지 않는다. 현재 코드 경로를 연결하고 측정 범위와 한계를 구분한다. 로컬 작업 폴더나 일회성 기록을 영구 근거로 인용하지 않는다.
