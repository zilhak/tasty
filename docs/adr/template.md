## 작성 규칙

이 절은 새 ADR에 복사하지 않는다.
문서의 목적은 중요한 선택을 이해하게 하는 것이다. 형식 항목을 채우기 위해 설명을 늘리지 않는다.

### 새 ADR 을 쓰기 전에

먼저 기존 가이드나 소스 주석을 고치는 것으로 충분한지 판단한다.
ADR은 다음 조건을 모두 만족하는 중요한 선택에 쓴다.

- 서로 다른 대안 중 하나를 골랐다. 보류나 거부도 선택에 포함된다.
- 그 선택이 코드·설정·운영 방식에 지속적인 영향을 준다.
- 선택을 바꿀 만한 조건을 설명할 수 있다.

단순 측정 결과, 한 테스트의 수정법, 문장 표기 규칙은 독립 ADR로 만들지 않는다.
현재 작업 규칙은 개발 가이드에, 특정 코드의 이유는 가까운 주석에,
일회성 실험 과정은 작업 기록이나 커밋 설명에 남긴다.

인덱스의 해당 주제와 결정 대상의 심볼·파일·설정 키로 기존 ADR을 검색한다.
예: `git grep -l '<심볼>' -- docs/adr/`. 태그나 제목만으로 검색을 끝내지 않는다.
같은 선택이면 기존 ADR을 인용하거나 설명을 보강한다.
새 ADR에는 관련 결정과 관계를 짧게 적는다. 검색 기록만 검사하는 별도 가드는 만들지 않는다.

### 번호와 상태

파일명은 `NNNN-<kebab-case-slug>.md`다. 새 번호는 현재 번호 체계에서 사용한 최대 번호 다음부터 배정한다.
평소에는 기존 번호를 바꾸거나 빈 번호를 재사용하지 않는다.
대규모 재정리에서 번호 변경을 명시적으로 요청받았다면 [재번호 절차](../dev-guide/adr-renumber.md)에 따라
대응표를 보관하고 파일명과 모든 인용을 함께 바꾼다.
동시에 작성할 때는 번호 구간을 나눠 충돌을 피한다. 자릿수가 부족하면 재사용보다 확장을 검토한다.

Status의 첫 단어는 다음 중 하나다. 필요한 설명은 ` — <사유>`로 덧붙인다.

| 상태 | 뜻 |
|---|---|
| Proposed | 아직 선택이 끝나지 않음. 필요한 결정을 본문에 명시 |
| Accepted | 채택한 선택. 미이행 부분이 있으면 구체적으로 표시 |
| Deferred | 지금은 하지 않기로 한 선택 |
| Experimental | 시험 운영 중이며 결과에 따라 다시 결정 |
| Deprecated | 대체 결정 없이 폐기 |
| Superseded by ADR-NNNN | 다른 ADR이 대체 |

사실 정정, 링크 수정, 문장 개선은 같은 문서에서 한다.
결정을 바꾸는 경우에는 바뀐 선택과 이유를 추적할 수 있게 남긴다.
과거 결정의 이유를 현재의 이유인 것처럼 덮어쓰지 않는다.

### 같은 결정이 두 ADR 에 적혀 있을 때

각 문서의 현재 유효한 선택과 고유한 근거를 읽고 겹치는 범위를 확인한다.
중복 조항을 정리하려고 새 ADR을 계속 추가하기보다 해당 주제의 설명을 한곳에서 읽게 한다.
운영 규칙과 검사 방법은 적절한 가이드로 옮기고, 중요한 기각 이유와 재검토 조건은 보존한다.
원본과 다른 전제에서 나온 내용을 같은 선택이라고 단정하지 않는다.

전체를 대체하면 이전 문서의 Status와 새 문서의 References를 연결한다.
일부만 바뀌면 현재 적용 범위와 대체 위치를 문서 앞에서 알리고,
남아 있는 유효한 선택까지 폐기한 것처럼 표시하지 않는다.
원본을 보관하고 삭제하는 정리가 승인된 경우에는 원본별 이동 위치와 제외 이유를 남기고
코드·가이드·다른 ADR의 인용을 모두 현재 위치로 바꾼다. 번호 변경은 위 절차를 따른다.

기존 부분 개정 관계를 유지하는 경우에는 `개정 대상:`과 `부분 개정:`을 양쪽에 남긴다.
전체 대체된 문서는 대체 문서와 같은 Group에 둔다.

### 재검토 조건

'필요하면' 대신 어떤 전제가 달라지는지 쓴다.
소스·설정에서 확인할 수 있는 조건과 실행 결과·사용자 경험을 관찰해야 하는 조건을 구분한다.
여러 조건이 섞여 길어지면 '코드와 설정에서 확인'과 '실행 결과로 확인'처럼 소제목을 쓴다.
빈 분류나 모든 문서에 같은 소제목을 억지로 넣지 않는다.

자동 검사가 있으면 이름과 검사 범위를 적는다. 없으면 자동으로 확인되는 것처럼 쓰지 않는다.
관측이 필요한 조건에는 확인 방법을 적는다. 모든 조건에 새 검사를 추가하지 않는다.
실제로 가까워진 조건과 자주 바뀌는 코드부터 필요한 검사를 검토한다.
조건과 무관한 문서 수나 파일 수를 대신 검사해서 재검토를 요구하지 않는다.

### 근거와 인용

[문서 작성 규칙](../documentation-model.md)을 따른다.
현재 구현은 파일과 심볼로 인용한다. References는 별도 설명이 없으면 현재 위치다.
결정 당시 사라진 구현을 설명해야 하면 당시 상태임을 명시한다.
나중의 무관한 파일 이동으로 깨진 경로는 갱신한다.
로컬 작업 티켓, 임시 경로, 일회성 원격 기록을 영구 근거로 쓰지 않는다.

### 인덱스에 행을 추가할 때

Group은 선택 대상이 속한 주제 하나로 정한다. 규칙·검증·문서 관리 결정은 해당 운영 주제에 둔다.
그룹 slug는 식별자이며 제목을 다듬을 때마다 바꾸지 않는다.
행은 직접 고치지 않고 `cargo run -p tasty-doc-guards --bin adr-index -- --write`로 생성한다.
그룹 머리말에는 현재 규칙의 위치와 필요한 관계만 짧게 적는다.
병합할 때는 새로 추가·변경·이동한 ADR의 내용도 비교한다.
[인덱스 관리](../dev-guide/adr-index.md)에 명령과 충돌 해결 방법이 있다.
