# ADR-0638: 프리셋 초안은 편집 중에 보존하고 저장 충돌을 확인한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: preset, draft, concurrency
- **Group**: ui

## Context

프리셋 화면은 저장소의 레이아웃을 캐시해 편집한다. 외부 저장이 그 사이 발생하면 캐시 전체를 저장하는 방식이 새 내용을 덮을 수 있다. 종류를 둘러보는 과정에서도 아직 확정하지 않은 값이 지워져서는 안 된다.

## Decision

### 설정 초안

surface 설정 초안은 kind를 바꿔도 값을 보존한다. 최종 kind가 원래와 다를 때만 확인 시점에 불필요한 필드를 정리한다. 같은 kind이면 선언된 필드만 덮고 알 수 없는 params는 보존한다. 빈 필드의 default는 전환할 때 보여 주어 확인 후 저장값과 맞춘다.

저장은 캐시 사본에 초안을 적용한 뒤 시도한다. 디스크 저장이 실패하면 캐시·초안·화면을 유지하고 오류를 알린다.

### 충돌 확인

캐시를 만든 시점의 레이아웃과 저장 직전 레이아웃이 다르면 저장하지 않는다. 외부 내용을 다시 읽고 이번 사용자 변경을 버린 사실을 알린다. 비교는 덮어쓸 레이아웃 부분에 한정하며 메타데이터 변경은 충돌로 보지 않는다.

### 보기와 편집의 갱신

보기 모드는 매 프레임 저장소를 따라가고 편집 중인 캐시는 따라가지 않는다. 보기→편집 전환 프레임에도 편집에 들어가기 전 한 번 확인한다. 캐시와 이전 모드 기록은 프리셋별로 분리한다.

## Consequences

종류를 왕복해도 초안 값이 남고 외부 저장을 조용히 덮지 않는다. 충돌 때에는 이번 변경이나 설정 초안을 잃고 다시 편집해야 한다. 편집 중 외부 변경은 저장할 때 알 수 있다.

보기 미리보기가 갱신되면 사용자가 눌렀던 mini-tab은 저장된 활성 탭으로 돌아갈 수 있다. 안정적인 pane ID가 없어 이전 보기 상태를 새 트리로 옮기지 않는다. 선택한 프리셋·모드·목록 스크롤은 유지한다.

## Alternatives Considered

전환할 때마다 새 kind의 키만 남기거나 surface를 통째로 교체하면 왕복 중 기존 params를 잃는다. default를 저장할 때만 채우면 화면과 저장 결과가 다르다.

편집 캐시까지 매 프레임 바꾸면 선택 leaf와 열린 초안이 다른 트리를 가리킬 수 있다. 구조 변경을 자동 병합하기에는 다른 트리의 leaf·pane ID 의미가 정의되지 않았다. 전체 프리셋 비교는 관련 없는 메타 수정까지 거절한다.

덮어쓰기 확인창은 별도 디자인과 갤러리 구현이 필요하다. 보기 모드에 새로고침 버튼만 두거나 Edit 클릭에서만 갱신하면 사용자가 계속 오래된 내용을 보게 된다.

## Reconsideration Triggers

저장소 revision·변경 알림이 생기면 레이아웃 복제·비교를 대체할지 검토한다. 충돌로 초안을 잃는 일이 잦거나 덮어쓰기 확인창 디자인이 마련되면 충돌 처리를 다시 정한다.

안정적인 pane ID가 생기면 mini-tab 보기 상태 유지도 검토한다. 같은 프리셋을 한 프레임에서 보기·편집 양쪽으로 그리는 기능은 현재 캐시 규칙과 충돌하므로 별도 결정을 해야 한다.

공용 Select가 키보드 선택을 지원하면 Kind autofocus를 검토한다. leaf 경계의 분할 영역이 없어지면 더블클릭 진입 범위도 다시 정한다. 이 두 UI 제약의 현재 동작은 프리셋 가이드에 둔다.
