# ADR-0043: CLI 오류 정보는 보존하고 진단 로그는 기록 주체를 나눈다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: cli, errors, logging, hooks
- **Group**: agents

## Context

CLI는 사람이 직접 실행하기도 하고 에이전트 훅이나 파이프에서 사용하기도 한다.
오류 메시지를 볼 사람이 없는 호출도 있으므로, 종료 상태와 진단 기록이 함께 필요하다.
특히 호스트에 연결하지 못한 실패를 다시 IPC로 보고할 수는 없다.

## Decision

에이전트 훅 전달 실패는 CLI가 접속하려던 인스턴스 홈의 로컬 파일에 기록한다.
Tasty 밖에서는 훅 명령을 실행하지 않으며, 설치된 래퍼는 전달 실패 때문에 에이전트 턴을
막지 않도록 성공으로 끝낸다. 실패 사실은 로그에 남긴다.

로그에서 실패를 분류할 때는 `method`, `event`, `surface`, JSON-RPC `code`를 사용한다.
`reason`은 사람이 읽을 설명이며 응답을 만든 쪽의 언어를 따른다.
CLI가 직접 만드는 연결·포트 오류 진단에는 영어 원문을 사용하지만 plugin 응답까지 영어로
강제하지 않는다. 사용자에게 보이는 stderr의 번역도 유지한다.

서버 없이 확인할 수 있는 요청 인자는 연결 전에 검사한다. 실패하면 그 인자 오류의
종료 코드를 유지한다. 서버가 있어야 확인할 수 있는 계약은 연결 뒤에 검사한다.
IPC 메서드는 CLI로 호출할 수 있게 하며, 불가능하거나 선행 작업이 필요하면 이유를 기록한다.
주로 플러그인이 쓴다는 관행만으로 CLI를 생략하지 않는다.

호스트 오류는 기존 첫 줄을 유지하고 값이 있는 `error.data`만 둘째 줄의 compact JSON으로
전달한다. stdout BrokenPipe는 CLI 경계에서 조용히 성공 종료하며 정상 Drop 정리는 수행한다.
stderr 쓰기 실패는 이미 정해진 명령의 종료 코드를 바꾸지 않는다. 실제 panic은 계속 보고한다.

공유 tracing 파일은 GUI·headless 호스트만 연다. CLI는 stderr로 기록해 잦은 명령 실행이
호스트 로그를 지우지 않게 한다. panic hook과 stderr 초기화는 프로그램 시작에 유지한다.

`new workspace --surface <ID>`는 대상 윈도우와 cwd 상속 원본을 함께 지정한다.
명시한 cwd가 우선하며 서피스를 생략한 기존 호출의 기본 동작은 유지한다.
이 명령에서는 생략한 서피스를 `TASTY_SURFACE_ID`로 채우지 않는다.

## Consequences

IPC 연결이 끊겨도 훅 실패를 조사할 수 있다. 기록 자체가 실패할 가능성은 남는다.
래퍼의 종료 코드만으로는 전달 성공을 알 수 없으므로 로그와 실제 상태를 확인해야 한다.
설명 문구를 파싱하던 외부 소비자는 구조화된 필드를 사용하도록 바꿔야 할 수 있다.
stdout의 조기 닫힘은 종료 코드로 구분하지 못하며, stderr를 닫으면 오류 설명도 받지 못한다.
호스트 재시작은 공유 로그를 비운다. 지정한 서피스의 cwd를 상속하는 호출은 같은 윈도우의
포커스 서피스에서 cwd를 가져오던 과거 호출과 결과가 달라질 수 있다.

## Alternatives Considered

- 훅 실패를 IPC로 다시 보고하면 연결 실패를 기록할 수 없다.
- 셸 리다이렉션만 사용하면 로그 디렉터리를 열지 못했을 때 훅 명령도 실행되지 않을 수 있다.
- 모든 오류 설명을 영어로 강제하면 같은 응답을 읽는 사용자의 번역된 안내를 잃는다.
- 훅의 비정상 종료를 그대로 외부 에이전트에 전달하려면 그 도구가 턴을 중단하는지 먼저 확인해야 한다.

- 연결 후 인자를 검사하면 서버가 없을 때 실제 입력 오류를 볼 수 없다.
- 첫 오류 줄에 JSON을 붙이거나 전체 형식을 바꾸면 기존 파서를 깨뜨릴 수 있다.
- SIGPIPE 기본 동작 복원은 Windows에 적용되지 않고 호스트까지 적용되면 자식 stdin 쓰기에서
  호스트가 종료될 수 있다. 출력 함수 안에서 즉시 process::exit하면 Drop 정리도 생략된다.
- stderr 실패를 성공으로 바꾸면 원래 실패한 명령을 성공처럼 보고하게 된다.
- 모든 프로세스가 공유 파일에 append해도 CLI와 호스트 로그가 섞인다.
  tracing 초기화를 늦추면 라우팅 중 실행되는 동적 CLI의 초기 로그를 놓친다.
- 윈도우 지정용 새 인자나 별도 cwd 원본 키는 기존 라우팅을 넓혀야 한다.
  현재는 서피스 ID를 쓰고 필요하면 cwd를 직접 지정한다.

## Reconsideration Triggers

- 외부 소비자가 오류 코드만으로 실패를 구분할 수 없거나 설명 파싱에 의존하는 사례가 확인될 때.
- 훅의 비정상 종료를 노출해도 턴 진행에 문제가 없다는 근거가 생길 때.
- 실패 기록 대상이나 오류 설명을 만드는 프로세스가 늘어날 때.

- IPC가 인자 스키마를 갖거나 CLI 접근성 검사의 문자열 추출이 실제 호출과 어긋날 때.
- 공통 출력 모드·종료 코드 정책, CLI 파일 로그, 다중 호스트 로그 보존 요구가 생길 때.
- 윈도우 ID 라우팅이나 윈도우 간 상태 조회 구조가 바뀔 때.
