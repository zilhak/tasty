# ADR-0114: 언어팩은 `~/.tasty/lang/<code>/pack.toml` 디렉토리이고 `[font]` 가 필수다 — 단일 `<code>.toml` 은 내장 오버라이드 전용, 팩 부재·형상 위반은 경고 토스트 + 영어 폴백(설정값 보존)

- **Status**: Accepted
- **Date**: 2026-09-03
- **Tags**: i18n, language-pack, settings, font, boot, toast, discovery

## Context

번역 테이블은 내장 `en`/`ko`/`ja` 위에 `~/.tasty/lang/<code>.toml` 을 overlay 했다. 설정 창의 언어 콤보는 내장 3 개를 하드코딩했고 표시 이름도 코드 안의 `match` 였다. 사용자가 새 언어 파일을 놓아도 콤보에 나타나지 않았고, `general.language` 에 손으로 그 코드를 적으면 파일이 없어도 아무 알림 없이 영어 베이스만 뜨거나(키 폴백) 파일이 있으면 문자열은 뜨되 글리프가 없는 스크립트는 □ 로 깨졌다. 즉 "언어팩" 이라는 단위가 없었다.

제약이 셋 있다.

1. 새 언어는 문자열만으로 성립하지 않는다 — 폰트 스택이 그 스크립트를 덮지 않으면 사용자는 번역이 됐는데 깨진 화면을 본다. 폰트를 실제로 resolve 하는 단계는 아직 없지만, 그 단계가 소비할 **선언의 형상**은 지금 정해야 팩 작성자가 두 번 고치지 않는다.
2. 활성 언어는 부팅 시 확정되어 자식 프로세스 env(`TASTY_LOCALE`, [ADR-0103](0103-plugin-locale-via-host-process-env.md))로 나간다. 설정값과 실제 적용 언어가 갈릴 수 있으면 어느 쪽을 env 에 싣는지 정해야 한다.
3. 설정값을 자동으로 고쳐 쓰면(팩이 없다고 `en` 으로 저장) 사용자가 팩을 넣은 뒤 재시작해도 원래 언어로 돌아오지 않는다 — 설정 창 콤보도 같은 문제를 갖는다(목록에 없는 값을 첫 항목으로 바꿔 그리면 Save 한 번에 값이 사라진다).

## Decision

**디렉토리 + `pack.toml` 이 언어팩이다.** `~/.tasty/lang/<code>/pack.toml` 은 `[meta] name`(선택, 콤보 표시 이름 — 없으면 코드) · **`[font]`(필수 — `builtin = true` / `file` / `family` / `candidates` 중 하나, 그 우선순위)** · 나머지 문자열 키를 갖는다. `[font]` 가 없거나 넷 다 없으면 **형상 위반**으로 팩 전체를 거부한다 — 문자열만 있는 팩은 "반쯤 동작" 이 아니라 불완전한 팩이다. 단일 `~/.tasty/lang/<code>.toml` 은 **내장 코드의 오버라이드 전용**으로 좁힌다(`[font]` 불필요 — 내장 폰트 스택이 이미 덮는 스크립트). 내장이 아닌 코드의 단일 파일은 팩으로 인정하지 않고 경고 후 무시한다.

**발견은 `tasty-i18n` 이 한다** — `available_languages()` = 내장 3 + `~/.tasty/lang/` 의 유효한 팩. 로더와 같은 규칙이므로 목록에 있는 것은 반드시 로드된다. 설정 콤보는 이 목록만 그린다(하드코딩 제거).

**팩의 빈 값은 번역 없음이다.** 값이 비었거나 공백뿐인 키는 overlay 에서 빼 영어 베이스가 보이게 한다. 저작자가 실수로 키를 비워 두는 것은 흔한 반면 의도적으로 빈 텍스트를 원하는 경우는 드물고, 빈 값이 그대로 나가면 라벨 없는 버튼이 생겨 **화면만 봐서는 어느 키가 비었는지 추적할 수 없다.** 의도적으로 비우려면 trim 이 먹지 않는 폭 없는 문자(U+200B)를 쓸 수 있어 표현력 손실도 없다(`str::trim` 이 유니코드 `White_Space` 를 전부 먹으므로 NBSP 류 공백은 해당하지 않는다). `[meta] name`·`[font]` 문자열이 이미 같은 규칙(공백 거부)을 쓰므로 팩 안에서 규칙이 하나다.

**팩 부재·형상 위반은 영어 폴백 + 경고, 설정값 보존.** `init` 이 `LoadReport { requested, effective, outcome }` 를 돌려주고, 폴백 시 테이블·`current_language()`·`TASTY_LOCALE` 은 모두 실제 적용 언어 `en` 을 싣는다(plugin 이 존재하지 않는 코드로 자기 파일을 찾지 않도록). 알림은 로드 시점 `tracing::warn!` 한 줄(요청 코드 + 기대 경로 — headless/CLI 의 전부)과 GUI 부팅 후 경고 토스트 1회(웹훅 bind 실패 경고와 같은 구조). 토스트에는 본문 200자 캡이 있어 넘기면 호스트가 뒤를 자르고 제한 접미를 붙인다 — **잘리는 자리가 하필 경로**라 안내가 통째로 사라진다. 그래서 캡을 넘길 때는 경로만 가운데를 생략해(`…`) 맞춘다: 머리(어느 루트)와 꼬리(`<code>/pack.toml`)를 남겨 *어느 팩인지* 는 지킨다. 로그의 경로는 온전하다. 설정값은 어느 경로에서도 고쳐 쓰지 않으며, 콤보는 목록에 없는 현재 값을 `"<code> (not found)"` 행으로 끝에 붙여 선택 상태로 유지하고 그 행 재선택도 값을 바꾸지 않는다.

## Consequences

- **얻은 것**: 언어를 추가하는 단위(디렉토리)가 생겨 폰트·부속 파일을 같이 둘 자리가 있다. 콤보와 로더가 같은 스캐너를 쓰므로 "보이는데 안 뜸" 이 없다. 팩 작성자는 `[font]` 부재를 부팅 직후 경고로 안다. 사용자가 팩을 잠시 치웠다가 되돌려도 설정이 살아 있다. 폰트 resolve 단계는 `FontDecl` 만 소비하면 된다.
- **잃은 것**: 기존에 `~/.tasty/lang/xx.toml` 처럼 단일 파일로 새 코드를 쓰던 사용자는 `xx/pack.toml` 로 옮기고 `[font]` 를 적어야 한다(경고 메시지가 경로를 안내한다). 폴백 상태에서는 설정과 화면 언어가 다르다 — 토스트가 그 차이를 알린다.
- **잃은 것 (추가)**: 팩이 어떤 문구를 의도적으로 빈 문자열로 두는 것은 이제 불가능하다(폭 없는 문자로 우회). 폴백 토스트의 경로는 데이터 루트가 길면 가운데가 생략되어 보인다 — 전체 경로는 로그에서 본다.
- **운영 비용 / 유지 부담**: 내장 `lang/*.toml` 에 `[meta] name` 이 생겨 세 파일이 하나의 비-문자열 키를 갖는다(`flatten` 은 문자열 leaf 만 모으므로 `meta.name` 도 조회 가능 — 문제 없음). `init` 의 반환 타입이 바뀌어 호출처(`src/boot/locale.rs`)가 report 를 소비한다.

## Alternatives Considered

- **A. 단일 `<code>.toml` 을 새 코드에도 그대로 허용** — 폰트를 둘 자리가 없고 `[font]` 필수 규칙을 단일 파일에 얹으면 내장 오버라이드(폰트 불필요)와 같은 파일 형식이 두 의미를 갖는다. 디렉토리로 갈라 의미를 하나씩 준다.
- **G. 팩의 빈 값을 그대로 반영** — 저작자 의도를 최대한 존중하지만, 실수와 의도를 구분할 수 없고 결과가 "UI 가 깨진 것처럼 보이는데 원인을 화면에서 못 찾는" 상태다. 실수 빈도가 의도 빈도보다 훨씬 높다.
- **H. 토스트 문구만 짧게 쓰고 경로는 손대지 않음** — 문구를 줄여도 데이터 루트 길이는 통제할 수 없어 언젠가 다시 잘린다(번역 문구가 길어지면 더 빨리). 예산을 계산해 경로를 줄이는 쪽이 길이에 무관하게 성립한다.
- **B. `[font]` 를 선택으로 두고 없으면 내장 폰트 가정** — "문자열만 있는 팩" 이 조용히 □ 를 만든다. 팩 작성자가 명시적으로 `builtin = true` 를 적게 해 판단의 흔적을 남기는 쪽이 낫다.
- **C. 팩 부재 시 설정값을 `en` 으로 고쳐 저장** — 사용자가 팩을 넣고 재시작해도 영어로 남는다. 설정 창에서 다시 골라야 하는데, 팩을 넣기 전에는 콤보에 그 코드가 없으므로 순서 의존이 생긴다.
- **D. 팩 부재 시 조용히 영어(알림 없음)** — 기존 동작. 오타·경로 실수를 사용자가 알 방법이 없다.
- **E. 콤보가 목록에 없는 값을 첫 항목으로 그림** — egui `ComboBox` 의 자연스러운 동작이지만 Save 한 번에 값이 `en` 으로 바뀐다(C 와 같은 결과를 UI 가 만든다).
- **F. 폴백 시 `TASTY_LOCALE` 에 요청 코드를 그대로 실음** — plugin 이 존재하지 않는 코드의 파일을 찾다 자기 `en` 으로 폴백하므로 결과는 같지만, host 와 plugin 이 서로 다른 "활성 언어" 를 말하게 된다. 한 값으로 맞춘다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- 폰트 resolve 단계가 `[font]` 네 형태 외의 선언(예: 가중치별 파일, 폴백 체인의 OS 분기)을 요구할 때 — 형상 확장은 이 ADR 의 "구현 확정 보강" 으로 흡수하되, 필수 여부를 뒤집는 것은 새 ADR.
- 팩 설치/배포 도구가 생겨 팩에 버전·서명 메타가 필요해질 때 — `[meta]` 확장.
- 재시작 없는 언어 전환이 요구될 때 — `LoadReport` 가 부팅 1회 값이라는 전제가 깨진다.
- plugin 이 자기 언어팩(디렉토리)을 갖게 될 때 — 발견 규칙을 plugin `lang/` 에도 적용할지 결정.
- 토스트의 본문 캡이 바뀌거나 토스트가 다중 행/펼침을 지원할 때 — 경로 생략 규칙의 전제가 사라진다.
