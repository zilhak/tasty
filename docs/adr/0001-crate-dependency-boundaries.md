# ADR-0001: 크레이트는 의존 관계와 실행 환경에 따라 나눈다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: architecture, crates, headless
- **Group**: foundation

## Context

호스트에 있던 작은 공용 모듈을 다른 크레이트로 옮기면 빌드 범위를 줄이고 재사용할 수 있다.
그러나 파일 크기만 보고 합치거나 나누면 SSH에 IPC가 딸려오거나,
헤드리스의 문자열 계산에 GUI 라이브러리가 따라오는 문제가 생긴다.

경계를 정할 때는 실제 소비자, 전이 의존성, 실행에 필요한 자원을 함께 본다.

## Decision

크레이트 분리의 첫 기준은 의존 방향이다. 줄 수는 빌드 개선 후보를 찾는 참고값이다.
작은 코드라도 둘 이상의 소비자가 있고 기존 크레이트에 넣을 때 불필요한 의존이 생기면 분리한다.
`tasty-remote`는 SSH와 IPC를 함께 사용하되 `tasty-ssh` 자체는 IPC를 모르게 한다.

계산과 부수효과를 나눈다. 선택·문자 폭·링크 검출은 공용 크레이트에서 계산하고,
브라우저 열기와 앱 이벤트 해석은 호스트에 남긴다. 선택 폭은 두 빌드에서 같은 Unicode 표를 쓴다.
`tasty-platform`은 OS 호출을 담당하고 앱 동작은 호출자가 제공한 callback으로 연결한다.
`StreamHub`는 공용 전송 계약인 `tasty-ipc`에, 실제 소켓 처리는 adapter에 둔다.

GUI 의존은 필요한 소비자가 명시적으로 켠다. 공용 appearance 타입의 기본 feature는 비워 두고,
폰트의 GPU atlas는 `gpu` feature로 분리한다. 헤드리스 폰트 이름 해석에 필요한 cosmic-text는 유지한다.
셀 렌더러는 공용 타입을 원래 크레이트 이름으로 참조한다.

레지스트리의 plugin port 구현은 타입 소유 크레이트에 둔다.
trait을 소유한 protocol 쪽에도 구현할 수는 있지만, 그러면 protocol이 도메인 구현을 의존하게 된다.
이 방향을 피하려고 file-format·file-handler의 protocol 의존을 명시적 계층 예외로 둔다.
번들 기본값은 크레이트 상수로 한 번 포함한다.

루트는 lib와 얇은 bin으로 나누되 도메인 내부를 외부 API로 일괄 공개하지 않는다.
셀 렌더링에서 반복 실행되는 세 계산 크레이트는 실행·재컴파일 비용을 비교한 결과에 따라
개별 dev 최적화를 적용한다. 새 크레이트까지 일괄 최적화하는 규칙은 아니다.

## Consequences

의존 방향과 GUI 요구 사항을 manifest에서 확인할 수 있다.
플랫폼 크레이트는 본체 타입을 직접 참조할 수 없고, 공용 계산은 GUI 없이 검사할 수 있다.

크레이트와 feature가 늘어 관리 비용도 생긴다. 공개 API와 재수출을 점검해야 하며,
루트 단위 테스트가 lib에 있다는 점을 고려해 테스트 타깃을 선택해야 한다.
컴파일 성공만으로 전이 의존성에서 GUI가 빠졌다고 판단하지 않는다.

## Alternatives Considered

- 크기가 작은 코드를 무조건 이웃 크레이트에 합치면 의존 방향을 훼손할 수 있다.
- 소비자마다 GUI 기본 feature를 끄게 하면 새 소비자가 빠뜨리기 쉽다.
- port 구현 하나만을 위한 adapter 크레이트는 고아 규칙과 의존 관계를 함께 해결해야 하며 관리 비용이 크다.
- 폰트 해석까지 제거하면 헤드리스 동작이 달라지므로 GPU 의존 제거와 함께 처리하지 않는다.

## Reconsideration Triggers

소비자가 하나로 줄거나 링크·메타데이터 비용이 분리 이득을 넘으면 경계를 다시 검토한다.
도메인-IO의 예외가 넷째로 늘거나 기존 이유로 설명되지 않는 예외가 생기면 trait 배치도 검토한다.

공용 크레이트에 GUI·OS 부수효과가 추가되면 `cargo tree`로 전이 의존성을 확인한다.
플랫폼 callback 수정은 해당 OS의 컴파일과 실제 메뉴·절전 복귀 동작을 각각 확인한다.
렌더 계산의 호출 빈도나 캐시 구조가 바뀌면 dev 최적화의 실행·편집 비용을 다시 측정한다.
