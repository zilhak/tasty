# ADR-0045: 테스트는 사용자 환경과 분리하고 E2E 인스턴스를 공유한다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: testing, isolation, e2e
- **Group**: rules

## Context

사용자 설정을 읽거나 전역 환경변수를 바꾸는 테스트는 실행 순서와 개발 환경에 따라 결과가 달라진다.
E2E 테스트마다 GUI 프로세스를 만들면 창이 포커스를 가져가고 GPU 초기화 비용도 반복된다.
그렇다고 모든 테스트를 한 프로세스로 묶으면 서로 다른 테스트가 같은 workspace를 점유할 수 있다.

## Decision

유닛 테스트에는 설정과 경로를 명시적으로 주입한다.
사용자 설정을 읽는 제품 진입점과 기본 설정을 쓰는 테스트 진입점은 구분한다.
파일 읽기 자체를 검증하는 테스트도 자신이 만든 임시 디렉터리를 사용한다.

E2E 테스트는 테스트 바이너리마다 Tasty 인스턴스 하나를 공유하고,
각 테스트가 workspace를 만들어 사용한다. 프로세스의 시작 설정이나 자원 사용량 자체가
검증 대상일 때만 별도 인스턴스를 만든다. 이런 예외에는 사유와 검사 대상 등록이 필요하다.

하네스의 실행 파일 선택은 `spawn_diag::instance_bin()`으로 모은다.
GUI 필요 여부는 테스트마다 판단한다. GUI 기능 하나 때문에 같은 파일의 모든 테스트를
건너뛰지 않는다. 실행 절차와 환경변수는 [E2E 가이드](../dev-guide/e2e-tests.md)에 둔다.

외부 headless 바이너리 사용은 선택 사항이다. 테스트 코드뿐 아니라 데몬의 호출 경로가
빌드 조합마다 달라지는 스위트도 `SameCombo`로 분류한다. 분류되지 않은 스위트는
자기 조합을 유지한다. 실행 속도 이득보다 별도 빌드 비용이 클 수 있어 기본으로 켜지 않는다.

전역 상태가 테스트에서만 바뀌면 모듈의 공용 락을 사용할 수 있다. 제품 코드도 읽는
환경변수를 바꾸는 경우에는 락 밖의 읽기를 막을 수 없으므로 경로 인자 주입을 우선한다.
이미 경로를 인자로 받는 함수가 있으면 테스트도 그 함수를 사용한다. 환경변수 해석 자체가
검증 대상인 경우만 환경변수 변경을 남기고, 그 테스트의 격리 범위를 따로 확인한다.

Linux GUI 하네스는 `TASTY_E2E_DISPLAY`로 디스플레이를 명시하도록 한다.
이름을 주면 `DISPLAY`로 전달하고 Wayland 선택 변수를 지운다. `inherit`은 상속을
명시하는 값이다. 디스플레이를 모두 지우면 GUI가 부팅할 수 없고, 하네스가 Xvfb를
직접 관리하면 플랫폼별 프로세스 수명 관리가 추가되므로 실행자가 준비한다.

## Consequences

테스트가 사용자 홈을 오염시키는 일을 줄이고, 프로세스 기동과 GPU 초기화 비용을 나눌 수 있다.
공유 인스턴스의 전역 목록에는 다른 테스트 항목이 섞일 수 있다.
따라서 목록 길이나 첫 항목 대신 자신이 만든 ID를 확인해야 한다.

스레드 로컬 홈 경로는 자식 스레드에 상속되지 않는다.
테스트 통과만으로 격리를 증명할 수 없으므로 빈 임시 홈의 잔여 파일도 확인한다.
환경변수를 직접 바꿔야 하는 테스트에는 같은 프로세스의 읽기·쓰기를 막는 공용 락과
패닉 때도 원래 값을 복원하는 RAII 가드가 필요하다.

## Alternatives Considered

- 테스트마다 새 프로세스를 만드는 방법은 단순하지만 GUI와 기동 비용이 크다.
- 저장소 전체가 프로세스 하나를 공유하면 테스트 바이너리 사이에 실행 순서 의존성이 생긴다.
- 실행 스크립트에서만 홈을 바꾸면 `cargo test`를 직접 실행할 때 격리가 빠진다.
- 제품의 설정 로드 함수를 테스트에서 무조건 기본값으로 바꾸면 실제 파일 로드 검증까지 사라진다.

## Reconsideration Triggers

공유 인스턴스의 간섭이 반복되면 workspace 격리로 충분한지 다시 판단한다.
홈 경로를 읽는 자식 스레드가 생기면 경로를 전달하는 범위를 스레드 경계까지 넓힌다.
GUI 빌드의 실행 시점 headless 선택이 가능해지면 별도 바이너리를 만드는 비용을 다시 검토한다.
