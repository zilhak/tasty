# ADR-0025: 플러그인 샌드박스와 마켓플레이스는 보류한다

- **Status**: Deferred
- **Date**: 2026-09-24
- **Tags**: plugins, runtime
- **Group**: plugins

## Context

플러그인은 별도 OS 프로세스로 실행되지만 사용자 계정의 파일과 네트워크에 직접 접근할 수 있다.
매니페스트 권한은 호스트 API 호출을 제한하며 OS 접근 전체를 차단하지 않는다.
외부 플러그인을 쉽게 배포하려면 설치 편의와 함께 이 신뢰 범위를 설명하고 실제 격리를 제공해야 한다.

현재는 로컬 설치와 앱에 동봉하는 번들이 중심이다.
이 상태에서 배포 목록만 먼저 공개하면 사용자가 설치를 승인할 때 기대하는 보호와 실제 동작이 달라질 수 있다.

## Decision

OS 샌드박스와 공개 마켓플레이스 도입을 보류한다. WASM 실험은 가능성을 검토한 단계이며 지원 제품으로 보지 않는다.
외부 플러그인은 로컬 경로로 설치하고, 호스트 API 권한과 사용자 승인은 현재 방식으로 적용한다.

샌드박스를 추진할 때는 기존 프로세스 모델에 선택적으로 적용하는 방식을 먼저 비교한다.
WASM은 선형 메모리, 공유 버퍼, 디버깅, 파일 경로와 동적 권한을 함께 설계해야 한다.
어느 방식을 쓰든 매니페스트의 권한 선언만으로 OS 격리가 구현됐다고 설명하지 않는다.

마켓플레이스를 도입하려면 현재 설치의 자동 권한 부여를 폐지하고,
설치할 때마다 사용자에게 권한 승인을 받아야 한다.
마켓플레이스에서 받은 플러그인에는 OS 수준 샌드박스를 강제한다.
세 조건을 함께 충족하기 전에는 마켓플레이스를 제공하지 않는다.
구체적인 격리 구현과 발급자 신뢰 정책은 도입할 때 정한다.
번들 매니페스트 서명은 현재 지원하지만 외부 생태계 전체의 발급자 신뢰 체계를 대신하지 않는다.
서명 키 선택과 보호 범위는 패키징 가이드에 둔다.

## Consequences

기존 플러그인을 현재 실행 모델로 유지할 수 있고 플랫폼별 격리 비용을 미리 떠안지 않는다.
그 대가로 설치한 플러그인의 직접 OS 접근을 호스트가 통제하지 못한다.

번들 서명은 매니페스트 변조 확인에 쓰인다. 플러그인 바이너리와 부속 파일 전체가 같은 서명으로 보호되는 것은 아니다.
마켓플레이스나 WASM을 사용 가능한 기능으로 안내해서는 안 된다.

## Alternatives Considered

- 마켓플레이스부터 공개하면 설치 규모만 늘고 실제 격리는 그대로다.
- 모든 플러그인을 WASM으로 바꾸면 기존 native 기능과 공유 메모리 경로를 함께 이전해야 한다.
- 호스트 권한을 OS 샌드박스라고 부르면 현재 제공하지 않는 보호를 약속하게 된다.

## Reconsideration Triggers

외부 플러그인 배포 요청, 실제 권한 오해 사고, OS 격리가 필요한 소비자가 생기면 이 결정을 다시 검토한다.
그때 설치 과정과 파일·네트워크 접근을 각 플랫폼에서 확인하고 WASM 실험 결과와 비교한다.
앱과 독립적인 플러그인 업데이트를 제공하려면 서명 키와 장기 신뢰 정책도 함께 정한다.
