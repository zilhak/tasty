# ADR-0627: 자동화는 호스트 메인 스레드를 기다리게 하지 않는다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: plugins, runtime
- **Group**: plugins

## Context

Lua와 훅은 이벤트를 받아 호스트 기능을 호출한다.
그 호출 결과를 호스트 명령 큐를 처리하는 스레드에서 기다리면 자신이 처리해야 할 명령을 기다리게 된다.
사용자 화면이 멈추고 실제로는 나중에 실행된 요청을 실패로 기록할 수도 있다.

실행 위치뿐 아니라 누가 흐름을 정하는지도 분명해야 한다.
외부 payload가 메서드나 셸 명령을 선택하는 구조와 사용자가 고정한 동작에 값을 전달하는 구조는 다르다.

## Decision

Lua VM은 전용 워커가 소유한다. 호스트 상태는 읽기 스냅샷과 명시 API로 접근하고 변경 요청은 메인 큐로 보낸다.
스크립트는 등록 후 단축키나 명시한 이벤트로 실행한다. init.lua 자동 로드와 임의 reload 방식은 제공하지 않는다.
VM 명령 실행에는 기한과 메모리 제한을 적용하되 OS 파일·프로세스 접근을 격리하는 샌드박스로 설명하지 않는다.
Lua 이벤트 콜백의 반환값은 원래 동작을 취소하거나 바꾸지 않는다. 명시 API 호출은 별도다.

내부 hook과 webhook은 공유 핸들러 레지스트리를 쓴다.
source와 action을 등록할 때 검사하며 webhook에는 IpcSequence만, ShellCommand에는 내부 Hook source만 허용한다.
호스트·플러그인 기여보다 사용자 patch를 나중에 적용해 부팅·재시작 순서와 무관하게 사용자 설정을 유지한다.

surface hook과 수동 hook_handler.dispatch의 IpcSequence는 공유 워커 하나에서 접수 순서대로 실행한다.
각 step은 응답 또는 대기 종료 뒤 다음 step으로 넘어가고 실패해도 다음 step을 진행한다.
대기열이 차거나 워커를 만들지 못하면 실행하지 않는다. 메인 스레드에서 대신 실행하지 않는다.
수동 요청에는 접수 실패를 오류로 답하고 회신 대상이 없는 hook에는 로그를 남긴다.
webhook은 별도 요청 스레드에서 실행하므로 이 공유 순서에 포함되지 않는다.

핸들러 get/upsert/remove는 Local 전용이며 ID를 유지해 필요한 필드만 고친다.
저장 실패를 성공으로 보고하지 않는다. 이미 등록된 webhook은 등록 시점의 시퀀스를 보존하므로 갱신하려면 다시 등록한다.
한 사건에서 한 번만 실행하는 hook은 첫 매칭 때 소비하고 지속 hook은 맞는 사건마다 실행한다.

## Consequences

호스트는 자동화의 응답을 기다리느라 멈추지 않는다.
공유 워커에서는 서로 다른 hook 시퀀스의 step이 섞이지 않지만 느린 시퀀스가 뒤 작업을 지연시킨다.
대기열 포화로 실행하지 못한 사건은 자동으로 재전송하지 않는다.

접수 응답과 HookFired는 실제 step 완료를 보장하지 않는다.
step의 대기 종료 뒤에도 호스트에 들어간 요청이 실행될 수 있으며 부분 적용도 가능하다.
Lua 기한은 VM 명령 훅에서 확인한다. 이미 들어간 외부 OS 호출을 강제로 취소하는 기능은 아니다.
GUI 시퀀스 본문 편집기는 아직 제공하지 않는다.

## Alternatives Considered

- 메인 스레드에서 직접 기다리면 명령 큐 처리와 대기가 서로 막힌다.
- 시퀀스마다 스레드를 만들면 step이 다른 시퀀스와 섞이고 폭주 시 스레드가 늘어난다.
- 무제한 큐는 처리 지연을 메모리 적체로 바꾼다.
- handler를 지우고 다시 만들면 ID를 참조하는 기존 hook이 끊길 수 있다.
- 모든 hook 실패를 전파하면 실패 뒤에도 필요한 로컬 정리를 건너뛸 수 있다.

## Reconsideration Triggers

공유 워커 지연이나 포화 로그가 반복되면 요청 출처와 시퀀스 길이를 측정해 병렬화와 순서를 다시 비교한다.
새 trigger나 action을 추가할 때는 source 검사와 외부 값의 적용 범위를 확인한다.
Lua를 불신 코드 실행에 쓰거나 plugin 쪽 scripting을 제공하려면 OS 격리와 API 경계를 새로 결정한다.
