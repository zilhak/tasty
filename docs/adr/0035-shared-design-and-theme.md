# ADR-0035: 디자인 값과 아이콘은 공용 정의에서 가져온다

- **Status**: Accepted
- **Date**: 2026-09-24
- **Tags**: design, theme, gallery
- **Group**: ui

## Context

같은 색과 아이콘을 화면마다 따로 정의하면 디자인을 바꿀 때 일부 화면만 이전 상태로 남는다. 값이 같더라도 글자·테두리·선택 배경은 서로 다른 역할이다.

## Decision

### 색과 토큰의 역할

UI와 공용 위젯은 색의 역할을 나타내는 Theme 접근자를 사용한다. 원시 팔레트 필드 사용은 테마 구현·색상 픽커·터미널 ANSI 처리·팔레트 전시처럼 원시 색 자체를 다루는 곳에 한정한다.

latte의 상태바 캡션과 비활성 탭 제목은 현재 팔레트에서 최소 대비 4.5:1에 미달하는 예외로 기록한다. 문서 정리나 토큰 치환 작업에서 팔레트·화면 색을 임의로 바꾸지 않는다. 새 화면은 테마 가이드의 대비 표에 따라 배경과 전경을 고른다.

토큰에 없는 값을 가장 가까운 토큰으로 바꾸는 것은 리팩터링에 포함하지 않는다. 역할에 맞는 토큰이 없으면 이유가 드러나는 이름을 붙이고 디자인 결정으로 해결한다. 같은 값이라는 이유만으로 다른 역할의 토큰을 사용하지 않는다. 값 비교는 구조 길이·폰트·반경·아이콘 등 해당 용도의 스케일 안에서 한다.

토큰 치환은 기본 배율의 숫자뿐 아니라 지원 배율에서의 결과도 확인한다. 하나의 UI에서 컨테이너 크기와 내부 위젯의 배율 적용이 달라 잘리는 것은 결함이다. 기본 배율을 보존하는 방법을 먼저 찾고, 둘 다 가능하면 함께 확대되는 방법을 택한다. 고정 크기가 필요하면 내부 내용도 같은 원칙을 따르고 이유를 적는다.

역할이 확정된 색과 치수는 임시 alias나 숫자 상수를 유지하지 않고 정해진 접근자를 사용한다. disabled 글자, 약하게 표시하는 chrome 글리프, 프레임 선, 내부 구분선, 장식 accent는 서로 다른 역할이다. 수치가 같아도 같은 토큰으로 합치지 않는다.

확정된 tint 채움·테두리 조합과 점 크기 종류도 공용 정의를 따른다. 이전 디자인 조정에서 승인된 폰트 반올림은 그 대상에 적용한 결정이며, 이후의 모든 임의 값을 자동으로 가까운 토큰에 맞추라는 규칙이 아니다.

### 공용 아이콘

아이콘의 SVG는 tasty-icons에서 한 번 정의한다. 본체와 갤러리는 런타임 SVG 이미지를 만들고, 플러그인은 같은 SVG를 빌드할 때 선분 데이터로 바꿔 그릴 수 있다.

### 갤러리와 렌더링 공유

갤러리에 본체 구현의 복사본을 만들기 전에 공용 타입·함수를 직접 사용할 수 있는지 확인한다. 타입의 소속 크레이트가 바뀌면 복제가 필요했던 이유도 다시 확인한다. 직접 공유할 수 없을 때만 복사본과 비교 검사를 유지한다.

토스트는 그리기뿐 아니라 줄바꿈·카드 크기·색 계산까지 `tasty-ui-widgets`에서 공유한다. alpha는 호스트의 기존 순서대로 straight-alpha 테마 색에 적용한 뒤 Color32로 바꾼다. 갤러리가 별도 감마 공간 계산으로 페이드 색을 만들지 않는다.

터미널 셀 강조색의 alpha는 CPU에서 해당 셀 배경 위에 source-over 합성한다. 셀당 배경 quad 하나와 GPU REPLACE 방식을 유지하고, 선택→vi 커서→링크→검색 순서로 합성한다.

### 디자인 반영 순서

새 디자인은 Claude Design 시안을 받은 뒤 갤러리→본체→사이트 사본 순서로 반영한다. 네 단계가 반영되어야 완료로 본다. 본체의 모든 modal·popup·공용 위젯·반복 레이아웃을 갤러리에 유지하며, 디자인 카탈로그에서 빠졌다는 이유로 삭제하지 않는다.

디자인 도구는 세션의 DesignSync 연결로 접근하고 실제 디자인 생성 지시는 사용자가 한다. 브라우저 자동화 플러그인을 제품 본체에 포함하지 않는다. 확정 시안은 원격 파일에 남기며 저장소 근거가 필요한 HTML은 docs/design에 보관한다.

UI가 소비하는 값은 Theme 접근자를 기준으로 한다. 원격 디자인에서 받은 토큰·아이콘과 사이트 사본을 맞추는 절차도 유지한다. 소스 검사의 통과는 원격 시안 전체가 최신이라는 보장이 아니다.

생성된 길이 상수는 해당 토큰 자신의 Theme 필드나 접근자를 통해 사용한다. 같은 값을 가진 다른 토큰으로 우회하지 않는다. 경로가 없는 토큰은 이유와 함께 명부로 관리하고 실제 소비가 생길 때 해당 경로와 정합 검사를 만든다.

## Consequences

화면별 복제 정의가 줄고 디자인 변경의 적용 범위를 확인할 수 있다. 원시 필드 접근은 clippy만으로 막을 수 없어 소스 검사도 필요하다.

토큰 밖 상수를 남기는 동안에는 해당 값이 배율에 따라 커지지 않을 수 있다. 이름을 붙였다고 디자인 차이가 해결되는 것은 아니다. 역할이 확정되면 해당 토큰을 적용하고 임시 예외를 제거한다.

공용 함수가 같아도 입력 rect·테마·배율이 다르면 픽셀은 다르다. 같은 조건의 갤러리와 앱 캡처 비교가 필요하다. 토스트 본문 글자는 현재 카드 chrome과 함께 페이드하지 않으며, 디자인 변경 없이 이 동작을 임의로 바꾸지 않는다.

디자인 카탈로그의 누락은 보강 요청으로 해결한다. 사이트 토큰 이름과 아이콘 검사는 문구·구성·컨트롤 삭제를 검사하지 못하므로 원격 파일 비교도 필요하다. 원격 접근이 불가능하면 사이트 반영을 완료로 보고하지 않는다.

가드의 안내는 semantic 매핑 표와 component 접근자에서 경로를 찾는다. 생성 주석 형식이나 경로 없는 토큰 목록이 바뀌면 이 검사도 갱신해야 한다. 검사 루트 밖의 직접 소비까지 자동으로 탐지하지는 못한다.

## Alternatives Considered

공용 위젯에서 원시 색을 허용하면 본체와 위젯이 서로 다른 규칙을 갖게 된다. 플러그인마다 SVG를 복사하면 아이콘이 달라질 수 있고, 매번 래스터 이미지를 전송하면 크기 변경과 텍스처 전송 비용이 생긴다.

latte의 muted 색만 더 어둡게 하면 secondary와 구분이 줄거나 밝기 순서가 뒤집힌다. secondary로 바꿔도 surface0 배경은 기준에 못 미친다. 배경 전체를 밝히는 방법은 팔레트 재설계이므로 디자인 변경으로 다룬다.

모든 값을 가까운 토큰에 맞추면 픽셀이 달라지고, 모든 기존 값에 새 토큰을 만들면 역할 설계를 코드 정리가 대신하게 된다. 폰트의 소수 크기를 유지하려고 전역 반올림을 없애면 전체 글꼴 크기와 래스터라이저 캐시에 영향을 준다.

임시 divergence 주석만 없애고 alias를 남기면 해결된 것으로 오해하게 된다. 값이 같다는 이유로 역할을 합치면 나중에 하나만 바꿀 수 없다. 공통으로 정해진 tint 조합을 컴포넌트별 이름으로 쪼개면 차이가 다시 늘어난다.

복제가 필요 없어진 뒤에도 검사만 유지하면 불필요한 동기화 비용이 남는다. enum만 공유하고 그리기를 복사하면 색·보더 차이는 계속 생긴다. 갤러리를 본체 바이너리에 의존시키거나 이미 공용 크레이트가 있는데 새 크레이트를 추가할 필요는 없다. alpha 계산 순서를 옵션으로 남기면 같은 카드의 두 계산이 계속 존재한다.

배경 파이프라인만 ALPHA_BLENDING으로 바꾸면 강조가 셀 배경 대신 아래 clear 색과 섞인다. 별도 quad는 인스턴스와 wide-cell 처리를 늘린다. 검색만 합성하면 같은 테마 형식의 다른 강조색은 계속 alpha를 무시하게 된다.

코드부터 시안을 탐색하면 빌드와 대안 비교 비용이 커진다. 대표 컴포넌트만 갤러리에 두면 빠진 화면의 검증 경로가 사라진다. 사이트 사본을 임의 편집하면 다음 동기화가 덮어쓰고 차이의 출처를 잃는다. 사본 시점은 수기 날짜 대신 Git 이력에서 계산한다.

## Reconsideration Triggers

위젯이 외부 프로젝트에서도 쓰이거나, 실행 중 받은 아이콘이 필요해지면 현재 경계를 다시 검토한다. 채워진 아이콘과 여러 색 아이콘에는 빌드 때 SVG를 선분 데이터로 바꾸는 방식이 충분한지도 확인한다.

latte 팔레트나 상태바·탭바 디자인을 수정하거나 AA 준수가 필수 배포 조건이 되면 대비 예외를 다시 검토한다.

폰트 반올림·지원 배율·토큰 스케일이 바뀌거나 고정 치수가 사용자 문제를 만들면 이름만 붙여 둔 값을 다시 검토한다. 같은 색 계수라도 역할이 같은지는 소스의 숫자 검사로 확인할 수 없어 디자인 검토가 필요하다.

갤러리에 자체 토스트 구현이나 색 계산이 다시 생기면 공유가 가능한지 먼저 확인하고, 불가능하면 비교 검사를 복원한다. 디자인이 본문 페이드나 감마 공간 계산을 요구하면 공용 함수 한 곳과 앱·갤러리 캡처를 함께 검토한다.

강조를 별도 GPU 인스턴스로 그리거나 셀 배경까지 창 투명도를 적용하게 되면 CPU 합성 위치와 공식을 다시 검토한다.

갤러리 유지 비용이나 HTML→egui 전사 비용이 커지면 변경 커밋에서 반복 수정 비중을 확인한다. 사이트 토큰 지연 목록이 비면 집합 동등 검사로 정리한다. 토큰 이름을 바꾸지 않는 디자인 변경이 반복해서 사이트에서 누락되면 원격 파일 비교 자동화를 검토한다.
