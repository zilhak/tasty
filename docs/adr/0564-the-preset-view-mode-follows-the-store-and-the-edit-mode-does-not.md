# ADR-0564: 프리셋 보기 모드의 미리보기는 저장소를 따라가고, 편집 모드의 캐시는 따라가지 않는다

- **Status**: Accepted
- **Date**: 2026-09-23
- **Tags**: preset, layout-presets, concurrency, agent-user-separation, identity-principle-1, adr-0531
- **Group**: ui-theme-gallery

## Context

프리셋 창(`PresetView`)의 미리보기는 선택한 preset 을 저장소(`PresetStore`)에서 한 번 읽어
`DemoLayout` 으로 짓고 egui temp memory 에 캐시한다. 보기 모드(read-only)와 편집 모드(WYSIWYG)가
**같은 캐시 칸**을 쓴다.

[ADR-0531](0531-the-preset-editor-does-not-overwrite-a-preset-changed-behind-its-cache.md) 은 편집
화면의 저장이 에이전트의 `preset.save` 를 덮지 않도록, 저장 직전에만 저장소와 대조하게 했다.
그 결과 캐시는 저장하는 순간 말고는 저장소를 보지 않는다 — 보기 모드도 마찬가지다. 그래서:

1. 사용자가 보기 모드로 preset 을 보고 있는 사이 에이전트가 같은 이름으로 저장한다.
2. 미리보기는 옛 판을 그대로 보인다(목록과 subtitle 은 매 프레임 저장소에서 읽어 이미 새 값이다).
3. 사용자가 그 화면을 믿고 편집 모드로 들어가 한 번 고치면, 캐시의 기준 판이 옛것이라 그 첫
   편집이 경합으로 판정돼 버려진다.

화면이 저장소와 어긋난 채 사용자가 작업하고, 그 작업이 사라진다. 풀려면 에이전트의 쓰기가
**언제** 사용자가 보는 화면을 바꿔도 되는지를 먼저 정해야 한다([정체성 원칙](../identity.md) 1:
에이전트 행동의 부수효과가 사용자 상태 — 포커스 · 닫은 항목 히스토리 · 선택 · 스크롤 · 커서 — 에
닿지 않는다).

## Decision

**보기 모드의 미리보기는 저장소의 레이아웃을 따라간다. 편집 모드의 캐시는 ADR-0531 그대로 저장
직전에만 대조한다. 가르는 기준은 "사용자가 고치는 중인 것이 그 화면에 있는가" 다.**

- 판정: 보기 모드의 미리보기는 **저장소 내용을 보여 주는 표시**이고 사용자 상태가 아니다. 목록 행과
  subtitle 이 이미 그렇듯, 에이전트가 저장한 내용은 다음 프레임에 그대로 보여도 된다. 반면 편집
  모드의 캐시는 사용자가 겨냥하고 있는 트리다(선택 leaf · 단축키 대상 · 열린 설정 draft 의 leaf id).
  그것을 에이전트 쓰기가 갈아 끼우면 사용자 조작의 대상이 발밑에서 바뀐다 — 그래서 따라가지 않는다.
- 시점: 보기 모드 추종은 사용자 행동(모드 전환 · 포커스 · 선택)에 걸지 않는다. 보기 모드로 그리는 **매 프레임**
  저장소의 레이아웃 부분(`LayoutBase`)을 캐시의 기준 판과 대조하고, 다르면 캐시를 저장소 판으로
  다시 짓는다. 에이전트의 저장과 Edit 클릭 사이에 보기 모드가 한 번이라도 다시 그려졌다면, 편집
  모드로 들어가는 순간 캐시는 이미 새 판이므로 첫 편집이 경합이 되지 않는다.
- 저장소의 레이아웃이 그대로면 캐시를 건드리지 않는다 — 미리보기에서 누른 mini-tab 같은, 저장되지
  않는 보기 상태가 매 프레임 지워지지 않는다.
- 다시 짓는 것은 캐시뿐이다. 선택한 preset · 모드 · 선택 leaf · 목록 스크롤은 건드리지 않고,
  toast 도 띄우지 않는다(버려진 사용자 변경이 없다).
- preset 이 사라졌으면 캐시를 그대로 둔다(되살리지도, 비우지도 않는다 — 이 결정 전과 같다).

### 보기 → 편집 전이 프레임 (같은 날 채택)

이 조항은 처음에는 범위를 이유로 안 골랐던 대안이고, 잔여 경로가 실재함이 행동 시험 `edit_mode_entered_on_the_first_frame_after_an_agent_save_starts_from_the_new_version`(`src/adapters/ui/preset/view_refresh_tests.rs`)으로 확인돼 같은 날 채택됐다.

- 보기 → 편집 전이 프레임: 그 사이 보기 프레임이 없었던 경우(저장 뒤 그 창의 첫 프레임이 곧
  Edit 를 누른 프레임)를 메우려고, 직전 프레임이 보기 모드로 그려졌는데 이번 프레임이 편집
  모드면 편집 갈래로 들어가기 전에 같은 대조를 **한 번** 한다. 직전 모드는 캐시 칸과 따로
  temp memory 에 둔다(설정 화면 · 경합 재적재가 캐시를 새로 지어도 흔들리지 않게). 이 시점의
  캐시에는 아직 사용자 편집이 없으므로 편집 모드 조항과 부딪히지 않는다. 그 뒤의 편집 프레임은
  따라가지 않는다.

## Consequences

- **얻은 것**: 에이전트 저장 뒤 보기 모드가 새 판을 보이고, 그 뒤 들어간 편집이 — 저장 뒤 첫
  프레임이 곧 Edit 를 누른 프레임이어도 — 버려지지 않는다. 편집 모드의 동작(미저장 draft · 선택 ·
  저장 시점 경합 판정)은 바뀌지 않는다. 미저장 draft 는 `surface_cfg` 에 따로 살아 캐시 교체와 무관하다 — 그 성질 자체를 재는
  시험은 없고 이 기제로만 고정돼 있다.
- **잃은 것**: 에이전트가 레이아웃을 바꾸면 보기 모드 미리보기에서 사용자가 눌러 둔 mini-tab 이
  저장된 `active_tab` 으로 돌아간다. 새 트리에서 옛 pane 을 가리킬 안정 id 가 없어(pane id 는
  세션마다 새로 매긴다) 옮길 수 없다. 편집 모드 도중 에이전트가 저장하면 여전히 저장 순간에야
  드러난다(ADR-0531 의 잃은 것 그대로).
- **닫힌 잔여 경로 — 보기 프레임 없는 Edit 전이**: `PresetView` 는 한 프레임 안에서
  `apply_toolbar_actions` 가 먼저 `editing = true` 를 세우고 그다음 `draw_preview` 가 불린다.
  에이전트의 저장은 프리셋 창을 다시 그리게 하지 않는다 — IPC 처리 뒤 다시 그리기
  요청(`mark_dirty`)은 `focused_window_mut()` 로 가는데 그 함수는 `MainView` 로만 내리므로, 프리셋
  창의 포커스 여부와 무관하게 메인 창에만 간다. 그래서 저장 뒤 그 창의 첫 프레임이 Edit 가 눌린
  프레임일 수 있다(⑴ press 와 release 가 한 이벤트 배치로 와 `RedrawRequested` 가 그 뒤 한 번만
  오거나, ⑵ 키보드 포커스로 Edit 를 Space/Enter 로 누른 경우 — 어느 플랫폼에서 실제로 나는지는
  GUI 로 재지 않았다). 그 프레임은 곧바로 편집 갈래로 가므로, 전이 조항이 없으면 편집 모드가 옛 판 ·
  옛 기준 판으로 시작하고 첫 구조 편집이 ADR-0531 경로로 버려진다(전이 조항 없이 잰 값: 탭 1 → 2
  저장 뒤 `tabs=1`, `base_matches=false`). Decision 의 "보기 → 편집 전이 프레임" 조항이 이것을
  닫고, 시험
  `edit_mode_entered_on_the_first_frame_after_an_agent_save_starts_from_the_new_version`
  (`src/adapters/ui/preset/view_refresh_tests.rs`)이 보기 프레임 → 저장 → 곧바로 편집 프레임 순서로
  캐시의 탭 수와 기준 판을 잰다. 대가는 없다 — 전이 프레임의 캐시에는 버릴 사용자 편집이 아직
  없다.
- **운영 비용 / 유지 부담**: 보기 모드 프레임마다 선택 preset 의 레이아웃 부분 복제 한 번과 대조
  한 번. preset 레이아웃은 작다.

## Alternatives Considered

- **편집 모드로 들어갈 때(Edit 클릭) 다시 짓는다** — 첫 편집이 버려지는 것은 막지만 보기 모드는
  계속 옛 판을 보인다. 그리고 새로고침이 사용자 행동에 걸려, 사용자가 본 것과 편집에 들어간 것이
  달라진다 — 원칙 1 의 경계를 거꾸로 밟는다. Decision 의 전이 프레임 조항은 이것과 다르다 — 여기서
  기각한 것은 Edit 클릭 때 다시 짓기를 보기 모드 추종 없이 **단독 수단**으로 쓰는 것이고, 그 조항은
  매 프레임 보기 모드 추종을 그대로 두고 그 사이 빈틈 한 프레임만 메운다(그 프레임에서 사용자가 본
  것은 이미 저장소 판이어야 했던 화면이다).
- **두 모드 모두 매 프레임 따라간다** — ADR-0531 의 기각 대안 그대로다. 선택 leaf · 열린 draft 의
  leaf id 가 다른 트리를 가리킬 수 있다.
- **보기 모드에서 "다른 곳에서 바뀜" 표시만 띄우고 사용자가 눌러 새로고침한다** — 새 표시 위젯이
  필요해 디자인 시안 → 갤러리 specimen 을 먼저 거쳐야 하고, 보기 모드에는 버릴 것이 없어 묻는 이득이
  없다.
- **저장소가 변경 알림을 보내 캐시를 무효화한다** — 저장소에 구독 채널이 없고, 매 프레임 대조와
  결과가 같다.

## Reconsideration Triggers

**채널이 붙는 것** — 판정 시점에 레포가 읽을 수 있는 사실이다.

- 저장소가 판 번호(revision)나 변경 알림을 싣게 된다. 그때 매 프레임 레이아웃 대조를 그 값 대조로
  바꿀지 본다(ADR-0531 의 같은 조건과 함께).
- 미리보기 pane 에 세션을 넘어 안정한 id 가 생긴다. 그때 새로고침 뒤에도 눌러 둔 mini-tab 을 옮길지
  본다.

**원리적으로 안 붙는 것** — 사람이 관측해야 한다. 재는 법을 함께 적는다.

- 보기 모드에서 미리보기가 바뀌는 것이 방해된다는 보고. 재는 법: 이슈·사용자 보고.
