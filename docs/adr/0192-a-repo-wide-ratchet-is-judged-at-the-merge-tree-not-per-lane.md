# ADR-0192: 레포 전체를 세는 래칫은 lane 단위로 예측되지 않는다 — 판정은 병합 트리에서 한다

- **Status**: Accepted
- **Date**: 2026-09-07
- **Tags**: ci, guards, ratchet, merge-tree, per-lane, split-landing, cap, r746, r751, r752, r753, r756, adr-0139, adr-0137, adr-0183

## Context

여러 lane 이 각자 worktree 에서 병렬로 작업하고, 조립 회차가 그것들을 병합 트리로 모은다. 게이트 중 일부는 **레포 전체를 세는 상한 래칫**이다 — 억제(`#[allow]`)의 수, 통합 테스트 타깃의 직접 `read_dir(` 호출 수 같은 것을 세서 상한(CAP)과 비교한다. 그중 **여유가 0 인 래칫이 여럿 있고, 확인한 것은 모두 양방향이다**: 상한을 넘어도 빨갛고, 값이 상한보다 **줄어도** 빨갛다(게이트 스크립트가 `count < CAP` 도 실패로 처리하며, 머리말이 "줄면 실패한다 — 상한을 같이 내리라는 뜻이고, 남는 여유는 곧 안 보는 구간이다" 라고 적어 둔다).

- **극성은 게이트가 아니라 술어에 붙는다 (R691).** "이 래칫은 줄면 안 빨갛다" 같은 성질은 남의 말로 받지 말고 술어를 읽어 확인한다 — 두 스크립트를 읽으면 몇 분이다. 남이 흘린 극성을 확인 없이 **작업 단위로 키우는 것**이 가장 비싼 오판이다(R688): 이미 있는 성질을 "넣으라" 고 배정하게 된다.

여유 0 이고 양방향이면 lane 단위 예측이 오히려 단순해진다. **`rc=0 ⟺ 값 == CAP` 이고, CAP 은 커밋된 상수 = `main` 의 값이다 (R753).** 그래서 **어느 lane 도 CAP 을 안 건드린 한, rc=0 을 보고한 lane 의 순증분은 정의상 0 이다** — 게이트를 흉내 내 바늘을 셀 필요 없이 게이트를 부르면 된다. 바늘 세기(diff 카운트)가 필요한 것은 **여유가 있는** 게이트다.

문제는 lane 이 **CAP 을 건드릴 때** 생긴다. lane A 가 값을 하나 늘리고 상한을 같이 하나 올리면(게이트가 실패문으로 시키는 일이다), 자기 base 에서 `값==CAP` 라 초록이다. lane B 도 독립으로 같은 일을 하면 자기 base 에서 초록이다. 그런데 병합 트리에서는 **두 증분이 다 살아 값이 둘만큼** 늘고, 두 lane 이 각자 상한 줄에 **같은 새 값을** 썼으므로 **git 은 같은 줄에 같은 내용이라 conflict 를 못 본다**. 상한은 한 번만 올라간 채 값만 둘 올라, **어느 lane 도 안 빨갛고 병합만 빨갛다.**

이것은 [ADR-0137](0137-plugin-version-bump-is-judged-by-content-not-file-count.md) 이 기록한 plugin 분할 착지 함정과 **같은 자리**다 — 두 lane 이 서로 다른 base 에서 같은 버전 값을 올리고, 앞이 먼저 push 되면 그 값이 앞 내용으로 발행돼 뒤의 변경이 조용히 묻힌다. 좌변이 "레포 전체 카운트" 든 "발행 버전 문자열" 이든, **여러 lane 이 같은 값을 같은 줄에 쓰므로 병합이 상호작용을 숨긴다**는 구조가 동일하다.

lane 이 **여유 있는** 게이트에서 delta 를 재려 할 때는 두 계기가 조용히 어긋난다(위 양방향 여유 0 래칫에는 R753 이라 불필요하지만, 규칙으로 남긴다).

- **diff 로 잰 delta 는 하한이다 (R751).** `git diff <base>..HEAD | grep -c <바늘>` 은 두 형태에서 조용히 0 을 낸다. (가) 억제 래칫의 바늘은 "`#[allow]` 이 있는가" 가 아니라 **"사유 주석이 없는 `#[allow]` 인가"** 다 — 억제는 두고 그 위 사유 주석만 지운 편집은 diff 에 억제 줄이 없어 0 인데 값은 하나 는다(사유를 더하면 반대로 하나 준다). (나) 파일-목록 래칫의 좌변은 `git ls-files` 로 고른 파일 집합이라, `read_dir(` 를 한 줄도 안 건드리고 **파일을 그 집합 안팎으로 옮기기만 해도**(순수 rename) 값이 움직이는데 `-U0` diff 엔 그 줄이 없다. 그래서 **diff 0 은 "기여 없음" 이 아니라 "이 술어가 보는 형태로는 없음" 이다.**
- **Σdelta 는 바늘이 줄 단위로 가산될 때만 성립한다 (R752).** 억제 래칫은 줄 단위라 합산이 성립한다. 파일-목록 래칫은 좌변이 파일 집합이라, 두 lane 이 같은 파일을 각각 고쳐 병합되면 delta 합과 실측이 정상적으로도 어긋난다. 그러니 어긋남을 곧바로 "예측 못 한 상호작용" 으로 읽지 말고, **먼저 "같은 파일을 둘이 만졌는가" 를 묻는다.**
- **판정기가 없거나 낡으면 세 게이트가 거짓 빨강이고, 그 모양이 회귀와 같다 (R746).** 억제·호출을 문자열 리터럴·주석이 아니라 코드에서 세려면 마스킹 판정기(`mask-source`)가 필요한데, 평범한 `cargo build` 는 이 바이너리를 짓지 않는다. 판정기가 없으면 원문에서 세어 문자열·주석 안 언급까지 잡히고, 값이 상한을 넘어 빨개진다 — 그 증가폭은 **회귀의 크기가 아니라 세는 사본이 바뀐 폭**이다. 신선도는 mtime 이 아니라 내용 지문으로 물어, 낡은 판정기도 없는 것으로 다룬다. 그래서 값을 보기 전에 판정기의 존재·신선을 먼저 물어야 한다.

## Decision

**레포 전체를 세는 래칫의 판정은 병합 트리에서 한 번 한다. lane 은 자기 base 기준 상태를 보고만 한다.**

- **여유 0 양방향 래칫**: lane 은 `rc` 와 **CAP 을 건드렸는가** 만 보고한다(R753). CAP 을 안 건드렸으면 순증분은 정의상 0 이라 delta 를 따로 재지 않는다. CAP 을 건드린 lane 은 조립이 병합 트리에서 반드시 재판정할 대상으로 표시한다.
- **그 외 게이트**(여유가 있거나 값을 안 찍는 것): 이전 형식대로 **rc · 값 · delta(계기를 밝힌다) · 상태(tip · dirty) · 게이트별 tip** 을 보고한다. delta 를 닫는 계기는 셋이다(R756): (i) **diff 법** — 싸지만 하한 0(R751), (ii) **재측정법** — base 를 임시 worktree 로 떼어 값을 만드는 술어를 그대로 다시 돌린 확정 0, (iii) **변경집합 형태로 닫기** — `--name-status` 가 `.md` `M` 만이면 R751 두 채널이 구조적으로 발동 불가라 확정 0, 가장 싸지만 변경 부류가 좁을 때만 쓴다. 재측정법이 diff 법과 다른 진짜 지점은 **조용히 틀린 값이 나오는 경로가 없다**는 것이다 — `resolve_judge` 는 환경변수로 판정기 경로를 줘도 `--check-fresh` 를 돌리므로(R746), 새 체크아웃에서 마스킹된 값이 나온 사실 자체가 "판정기가 base 와 tip 에서 같다" 는 전제의 증명이고(다르면 값이 안 나오고 판정 불가로 떨어진다), 그 값이 원문 카운트가 아니라는 것 자체가 양성 대조다. **변경 부류가 R751 두 형태(`#[allow]` 을 담을 수 있는 소스 편집 · 파일 rename)에 애초에 닿지 않는 lane**(예: 문서만 고친 lane)은 (iii) 로 닫는다 — 그 확정은 계기가 세서가 아니라 변경 부류가 좁아서다.
- **최종 판정은 병합하는 쪽(조립 회차)이 병합 트리에서** 한 번 돌려 정한다. lane 의 보고로 병합 값을 예측하되, 예측과 실측이 어긋나면 그 어긋남을 신호로 삼는다(단 파일-목록 래칫에서는 R752 대로 "같은 파일" 을 먼저 묻는다).
- **여유 0 인 래칫은 그 실행이 push 전에 끝나 있어야 한다** — push 뒤 조립에서야 빨개지면 그 커밋은 이미 공유 이력에 얹혀 있다.

## Consequences

- **얻은 것**: 여유 0 래칫이 병합에서 처음 빨개지는 형태(두 lane 이 각자 값·CAP 을 올려 병합만 깨지는)를 조립 회차가 push 전에 잡는다. 그 탐색이 **CAP 을 건드린 lane** 으로 좁혀진다.
- **얻은 것**: lane 은 예측 불가능한 것을 예측하려 애쓰지 않고 자기 몫(rc·CAP 접촉 여부)만 한다. 양방향 여유 0 래칫에서 바늘 세기라는 잉여 작업이 사라진다.
- **잃은 것**: CAP 을 건드린 lane 은 자기 커밋이 병합에서 래칫을 깨뜨릴지 확실히는 모른 채 push 한다 — 확정은 조립에서만 선다. 임시 worktree 재측정으로 불확실을 줄일 수 있으나 상호작용 자체는 조립에서만 드러난다.
- **운영 비용**: 조립 회차가 병합 트리에서 게이트를 한 번 더 돌린다. 착지 직전 `cargo test -p tasty-doc-guards` 를 한 번 돌리는 규율(초 단위)이 붙는다.

## Alternatives Considered

- **lane 마다 `--staged` 로 "내 커밋이 값을 늘렸나" 만 본다** — 기각. 그 검사는 "내 커밋이 늘렸나" 를 보는데, 물어야 할 것은 "병합될 값과 지금 내용이 짝이 맞나" 다. **lane 의 base 가 낡으면 통과도 낡는다.**
- **게이트에 `--range <base> HEAD` 를 붙여 lane 이 두 지점을 잰다** — 부분해로 채택하되 완전해로는 기각. 형제 게이트가 이미 이렇게 푼 선례가 있다([`check-plugin-version-bump.sh`](../../scripts/check-plugin-version-bump.sh) 의 `--range`, [ADR-0137](0137-plugin-version-bump-is-judged-by-content-not-file-count.md)). lane 이 자기 범위를 재는 데는 도움이 되지만, 두 lane 의 **상호작용**은 여전히 병합 트리에서만 나므로 이 대안 하나로는 예측이 서지 않는다.
- **lane 이 게이트를 흉내 내 바늘을 직접 센다** — 양방향 여유 0 래칫에서는 기각. `rc=0 ⟺ 값==CAP` 이라 게이트를 부르는 것이 곧 답이고, 바늘 세기는 R751·R752 의 함정만 들인다.

## Reconsideration Triggers

다음 중 하나가 충족되면 본 ADR 을 재검토한다.

- 대상 래칫의 **여유가 0 이 아니게** 되면 — `rc=0 ⟺ 값==CAP` (R753) 전제가 사라져 delta 를 실제로 재야 한다.
- 래칫이 **양방향이 아니게**(줄면 통과하게) 되면 — 극성이 바뀌어 CAP 접촉만으로는 예측이 안 선다.
- 래칫의 **좌변이 파일 목록이 아니게**(순수 줄 단위 카운트로) 되면 — R751 (나)·R752 의 파일-목록 예외가 사라진다.
- 병합 트리에서만 나던 상호작용을 lane 단위로 **결정적으로** 예측하는 도구가 생기면.
