# Markdown Viewer (`com.tasty.markdown`)

- **Status**: Implemented (bundled plugin)
- **Actors**: local user (GUI surface) · AI agent (`tasty markdown` CLI)
- **Distribution / integration**: bundled · surface_kind (webview) · file handler — [plugin concepts](../../concepts/plugins.md)
- **Code**: `crates/tasty-plugin-markdown/` (`src/render.rs` = `pulldown-cmark` → sanitize (`ammonia`) → CSS-injected HTML document generation, `src/main.rs` surface lifecycle/navigation/popups, `src/watch.rs` idle auto-reload) — [ADR-0065](../../adr/0065-markdown-webview-render-channel.md) (the EguiMesh→Webview switch decision) · [ADR-0028](../../adr/0028-plugin-egui-mesh-render-channel.md) (the egui-mesh channel, still used for popups only)
- **Permissions**: `surface.read/write`, `fs.read` (file reading + link dispatch), `file_handler.*`, `ui.settings_page`, `ui.popup` (only file-open/large-file-confirm self-render — not the body) (manifest `permissions`)
- **Screens**: [screens/markdown.md](screens/markdown.md)

> **As an example**: the example gathering a webview surface (the plugin generates a sanitised HTML document, the host native WebView renders it) + **file detector/handler** + cli + settings_page in one plugin → [plugin-development](../../dev-guide/plugin-development.md#파일-핸들러-detector--handler).

## Purpose

Provides the **`markdown` surface kind** that renders markdown files. `rendering = "webview"` ([ADR-0065](../../adr/0065-markdown-webview-render-channel.md)) — the plugin converts markdown to HTML with `pulldown-cmark`, sanitises it with `ammonia`, inlines a `<style>` that injects Theme tokens as CSS custom properties into the document, and puts it on the host's native OS WebView (WebKitGTK/WKWebView/WebView2) overlay (`webview.set_url`). The host does not touch the document's pixels — unlike the egui-mesh days, the host composites no mesh.

## Internal behaviour

- **surface_kind `markdown` (webview)** — the plugin owns `MdDoc` (file path · content · base_dir · load_error), and `render::render_document` generates one complete `<!doctype html>` document: `<base href="file:///<base_dir>/">` (anchoring relative-path images/links) + `<style>` (CSS custom properties, Theme→tokens) + the address bar `<input>`+`<button>` + the body (sanitised HTML) + a trusted inline `<script>` (address bar Go/Enter + scroll restore). display_name is the file name.
  - **Heading ladder**: `render::heading_sizes_px` **linearly interpolates** five steps between `font-size-prose-h1` (h1) and `font-size-body` (h6) — being CSS, with no library constraint, this interpolation itself is the plugin's design choice (per-level values can be freely overridden if wanted).
  - **Tables (GFM)**: real `<table>`/`<th>`/`<td>` — header band · zebra (`tr:nth-child(even)`) · cell padding all achieved directly in CSS (no egui `Grid` workaround needed).
  - **Code blocks**: the fenced language tag (` ```rust `) survives on `<code>` as `class="language-rust"` (`render::sanitize_fence_lang` normalises to `[A-Za-z0-9_+-]`, then `code`/`class` are explicitly allowed in the ammonia whitelist) — the premise for identifying future mermaid fenced blocks (`language-mermaid`). Actual syntax highlighting/mermaid rendering is not yet wired (follow-up).
- **sanitize (the first gate of XSS defence)** — a minimal `ammonia::Builder` whitelist: `<script>`/event-handler attributes (`onerror=` etc.)/`javascript:` scheme hrefs are all stripped. `classify_link` also separately treats `javascript:` as unresolvable (`None`) for double defence. Only the tags GFM rendering needs (`table`/checkbox `input[type=checkbox]`/`del`/footnote `sup`/`div`/images/links) are allowed — the code is canonical in `crates/tasty-plugin-markdown/src/render.rs::sanitize_html`.
- **Reload · deletion handling** — the `markdown.reload` IPC (explicit call) and idle-watch-detected reloads converge on **the same single function** (`MarkdownPlugin::markdown_reload`) — the actual read (`MdDoc::force_reload`) and document regeneration (`reload_webview`) always take only this one path, so even with rapid successive edits the race of "a stale read overwriting the latest value" never arises in the first place (the plugin runtime is a single-threaded dispatch loop). If the file disappears through external deletion it is shown as the error state (`markdown.state.failed`) and recovers automatically when it reappears.
- **Idle auto-reload (updates even without input)** — webview-kind surfaces **never receive** `surface.set_context`/`paint` (= egui-mesh-only forwards) — so the idle watch (`src/watch.rs`) is effectively the only automatic refresh path. `on_start` spawns a separate thread that stats the file mtime of every open markdown surface every `RELOAD_CHECK_INTERVAL_SECS` (1 s) and, on detecting a change, round-trips through the host to call **the plugin's own** `markdown.reload` IPC (`host.call`) — the identical request to a CLI/user calling the same method arrives serially on the single dispatch loop, sharing the no-race guarantee above as-is.
- **Content delivery** — at surface creation the host sends `surface.create{file}` to the plugin. The plugin reads the file directly (`fs.read`).
- **Theme parity** — webview-kind surfaces do not get the Theme pushed automatically (unlike egui-mesh's `set_context.theme`), so each time the plugin (re)generates a document it queries the current colours + `is_light` + UI zoom directly with the host's read-only **`theme.query`** IPC. When colours change afterwards, it subscribes to the **`theme.changed`** event the host publishes (manifest `event_subscribe`) and regenerates every open markdown document.
- **JS allowed by default** — the host's webview setting defaults differ per plugin: the html plugin blocks JS by default (it can open arbitrary remote content), markdown **allows by default** (the per-plugin override in `resolve_webview_settings`, `src/view/main/redraw.rs`) — the trusted address bar/navigation scripts must always run, and the actual markdown content itself is already sanitised separately, so allowing JS creates no additional attack surface.
- **Inline images** — the `<base href="file:///<base_dir>/">` in the document `<head>` anchors relative-path image `src`/link `href`, and otherwise plain `<img>` tags are loaded directly by the browser engine (no host/plugin involvement — completely outside the egui texture pipeline). `<base>` does not touch absolute paths/remote URLs that already have a scheme, so the bug the old `image_uri_prefix` had of "absolute-path images wrongly anchored like relative paths" does not exist. Supported formats are everything the browser engine supports (PNG/JPEG/GIF/SVG/WebP etc. — the `image` crate's PNG/JPEG limitation is gone).
- **File handler** — `detector "markdown"` (extension mapping) + `handler` action `open_surface{surface_kind:"markdown"}`. Opening a markdown file yields this surface.
- **File-open / large-file confirm popups** — the plugin manifest `[[contributes.popup]] id="file-open"`/`id="large-file-confirm"` — **remain egui-mesh** (Stage B switched only body rendering to webview; the two confirm popups stayed). Composed of a path input field + **Browse** + Open/Cancel. **They open by two paths**: (1) the surface_kind manifest `convert_input_popup = "file-open"` capability — the host opens this popup directly with `open_popup_instance` from the convert popup/`open_markdown`·`convert_to_markdown` shortcuts/context-menu entry points ([ADR-0043](../../adr/0043-convert-input-popup-capability.md)), (2) the event trigger `com.tasty.markdown.file_open`. **Browse** opens the host-owned in-app `file_picker` popup via the host generic **`file_picker.trigger {filters,owner_popup_instance?} → {request_id}`** IPC ([ADR-0058](../../adr/0058-plugin-triggered-host-popup-async-ack-push.md) — replacing the old native rfd dialog delegation [ADR-0042](../../adr/0042-fs-pick-file-native-dialog-host-delegation.md)). The call receives only a `request_id` immediately and the selection result arrives asynchronously as the `file_picker.result` event. Here `owner_popup_instance` reports **file-open's own popup instance** so the two popups form a parent-child stack ([ADR-0084](../../adr/0084-plugin-triggered-host-popup-ownership.md)) — while the picker is up, file-open does not close on an outside click, Esc closes one level at a time from the upper picker, and if file-open closes first the picker is cleaned up too so the chosen file is not lost. **On confirming Open, it branches on whether the open context has a `surface_id`**: if present, that surface is converted in place (host `markdown.navigate {surface_id,path}` — convert-to-markdown); if absent, it opens in a new tab (host `file_handler.dispatch {path,depth:"deep"}` — open-markdown). `file_picker.trigger` is gated by the **`fs.read`** permission.
- **Link click routing** — every non-anchor link destination in the document is rewritten at HTML generation time to the internal nav-fragment scheme (`#tasty-nav:link:<percent-encoded-dest>`) (`render::rewrite_link_dest`) — leaving the real `href` would make the native WebView navigate to a real file/unknown scheme (the host blocks only *remote* http(s)), breaking the rendered document on the spot. A same-document navigation changing only the fragment (a) is still captured by WebKitGTK's `decide-policy` (→ the host forwards it as the `webview.navigation_attempt` event) but (b) causes no actual page reload (verified by measurement) — this property makes a signal channel that "intercepts the click without breaking the screen". The plugin's `on_webview_navigation_attempt` handler receives that event and judges with `render::parse_nav_fragment`+`classify_link`:
  - **Relative paths** (`docs/index.md`, `../sibling.md`) are absolutised **relative to the current markdown file's folder (base_dir)** (not the process cwd). Absolute paths as-is. `javascript:` is ignored unconditionally (a second line of defence separate from sanitize).
  - Only **external URLs** (`http(s)://`·`mailto:`·`data:`) are delegated by the plugin to the OS handler (`webbrowser`).
  - File links are sent to the host `file_handler.dispatch` (the same `DispatchFile` path as the Explorer "open file" — a **new tab in the Pane** that surface belongs to, no focus change).
- **Address bar** — no longer a host egui widget (the old `PathField`). `render::addr_bar_html` bakes `<input list="tasty-addr-recent">` + a native `<datalist>` (recent paths, the browser's built-in autocomplete — no custom dropdown JS needed) + a Go `<button>` into the document itself. It is baked with the *current* path/recent list at document generation time, and since the webview has no JS↔plugin real-time message bridge (see the module doc) there is no reactive re-fetch on focus like the old PathField — a Go click/Enter is sent by the trusted inline `<script>` (`render::nav_script`) through the nav-fragment channel above as `location.hash = 'tasty-nav:addr:' + encodeURIComponent(v)`.
- **Recent list query** — the host's generic **`recent.query {kind}`** IPC returns that kind's recently opened files, **newest first, up to 10** (`{recent:[{path,file_name}]}`). The markdown plugin calls it with `kind:"markdown"` to fill the address bar `<datalist>` above. **Read-only** — it only queries the host `AppState.recent_files` cache without filtering and changes no user state (the inviolable principle). **`surface.read`** permission. Whether a surface is recorded in recents is judged by the manifest `records_recent` capability.
- **Scroll position preservation (best-effort)** — idle-watch auto-reload and `markdown.reload` replace the entire document wholesale via `load_html` (no partial DOM patching) — as-is, the native WebView's scroll would reset to 0 on every reload. `render::nav_script` mitigates this with `sessionStorage` (keyed by file path; saved on `scroll` events with a 150 ms debounce + restored on load). It depends on same-origin scope, and whether repeated `load_html` calls keep origin identity may differ per webview engine (WebKitGTK/WKWebView/WebView2), so it is not verified across all three — on failure it only degrades gracefully to "not restored" with no error.
- **cli** — `tasty markdown recent` (recent list query — the plugin CLI subcommand trampolines to `recent.query`). reload etc. are also plugin CLI.
- **settings_page** — the `markdown` page.

## Interface

- **User**: open a markdown file → markdown surface, or switch the surface kind.
- **AI agent**: `tasty markdown …` CLI / `markdown.*` IPC. Surface creation is [work-area](../../features/work-area/index.md) (`--type markdown`).

## Non-goals

- The surface placement/creation domain — [work-area](../../features/work-area/index.md).
- Pixels/typography — design-system.
