# 문제 해결

Tasty를 쓰다가 막혔다면 아래에서 증상에 맞는 항목을 찾아보세요. 설치와 권한, 터미널 연결, 알림 문제를 확인하는 방법을 안내합니다. 해결되지 않으면 페이지 아래의 문제 신고 방법을 참고하세요.

## 먼저 볼 파일

모두 `~/.tasty/` 아래에 있습니다 (Windows 는 `%USERPROFILE%\.tasty\`).

| 파일 | 내용 |
|---|---|
| `config.toml` | 설정. 설정 윈도우에서 저장한 값이 여기 들어갑니다 |
| `tasty.port` | 실행 중인 Tasty 의 IPC 포트 번호. Tasty 가 뜰 때 만들어집니다 |
| `debug.log` | 직전 실행의 경고 이상 로그. Tasty 를 다시 켜면 비워집니다 |
| `crash-reports/crash-*.log` | 크래시 리포트 — 버전 · OS · 위치 · 메시지 · backtrace |
| `crash-reports/hang-*.log` | 윈도우가 5초 넘게 멈췄을 때 자동으로 남는 기록 |
| `hook-failures.log` | Claude / Codex 훅이 Tasty 에 닿지 못한 기록 |
| `plugins-logs/<플러그인 id>.log` | 플러그인별 로그. `tasty plugin logs <id>` 로도 봅니다 |
| `state.db` | 최근 파일 등 앱이 자동으로 관리하는 데이터 |

더 자세한 로그가 필요하면 터미널에서 로그 레벨을 올려 실행합니다. `RUST_LOG` 가 아니라 `TASTY_LOG` 입니다.

```sh
TASTY_LOG=debug tasty 2> tasty.log
```

## 설치 · 첫 실행

- **Windows: "Windows 의 PC 보호" 경고가 뜹니다** — 코드 서명이 없어서입니다. **추가 정보 → 실행** 을 누릅니다.
- **macOS: "확인되지 않은 개발자" 라며 열리지 않습니다** — Gatekeeper 입니다. **시스템 설정 > 개인정보 보호 및 보안** 에서 허용하거나, 터미널에서 `xattr -dr com.apple.quarantine /Applications/Tasty.app` 을 실행합니다.
- **Linux: AppImage 가 실행되지 않습니다** — 실행 권한이 없거나 FUSE 가 없습니다. `chmod +x Tasty-*.AppImage` 를 먼저 하고, 그래도 안 되면 `./Tasty-*.AppImage --appimage-extract-and-run` 으로 실행합니다.
- **Linux: `GLIBC_2.39 not found` 로 실행되지 않습니다** — Ubuntu 20.04 · Debian 11 처럼 빌드 기준(Ubuntu 24.04)보다 오래된 배포판입니다. 구배포판용 빌드는 없습니다.
- **Linux `.tar.gz`: 라이브러리가 없다며 종료됩니다** — `tasty` 가 빠진 라이브러리를 안내하고 끝납니다. 안내된 패키지(`libfreetype6` · `libfontconfig1` · `libgtk-3` · `libwebkit2gtk-4.1` 등)를 설치합니다. 자동으로 끌어오게 하려면 `.deb` / `.rpm` 을 씁니다.
- **"GPU 어댑터를 찾을 수 없음" 이 뜨고 종료됩니다** — 사용할 수 있는 GPU 어댑터(Vulkan / DirectX 12 / Metal)를 찾지 못했습니다. 드라이버를 설치·업데이트합니다. Linux 는 `libvulkan1` / `vulkan-loader` 가 있으면 Vulkan 으로, 없으면 OpenGL 로, 그것도 안 되면 소프트웨어 렌더링으로 뜹니다. 그래픽 화면 없이 서버 · VM에서 실행하려면 [headless 빌드](../getting-started/install.md#headless-빌드)를 사용하세요.
- **Windows: "Git Bash를 찾을 수 없습니다"** — Tasty 는 Windows 에서 Git Bash 를 셸로 씁니다. Git for Windows 를 설치하거나 **설정** <!-- en: Settings --> > **터미널** <!-- en: Terminal --> > **셸** <!-- en: Shell --> 에서 bash 경로를 직접 지정합니다.
- **"데이터베이스 초기화 오류" 로 시작하자마자 종료됩니다** — 본문을 봅니다. "DB가 잠겨 있습니다" 면 다른 Tasty 가 이미 떠 있습니다. "손상되었습니다" / "스키마 버전이 맞지 않습니다" 면 `~/.tasty/state.db` 를 백업한 뒤 지우면 새로 시작됩니다. 최근 파일 목록과 튜토리얼 진행 기록만 사라집니다.
- **Tasty 터미널 안에서 `tasty` 를 쳤는데 새 윈도우가 안 뜹니다** — Tasty 안에서 인자 없이 실행하면 새 윈도우 대신 도움말을 보여줍니다. 새 윈도우는 `tasty new window`(보던 윈도우의 포커스는 그대로 둡니다), GUI 를 강제로 띄우려면 `tasty --launch`.

설치 절차 자체는 [설치](../getting-started/install.md) 에 있습니다.

## macOS 권한 프롬프트

**증상** — 작업 도중에 권한 프롬프트가 떠서 하던 일이 멈춥니다. 터미널 안의 명령(과 그 안의 에이전트)이 새 폴더를 처음 건드릴 때마다 생깁니다.

**원인** — 터미널 안에서 실행한 명령이 파일을 읽으면 macOS 는 그 접근을 Tasty 의 것으로 봅니다(Terminal.app · iTerm2 도 같습니다). macOS 는 실제로 접근하는 그 순간에만 묻기 때문에, 미리 받아두지 않으면 프롬프트가 작업 한가운데에서 뜹니다.

**해결 — 미리 한 번에 받아둡니다.** **설정** > **일반** <!-- en: General --> > **권한** <!-- en: Permissions --> 에서 **모든 권한 요청하기** <!-- en: Request all permissions --> 를 누르면 다운로드 · 문서 · 데스크탑 폴더 → (연결돼 있으면) 외장 · 네트워크 볼륨 → 화면 기록 순으로 하나씩 물어봅니다. 앞의 것에 답해야 다음이 뜨고, 프롬프트가 떠 있는 동안에도 윈도우는 정상 동작합니다. 이미 허용하거나 거부한 항목은 다시 뜨지 않으므로 몇 번을 눌러도 괜찮습니다. 볼륨을 새로 연결한 뒤 다시 누르면 그 볼륨만 추가로 물어봅니다.

Tasty 는 시작할 때 프롬프트를 **자동으로 띄우지 않습니다.** 앱을 처음 켠 사람에게 이유를 알 수 없는 프롬프트가 줄줄이 뜨는 것을 없애기 위해서입니다. 대신 허용되지 않은 권한이 남아 있으면 시작할 때 안내가 떠서 이 화면으로 데려갑니다.

**어떻게 답하나**

| 권한 | 허용하지 않으면 | 나중에 바꾸려면 |
|---|---|---|
| 폴더 접근 (다운로드 · 문서 · 데스크탑 · 볼륨) | 그 폴더를 읽거나 쓰는 명령이 실패할 수 있습니다 | 시스템 설정 > 개인정보 보호 및 보안 > 파일 및 폴더 |
| 화면 기록 | `Ctrl+Alt+S` 스크린샷 → 클립보드 기능이 "화면 기록 권한이 필요합니다" 안내만 띄웁니다. 한 번 거부하면 다시 묻지 않습니다 | 시스템 설정 > 개인정보 보호 및 보안 > 화면 및 시스템 오디오 기록 |

현재 상태도 같은 탭에서 볼 수 있습니다(macOS 에서만 보입니다). 전체 디스크 접근 권한은 앱이 요청할 수 없어 이 버튼에 포함되지 않습니다. 그 아래의 **전체 디스크 접근 권한 설정 열기** <!-- en: Open Full Disk Access settings --> 로 시스템 설정을 열어 직접 추가하세요. 폴더 권한은 상태를 물어볼 방법이 없어 "조회 수단 없음" <!-- en: Cannot be observed --> 으로 표시됩니다.

- **"허용되지 않은 권한이 있습니다" 안내가 떴습니다** — 전체 디스크 접근 권한이나 화면 기록 권한이 없어 보이는 동안 시작할 때마다 뜹니다. 어떤 권한이 어떤 상태인지는 **설정** > **일반** > **권한** 탭에서 봅니다. **권한 설정 열기** <!-- en: Open permission settings --> 를 누르면 Tasty 의 권한 화면이 열립니다. 전체 디스크 접근 권한은 앱이 직접 요청할 수 없어, 그 화면의 **전체 디스크 접근 권한 설정 열기** <!-- en: Open Full Disk Access settings --> 로 시스템 설정을 열고 Tasty 를 목록에 직접 추가해야 합니다. 이 권한을 주면 파일 접근 프롬프트(다른 앱의 데이터 · 다운로드 · 문서 · 데스크탑 · 볼륨)가 사라집니다. 다만 다른 앱 제어(Automation) · 화면 기록은 별개 권한이라 그대로 남습니다. 권한을 주면 다음 시작부터 안내가 뜨지 않습니다. 안내를 끄는 설정은 없습니다. 껐다는 기록을 남기면 나중에 권한이 초기화됐을 때 알려줄 방법이 없어지기 때문입니다.
- **권한을 다 줬는데 폴더 접근 프롬프트는 여전히 뜹니다** — 시작 안내는 확인할 수 있는 권한만 봅니다. 다운로드 · 문서 · 데스크탑 · 볼륨 같은 폴더 권한은 macOS 가 상태를 물어볼 방법을 제공하지 않아서(물어보는 행위 자체가 프롬프트입니다) 안내 판정에 넣지 않습니다. 이 폴더들은 전체 디스크 접근 권한을 주면 함께 덮입니다.
- **권한을 줬는데도 안내가 다시 뜹니다** — Tasty 를 직접 빌드해 쓰는 경우입니다. ad-hoc 으로 서명된 빌드는 다시 빌드할 때마다 macOS 에 **다른 앱**으로 보여서 권한이 초기화됩니다. `./scripts/macos-codesign-identity.sh --create` 로 "Tasty Dev" 인증서를 한 번 만들고 그 인증서로 서명해 설치하면, 다시 빌드해도 권한이 유지됩니다. 인증서로 바꾼 직후 한 번은 목록에서 기존 Tasty 를 빼고 다시 추가해야 합니다.
- **전체 디스크 접근 권한 상태가 "확인 불가" 로 나옵니다** <!-- en: The Full Disk Access status shows "Unknown" --> — 이 상태는 macOS 에 묻는 API 가 없어 추정으로 구합니다. 추정에 쓰는 파일이 이 macOS 버전에 없으면 허용 여부를 판단할 근거가 없어 확인 불가로 표시하고, 이 권한을 이유로 시작 안내를 띄우지도 않습니다(화면 기록이 미승인이면 그 이유로는 뜹니다). 이 값으로 막히는 기능은 없습니다.
- **"Tasty이(가) 다른 앱의 데이터에 접근하려고 합니다" 가 앱 폴더마다 계속 뜹니다** — `~/Library/Application Support/<앱>` 같은 경로는 앱별로 따로 물어서 **모든 권한 요청하기** 로도 미리 받아둘 수 없습니다. 위의 전체 디스크 접근 권한을 주면 사라집니다.
- **`osascript` 를 쓸 때 "다른 앱을 제어하려고 합니다" 가 뜹니다** — Automation 권한은 대상 앱마다 승인해야 하며 전체 디스크 접근 권한으로도 덮이지 않습니다. Tasty 가 미리 해둘 수 있는 것이 없습니다.

## 윈도우가 멈추거나 갑자기 종료될 때

- **윈도우가 클릭 · 키 입력 · CLI 에 전혀 반응하지 않습니다** — 5초 넘게 멈추면 `~/.tasty/crash-reports/hang-*.log` 가 자동으로 남습니다. 파일의 `Render phase`가 `acquire` / `submit` / `present`이면 해당 렌더링 단계에서 멈춘 기록입니다. GPU 드라이버 문제일 수 있으므로 드라이버 업데이트도 확인하세요. Tasty 는 스스로 복구하지 않으므로 강제 종료하고 다시 띄웁니다.
- **갑자기 종료됐습니다** — `~/.tasty/crash-reports/crash-*.log` 를 봅니다. 문제를 신고할 때 이 파일을 함께 붙입니다.

## 설정이나 윈도우 구성이 초기화된 것처럼 보일 때

- **설정이 기본값으로 돌아갔습니다** — `~/.tasty/config.toml` 이 TOML 로 해석되지 않으면 기본값으로 시작합니다. 원래 파일은 지워지지 않습니다. 그대로 두었다가, 설정을 저장해 파일을 새로 쓰는 순간 같은 폴더의 `config.toml.bak` 으로 옮겨집니다. 그 파일을 열어 고친 뒤 `config.toml` 로 되돌리면 설정이 복원됩니다. 어느 줄이 문제인지는 `~/.tasty/debug.log` 에 적힙니다.
- **저장해둔 윈도우 구성이 복원되지 않았습니다** — `~/.tasty/layouts/` 의 슬롯 파일이 손상됐을 때도 같습니다. 원본은 `01.json.bak` 처럼 옆에 남습니다.
- **"저장되지 않는다, `.bak` 파일을 옮기거나 지워라" 는 알림이 떴습니다** — 원본을 옆으로 옮기려 했지만 `.bak` 부터 `.bak.9` 까지 아홉 자리가 이미 차 있어 더 둘 곳이 없는 경우입니다. 원본을 지우지 않으려고 저장 자체를 멈춘 상태이며, 그 세션 동안은 계속 저장되지 않습니다. 쌓인 `.bak` 파일 중 필요 없는 것을 옮기거나 지운 뒤 다시 켜면 정상으로 돌아옵니다.
- **"설정 파일을 읽지 못했다" 는 알림이 떴습니다** — 파일이 있는데 **읽지 못한** 경우입니다(권한 문제나 디스크 오류). 이때 Tasty 는 그 파일을 건드리지 않고 저장도 하지 않습니다 — 그대로 두면 지금 화면의 기본값이 원래 설정을 덮어쓰지 않습니다. 권한을 고치거나 파일을 다른 이름으로 옮긴 뒤 다시 켭니다.

  ```sh
  ls -l ~/.tasty/config.toml ~/.tasty/layouts/
  ```

## `tasty` 명령이 연결되지 않을 때

- **`No running tasty instance found (port file not found at …)`** — CLI가 확인한 경로에 포트 파일이 없습니다. 메시지에 적힌 경로가 `~/.tasty/tasty.port` 가 아니면 다른 홈 디렉토리(`TASTY_HOME`)를 보고 있는 것입니다. 이 메시지는 설정 언어(`general.language`, 기본값 영어)를 따르므로 한국어로 설정했다면 "실행 중인 tasty 인스턴스를 찾을 수 없습니다" 로 나옵니다. 인자가 잘못됐으면(깨진 JSON, 없는 `--cwd` 폴더 등) 이 메시지보다 그 인자의 오류가 먼저 나오므로, 이 메시지가 보였다면 접속 전에 수행하는 인자 검사를 통과한 것입니다.
- **포트 파일은 있는데 연결이 안 됩니다** — 이전 실행의 파일이 남았거나 다른 인스턴스의 경로를 보고 있을 수 있습니다. 오류에 나온 경로와 `TASTY_HOME`을 확인하고, 해당 파일을 사용하는 Tasty 인스턴스가 종료됐는지 확인하세요. 종료된 인스턴스의 남은 파일일 때만 직접 지우고 다시 시작하세요. 프로세스 이름 검색 결과만으로 파일을 삭제하지 마세요.


- **`tasty: command not found`** — Tasty 가 띄운 터미널 안에서는 PATH 에 자동으로 잡히고, `.deb` · `.rpm` · `.msi` 로 설치했다면 다른 터미널 앱에서도 잡힙니다. 그 밖의 설치 방식은 직접 등록해야 합니다. 설치 방식별 경로는 [설치 위치](../getting-started/install.md#설치-위치).

## 알림이 안 오거나 너무 많을 때

- **OS 알림이 안 뜹니다** — Tasty 윈도우가 활성일 때는 OS 알림을 보내지 않고 앱 안의 패널 · 테두리 · 배지로만 알립니다. 윈도우가 비활성일 때만 OS 알림이 가며, 초당 1회로 제한됩니다. **설정** > **일반** > **알림** <!-- en: Notifications --> 의 **알림 활성화** <!-- en: Notifications enabled --> 가 꺼져 있지 않은지 봅니다. 패널은 `Ctrl+Shift+I` 로 엽니다.
- **벨 소리(`\a`)마다 알림이 떠서 시끄럽습니다** — **설정** > **터미널** > **벨 알림 표시** <!-- en: Show bell notification --> 를 끕니다. `config.toml` 에서는 `[general]` 의 `bell_notification = false`. 벨 훅은 그대로 발생합니다.
- **소리가 안 납니다** — **설정** > **일반** > **알림** > **소리** <!-- en: Sound --> 가 기본 꺼짐입니다. 켜도 병합 간격 안에 같은 출처에서 연달아 온 알림은 하나로 합쳐져 소리가 한 번만 납니다.

설정 항목 전체는 [훅 · 알림 · 웹훅](../agents/hooks-notifications.md#설정).

## Claude · Codex 훅이 동작하지 않을 때

**증상** — 자식 에이전트의 완료 알림이 안 옵니다. 에이전트가 응답을 마쳐도 서피스 테두리 · 사이드바 배지가 켜지지 않습니다. 탭을 복원하거나 Tasty 를 재시작해도 같은 세션으로 이어지지 않습니다. `tasty claude reboot` 가 `claude-session-id meta not set` 으로 실패합니다. `tasty claude children` 이 보여주는 상태가 실제와 다릅니다.

**원인** — 훅이 설치돼 있지 않거나, Tasty 를 업데이트한 뒤 옛 훅 명령이 설정 파일에 그대로 남아 있습니다.

**해결** — 훅을 다시 설치합니다. 여러 번 실행해도 중복되지 않습니다.

```sh
tasty claude install    # ~/.claude/settings.json
tasty codex install     # ~/.codex/config.toml
```

그래도 안 되면 `~/.tasty/hook-failures.log` 와 `tasty plugin logs com.tasty.claude --follow` 를 봅니다. 세부 항목은 [Claude · Codex 와 함께 쓰기](../agents/claude-codex.md#문제-해결).

## 플러그인이 멈췄을 때

- **`tasty plugin list` 에서 enabled 인데 running 이 아닙니다** — 10초 안에 3번 실행에 실패하면 자동으로 정지됩니다. `tasty plugin logs <id>` 로 원인을 본 뒤 `tasty plugin enable <id>` 로 다시 시작합니다.
- **`plugin enable` 직후에는 running 인데 잠시 뒤 running 이 아니게 됩니다** — `plugin enable` 은 플러그인이 Tasty 에 연결하기를 기다리지 않고 바로 돌아옵니다. 그래서 막 켠 플러그인은 연결 전에도 running 으로 보이고, 그 사이 보낸 요청은 연결된 뒤 전달됩니다. 10초 안에 연결하지 못하면 실행 실패로 세어 running 이 아니게 됩니다. 원인은 `tasty plugin logs <id>` 로 봅니다.
- **번들 플러그인이 깨졌습니다** — `tasty plugin upgrade-builtins --force` 로 번들에서 다시 복사합니다. 플러그인 데이터(북마크 · 프로필 등)는 유지됩니다.

## 명령으로 파일 선택 팝업을 열 수 없을 때

- **스크립트나 에이전트가 IPC 로 파일 선택 팝업을 열려고 하면 `-32016` 오류가 납니다** — 정상입니다. 파일 선택 팝업은 사용자가 사이드바의 **도구** <!-- en: Tools --> > **파일 열기…** <!-- en: Open File… --> 로 열거나, 플러그인이 엽니다(마크다운의 파일 열기에서 **찾아보기…** <!-- en: Browse… --> 를 누를 때 등). 명령이 팝업을 띄우면 사용자가 입력하던 곳의 포커스를 빼앗고, 고른 경로도 그 명령에게는 돌아가지 않기 때문입니다. 스크립트·에이전트는 파일 경로를 직접 지정하세요.

## 개발 서버의 포트를 찾고 싶을 때

사이드바의 **도구** <!-- en: Tools --> 메뉴에서 **리스닝 포트...** <!-- en: Listening ports... --> 를 엽니다. Tasty 터미널에서 띄운 프로세스가 열어둔 TCP 포트를 포트 · 프로세스 · 워크스페이스 · 탭과 함께 보여줍니다.

- 기본은 LISTEN 상태만 보입니다. 목록이 비고 "상태 필터에 맞는 포트가 없습니다" 가 떠 있으면 다른 상태의 포트가 있을 수 있습니다 — 필터 행 우측의 **상태** <!-- en: State --> 버튼으로 다른 상태를 켜고 **적용** <!-- en: Apply --> 합니다.
- Tasty 밖 프로세스까지 보려면 **전체 보기** <!-- en: Show all (system-wide) --> 를 켭니다.
- 행을 클릭해 선택하고 **주소 복사** <!-- en: Copy address --> 로 `host:port` 를 클립보드에 넣습니다.
- 별 아이콘으로 즐겨찾기에 넣으면 상단에 항상 보이고, 재시작해도 남습니다 (`~/.tasty/port-favorites.toml`).

## 문제 신고

[GitHub 이슈](https://github.com/zilhak/tasty/issues)에 증상을 알려주세요. 아래 정보를 함께 남기면 원인을 확인하는 데 도움이 됩니다.

- `tasty --version` 출력과 OS · 버전
- 재현 절차
- `~/.tasty/crash-reports/` 의 해당 `crash-*.log` / `hang-*.log`
- 증상 직후의 `~/.tasty/debug.log` (다시 켜면 비워지므로 먼저 복사해 둡니다)

### 부모 에이전트가 자식 결과를 받지 못합니다

자식의 테두리·배지 상태와 부모 결과 수신은 별개입니다. 부모가 Claude Code이면 완료 로그와 Monitor 구독을 확인하세요. [연결·복구 안내](../agents/claude-codex.md)를 따르세요.

### 세마포어 · 배리어를 만들 때 "invalid char" 로 거절됩니다

이름에 대문자나 공백 같은 쓸 수 없는 글자가 들어 있습니다. 메시지가 가리키는 위치는 입력한 이름에서 센 자리입니다(첫 글자가 0). 영문 소문자 · 숫자 · `.` · `_` · `-` 로 바꿔서 다시 만드세요. [동시 실행 제한과 신호](../agents/tasks.md#동시-실행-제한과-신호)
