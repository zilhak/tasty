# Lua 스크립트

작은 Lua 스크립트를 등록해 단축키로 실행하거나, 윈도우·워크스페이스·탭이 생기고 사라지는 순간에 자동으로 실행합니다. 스크립트는 tasty 를 정해진 통로로만 다루고 전용 스레드에서 돌기 때문에, 스크립트가 멈춰도 윈도우는 멈추지 않습니다.

부팅할 때 자동으로 불러오는 파일은 없습니다. 등록하고 트리거를 붙인 스크립트만 실행됩니다.

## 등록

**설정** <!-- en: Settings --> > **기타** <!-- en: Misc --> > **스크립트** <!-- en: Scripts --> 에서 **스크립트 추가** <!-- en: Add script --> 를 누릅니다.

- **파일** <!-- en: File --> — `.lua` 파일 경로. **찾아보기…** <!-- en: Browse… --> 로 골라도 됩니다. 두는 위치는 자유지만 관례는 `~/.tasty/scripts/` 입니다.
- **표시 이름** <!-- en: Display name --> — 목록과 단축키 화면에 보일 이름. 비우면 파일명을 씁니다.

등록하면 목록에 행이 하나 생기고, 붙은 단축키가 함께 보입니다. 아직 없으면 **미지정** <!-- en: Unbound --> 입니다. 행에서 이름을 바꾸거나 제거할 수 있습니다. 제거하면 연결된 단축키도 함께 풀립니다.

## 단축키로 실행

**설정** > **단축키** <!-- en: Keybindings --> > **스크립트 실행** <!-- en: Run Scripts --> 에서 등록한 스크립트마다 조합을 지정합니다. 지정한 조합을 누르면 그 자리에서 실행됩니다.

## 이벤트로 자동 실행

스크립트 행 아래 **자동 실행** <!-- en: Auto-run --> 줄에서 **트리거 추가…** <!-- en: Add trigger… --> 로 이벤트를 고릅니다. 여러 개를 붙일 수 있고, 붙인 이벤트는 칩으로 표시되며 클릭해서 뗍니다.

| 이벤트 | 언제 |
|---|---|
| `tasty.startup.post` | tasty 가 다 뜬 직후 |
| `window.create.post` · `window.delete.post` | 윈도우가 생기고 닫힐 때 |
| `workspace.create.post` · `workspace.delete.post` | 워크스페이스가 생기고 닫힐 때 |
| `workspace.change.post` | 워크스페이스 이름·설명을 윈도우에서 직접 바꿨을 때 |
| `tab.create.post` · `tab.delete.post` | 탭이 생기고 닫힐 때 |
| `tab.change.post` | 탭 이름을 윈도우에서 직접 바꿨을 때 |
| `pane.create.post` · `pane.delete.post` | 페인이 생기고 닫힐 때 |
| `surface.create.post` · `surface.delete.post` | 서피스가 생기고 닫힐 때 |

이름을 바꾸는 두 이벤트는 **윈도우에서 직접 바꾼 경우에만** 발화합니다. CLI 로 바꾼 이름은 발화하지 않습니다.

자동 실행 스크립트가 CLI 로 또 다른 이벤트를 일으키면 연쇄가 될 수 있습니다. 이걸 막는 장치가 있어서, 자동 실행이 도는 동안과 끝난 직후에는 새 자동 실행이 잠깐 억제됩니다.

## 스크립트에서 할 수 있는 것

tasty 는 다음만 제공합니다. 그 밖에 tasty 내부를 직접 건드릴 방법은 없습니다.

| 함수 | 하는 일 |
|---|---|
| `tasty.tree()` | 윈도우 · 워크스페이스 · 탭 · 서피스 구조를 테이블로 읽습니다. 읽기 전용 사본입니다 |
| `tasty.run_cli(args)` | `tasty` 명령을 실행합니다. 문자열 하나 또는 문자열 테이블을 넘깁니다 |
| `tasty.log(msg)` · `tasty.warn(msg)` | 로그에 남깁니다 |
| `tasty.on(event, cb)` | 이벤트가 날 때 호출될 함수를 등록합니다. 보기만 할 수 있고 tasty 의 동작을 바꾸지는 못합니다 |

tasty 를 실제로 조작하는 일은 대부분 `tasty.run_cli` 로 합니다. 워크스페이스를 만들든 알림을 보내든 [CLI](../agents/cli.md) 로 할 수 있는 것은 전부 여기서도 됩니다.

```lua
-- 워크스페이스가 새로 생기면 오른쪽에 로그 창 하나 붙이기
local tree = tasty.tree()
tasty.log("workspaces: " .. tostring(#tree.workspaces))
tasty.run_cli({ "notify", "새 워크스페이스", "--title", "script" })
```

Lua 표준 라이브러리의 파일 입출력과 외부 명령 실행은 그대로 쓸 수 있습니다. 내 머신에서 내가 쓴 스크립트를 도는 것이라 따로 가두지 않습니다.

## 파일이 바뀌면

등록할 때 파일의 해시를 기록해 두고, 실행할 때마다 지금 파일과 비교합니다. 편집기로 스크립트를 고치면 목록에 **변경됨** <!-- en: changed --> 배지가 붙습니다.

- **단축키로 실행** — 확인 창이 뜹니다. 승인하면 새 내용으로 실행하고 해시를 갱신합니다.
- **자동 실행** — 실행하지 않고 막습니다. 사람이 보지 않는 사이에 바뀐 스크립트가 도는 것을 막기 위해서입니다. 목록에서 배지를 확인하고 한 번 직접 실행해 승인하면 다시 돕니다.

`require` 로 불러오는 다른 파일까지는 검사하지 않습니다.

## 실행 제약

- 메모리 상한이 있고, 넘으면 그 실행만 중단됩니다.
- 무한 루프처럼 끝나지 않는 스크립트는 시간이 지나면 중단됩니다. 중단되는 것은 스크립트 스레드뿐이고 tasty 는 그대로 돕니다.
- 텍스트 소스만 받습니다. 미리 컴파일한 바이트코드는 거부합니다.
- 디버그 라이브러리와 임의 코드 로드 계열 함수는 막혀 있습니다.

## 문제가 생기면

무엇이 왜 안 도는지 보려면 로그 수준을 올려 실행합니다.

```sh
TASTY_LOG=tasty_lua=debug tasty
```

자동 실행이 막혔거나 연쇄가 억제된 경우도 여기에 경고로 남습니다.
