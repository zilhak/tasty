# 작업 배치 만들고 다시 쓰기

구현하는 터미널과 테스트하는 터미널을 나란히 두세요. 자주 쓰는 배치를 프리셋으로 저장하면 다음 작업에서 다시 꺼내 쓸 수 있습니다.

<!-- tasty-diagram: workflow-layout -->
```
왼쪽 페인: 구현 터미널 | 오른쪽 페인: 테스트 터미널
각 페인의 탭은 따로 전환합니다.
```

## 1. 작업 공간 나누기

1. 프로젝트의 워크스페이스를 열고 터미널에서 프로젝트 디렉터리로 이동하세요.
2. `Alt+E`로 페인을 좌우로 나누세요. 기본 Tasty 단축키 기준입니다. 바꿨다면 [단축키 설정](../customize/keybindings.md)을 확인하세요.
3. 한쪽에서는 구현하고, 다른 쪽에서는 프로젝트의 테스트 명령을 실행하세요.

페인마다 탭을 따로 바꿀 수 있어서, 테스트 로그를 남겨둔 채 다른 쪽에서 문서를 확인하기 좋습니다. 여러 화면을 한 탭에 묶어 함께 전환하고 싶다면 [서피스 분할](panes-tabs-splits.md)을 사용하세요.

## 2. 문서를 가까이에 두기

문서를 볼 페인의 탭 스트립 빈 곳을 우클릭하고 **새 마크다운...** 을 선택해 프로젝트의 README를 여세요. 터미널로 돌아갈 때는 같은 페인의 터미널 탭을 누르면 됩니다. 다른 페인의 테스트 화면은 그대로 남습니다.

이미지나 HTML 결과물도 [파일 열기](files.md)에서 안내하는 뷰어로 확인할 수 있습니다. 작업 배치는 실행과 결과 확인을 가까이 두기 위한 것이며, 파일 편집기나 모든 웹브라우저 기능을 대신하는 것은 아닙니다.

## 3. 지금 배치를 프리셋으로 저장하기

1. 사이드바의 워크스페이스를 우클릭하세요.
2. **워크스페이스 프리셋으로 저장** 을 선택하세요.
3. **도구 > 프리셋** 에서 저장된 워크스페이스 프리셋을 확인하세요.
4. **편집** 에서 각 칸의 종류, 작업 디렉터리, 시작 명령을 확인하세요. 변경은 자동 저장됩니다.

시작 명령은 새 터미널이 열릴 때 실행됩니다. 자동으로 실행할 필요가 없는 칸은 비워 두세요. 다른 프로젝트에서도 쓸 배치라면 경로와 명령을 먼저 맞추세요.

## 4. 새 작업에서 다시 사용하기

**새 워크스페이스** 버튼을 우클릭하고 **프리셋으로 새 워크스페이스 생성...** 을 선택하세요. 저장한 프리셋을 고른 뒤, 각 터미널이 의도한 디렉터리에서 시작했는지 확인하세요.

프리셋은 배치와 시작 설정을 다시 사용합니다. 실행 중인 프로세스를 복제하지는 않습니다. 앱을 다시 열었을 때의 [배치와 기록 복원](workspaces.md)은 별도의 기능입니다.

## 에이전트와 함께 쓰려면

한쪽에 [Claude Code나 Codex CLI](../agents/claude-codex.md)를 연결하고 다른 쪽에서 내 작업을 이어가세요. 에이전트가 백그라운드 탭을 만들더라도 내가 보던 화면의 포커스와 선택·스크롤은 바뀌지 않습니다.

아예 탭 없이 실행하던 작업을 나중에 보고 싶다면 [백그라운드 작업을 탭으로 가져오기](../agents/background-tasks.md)를 살펴보세요.

## 모든 OS에서 동일한 환경을 사용하세요

Windows, macOS, Linux에서 같은 방식으로 작업하는 것이 Tasty의 사용자 경험 원칙입니다. 페인·탭·프리셋으로 작업을 구성하는 흐름도 같습니다. 다만 다른 OS로 배치를 옮길 때는 파일 경로, 설치된 도구와 셸 명령을 그 환경에 맞춰 확인하세요.
